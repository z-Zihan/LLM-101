# 为什么“预测下一个 Token”还能学到能力？

> Level: `Core` · Path: `Main`

## 一个小白真的会怎么问？

> 只是猜下一个 Token，为什么还能回答问题、翻译和写代码？
>
> 标准答案是谁标出来的？

## 先说人话

预测下一个 Token 看起来简单，但要在大量不同文本中持续预测得更准，模型必须捕捉词语、句法、语义、文本结构和许多事实关联。

它学到的是有助于预测的统计规律。由此形成的能力可以支持很多任务，但不能直接推出模型拥有人的理解或意识。

## 训练目标从哪里来？

一段现成文本可以自动提供许多练习题：

```text
文本：小猫坐在窗台上

输入：小                 目标：猫
输入：小猫               目标：坐
输入：小猫坐             目标：在
输入：小猫坐在           目标：窗台
```

实际 Token 切分未必按汉字，上图只展示“用后续单元作为目标”的思路。训练实现也可以并行计算多个位置，不必真的逐题慢慢运行。

因为目标来自数据序列本身，这类方法常称为自监督学习：不需要人工为每个位置重新写一个标签。

## 模型怎样从错误中改变？

```text
已有 Token
   ↓
模型给候选 Token 分配可能性
   ↓
检查真实后续 Token 得到的可能性
   ↓
计算 Loss
   ↓
调整参数，让真实后续 Token 的预测更合理
```

Loss 是衡量当前预测与训练目标差距的数值。完整的梯度和反向传播原理会在后文解释。

## 为什么会迁移到很多任务？

文本中包含多种结构：

- 问题后面常跟回答；
- 一种语言后面可能跟翻译；
- 代码注释后面可能跟实现；
- 论点后面可能跟证据或反驳；
- 故事开头会限制后续情节。

要预测这些内容，模型需要利用前文并形成可复用的内部表示。规模、数据和训练充分程度提高后，同一个预测目标可以支持多种输入输出模式。

```text
广泛文本中的共同结构
          ↓
参数学到可复用表示
          ↓
不同 Prompt 激活不同任务模式
```

这解释了为什么一个语言模型不只会机械补全固定句子，但不是对所有能力来源的完整证明。后训练、工具和产品系统也会显著影响最终行为。

## 聊天助手只做了预训练吗？

通常不是。只经过下一 Token 预训练的模型主要学会延续文本。为了更稳定地遵循指令和进行对话，团队常加入监督示例、偏好信号或其他后训练。

```text
预训练：学习广泛语言规律
   ↓
后训练：适配指令、对话、安全与具体目标
   ↓
产品系统：再加入规则、Context 和工具
```

## 最容易搞混的东西

### 下一个 Token ≠ 下一个词

Token 可能是词、子词、字符或其他片段。模型预测的是 Tokenizer 词表中的下一个单元。

### 预测目标 ≠ 事实核验目标

训练目标鼓励生成符合数据规律的后续内容，不直接保证每句话都经过事实验证。这是幻觉会出现的重要背景之一。

### 自监督 ≠ 没有训练目标

目标仍然存在，只是从数据本身构造，而不是由人工为每个 Token 单独标注。

### 能力 ≠ 意识

能完成翻译、问答或代码任务是可观察行为；是否具有人的理解或主观体验是另一个有争议的问题。

## 常见误区

### 误区 1：模型只是背下所有句子

模型可能记住部分训练片段，但处理新组合还涉及泛化。把所有表现都说成背诵或都说成理解都过于绝对。

### 误区 2：预测一次就学会了

训练会在大量样本与位置上反复计算和更新参数，能力来自累积过程。

### 误区 3：预训练完成就自然会当助手

续写与遵循用户意图不是同一个目标。聊天行为通常还依赖后训练与产品设计。

## 你只需要记住

1. 文本自身可以提供“已有 Token → 后续 Token”的训练目标。
2. 要持续预测得更好，模型需要捕捉可复用的语言与文本规律。
3. 预测目标能支持多种能力，但不保证事实正确，也不证明人类式理解。
4. 好用的聊天助手通常还需要后训练和产品系统。
