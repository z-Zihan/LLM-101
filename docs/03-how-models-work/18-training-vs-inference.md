# Training 和 Inference 有什么区别？

> Level: `Core` · Path: `Main`

## 一个小白真的会怎么问？

> 我平时和模型聊天，也是在训练它吗？
>
> 训练和生成回答都在做计算，区别到底在哪里？

## 先说人话

训练（Training）是在**调整模型参数**，让模型在目标任务上表现得更好。

推理（Inference）是在**使用训练好的参数**处理新输入，得到预测或生成结果。

```text
Training：用数据改参数
Inference：用参数算结果
```

## 举个例子

垃圾邮件模型训练时会读取许多样本、比较预测与标签，再调整参数。

部署后收到一封新邮件时，它使用已经训练好的参数判断类别。这次判断就是推理，通常不会反过来更新参数。

## 严格来说

训练通常包含：

```text
前向计算
  ↓
计算 Loss
  ↓
反向传播计算梯度
  ↓
优化器更新参数
  ↺
```

梯度可以先理解成“参数朝哪个方向改变会怎样影响 Loss”的信息；优化器根据梯度决定具体更新。

推理通常只需要前向计算：

```text
新输入 + 固定参数
        ↓
      前向计算
        ↓
预测 / 下一个 Token 的分数
        ↓
输出
```

对生成式模型，这个过程会重复多次，逐步生成 Token。

## 为什么训练通常更复杂？

训练除了计算输出，还要：

- 保存反向传播所需的中间信息；
- 计算每个可训练参数的梯度；
- 保存优化器状态；
- 更新并同步参数。

推理通常不需要这些训练状态，但仍需加载参数、处理 Context，并为生成过程保存必要缓存。

具体速度、显存和计算差异取决于模型、精度、批量、硬件与实现，不能用一个固定倍数概括所有情况。

## 聊天时模型会不会学习？

在普通产品交互中，底层模型通常是在推理，训练参数不会因单次消息立即改变。

但系统的其他状态可能变化：

- 产品保存聊天记录；
- 缓存中间结果；
- Memory 系统记录用户信息；
- 日志以后可能经过筛选用于新的训练流程。

这些都不等于“当前这次推理正在更新模型参数”。

## 最容易搞混的东西

### Training ≠ Pre-training

Training 是总称。Pre-training 是训练的一种阶段；SFT、偏好优化等后训练也会更新参数。

### Inference ≠ Reasoning

Inference 在机器学习工程中指使用模型计算输出；Reasoning 通常描述模型解决多步问题的行为或能力。中文都可能出现“推理”，需要看语境。

### Inference ≠ Deployment

Deployment 是把模型放进可运行服务的工程过程；Inference 是服务收到输入后执行模型计算。

### Context 改变 ≠ 参数改变

在 Prompt 中增加资料会改变本次输入和输出，但不会自动把资料训练进参数。

## 常见误区

### 误区 1：推理就是查表

不对。模型会使用参数对输入执行大量计算，生成模型还会反复计算后续 Token。

### 误区 2：训练结束后参数永远不再变化

一次训练运行结束后参数可以保存，但团队之后仍可继续训练、微调或发布新版本。重点是普通推理请求本身通常不更新它们。

### 误区 3：推理没有成本

推理仍需要计算、内存 / 显存和数据传输。大量用户、长 Context 或长输出都可能增加服务成本。

## 为什么我要知道它？

分清训练和推理，才能正确理解：

- 为什么聊天不会自动把资料永久训练进去；
- 为什么训练与部署需要不同工程资源；
- Fine-tuning、RAG 和 Context 分别改变什么；
- 模型文件为什么需要在推理服务中加载。

## 你只需要记住

1. Training 用数据和目标更新参数；Inference 使用训练好的参数处理新输入。
2. 两者都有前向计算，训练还要计算梯度并更新参数。
3. 普通聊天通常是推理；聊天记录或 Memory 的变化不等于参数更新。
4. 两者成本差异取决于具体模型与系统，不能套一个固定倍数。
