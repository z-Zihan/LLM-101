# AI Coding 是什么？

> Level: `Core` · Path: `Main`

## 先说人话

AI Coding 是把模型用于软件开发任务的广泛类别，包括代码补全、解释、生成、测试、Review、重构和多步 Coding Agent。

它不是某一个产品，也不等于“输入一句话就自动得到可上线软件”。

## 常见形态

```text
代码补全：根据光标附近内容续写
聊天助手：回答问题或生成代码片段
代码工具：执行特定生成、测试或 Review
Coding Agent：读取项目、编辑、运行并根据结果继续
```

这些形态的 Context、权限与自主程度不同。

## 模型怎样处理代码？

代码也会被转换成 Token。模型从训练数据中学习代码、注释和自然语言之间的模式，再根据当前 Context 预测输出。

它可能生成语法正确且风格合理的代码，但不直接证明逻辑、依赖、安全和业务需求正确。

## AI Coding 能帮助什么？

- 解释陌生代码；
- 生成样板与测试草稿；
- 根据错误信息提出排查方向；
- 重构局部实现；
- 搜索跨文件关系；
- 编写文档与迁移说明。

具体表现取决于模型、项目 Context、工具、语言、任务和验证方式。

## 为什么代码仍要验证？

软件行为由完整系统决定。模型可能：

- 猜错 API 或依赖版本；
- 漏掉边界条件；
- 引入安全漏洞；
- 修改错误文件；
- 让测试“通过”但偏离需求；
- 生成有许可证或来源风险的内容。

```text
生成代码
 ↓
检查 Diff
 ↓
运行测试、类型检查与安全检查
 ↓
人工 Review 需求与风险
```

## 最容易搞混的东西

### AI Coding ≠ Coding Agent

AI Coding 是大类；Coding Agent 是其中能围绕目标连续使用项目工具的一种系统。

### 生成代码 ≠ 执行代码

模型输出文本；Runtime 或终端才真正编译和运行。

### 测试通过 ≠ 产品正确

测试只覆盖已有断言。缺失的需求和环境差异仍可能造成问题。

## 常见误区

### 误区 1：模型见过很多代码，所以了解当前项目

模型仍需读取当前仓库、配置、版本和需求；训练知识不能替代 Project Context。

### 误区 2：AI 生成得快，交付一定更快

错误验证、返工和复杂集成可能抵消生成速度，需要看完整交付周期。

## 你只需要记住

1. AI Coding 覆盖补全、问答、生成、测试、Review 和 Coding Agent 等多种形态。
2. 模型生成代码不等于代码已执行、已验证或可上线。
3. 项目 Context、工具和验证流程与模型能力同样重要。
4. Diff、测试、静态检查和人工 Review 仍是交付闭环。
