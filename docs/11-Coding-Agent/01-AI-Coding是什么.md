# AI Coding 是什么？

> 所属专题：Coding Agent · 前置：[Agent 和 Skill 有什么区别](../10-Skill/05-Agent和Skill有什么区别.md) · 后续：[Coding Agent 是什么](./04-Coding-Agent是什么.md)

AI Coding 是把模型用于软件开发任务的广泛类别，包括补全、解释、代码生成、测试、Review、重构和多步 Coding Agent。它不是某一个产品，也不等于输入一句需求就得到可上线软件。

## 从局部补全到项目级行动

代码补全根据光标附近内容续写；聊天助手回答问题或给出片段；专用工具执行测试生成或 Review；Coding Agent 则能读取项目、修改文件、运行命令并根据结果继续。

```text
局部补全 → 对话式辅助 → 专用代码工具 → Coding Agent
上下文、工具、权限和自主程度逐步增加
```

这张图描述产品形态，不是质量排名。读图时注意，简单补全在明确任务上可能比复杂 Agent 更快、更可控。

代码也会被转换成 Token。模型从代码、注释和自然语言中学习模式，再根据当前上下文生成。语法流畅不证明依赖存在、逻辑正确、安全可靠或符合当前仓库规范。

## 终端与 IDE 只是不同交互表面

IDE Agent 容易利用当前文件、选区、诊断、符号和可视化 Diff；终端 Agent 更自然地运行 Shell、测试、构建、Git 和远程自动化。两者都可能连接同一模型和类似工具，也都可能实现完整 Agent Loop。

真正影响能力的是模型、可用项目上下文、工具质量、权限、运行时状态和验证闭环。界面会影响信息获取与人工 Review 体验，却不能单独决定“谁更智能”。IDE 产品也可能调用终端，CLI Agent 也能通过语言服务器获取语义导航。

选择时应看任务：局部交互和逐行审查适合 IDE；批处理、服务器环境和脚本化流程常适合终端。高风险修改无论在哪个界面，都需要 Diff、测试和权限控制。

## AI 能帮什么，证据要补什么

它适合解释陌生代码、生成样板与测试草稿、分析错误、重构局部实现、搜索跨文件关系和编写迁移说明。实际效果取决于模型、语言、仓库上下文、工具和验证流程。

生成代码后要检查 Diff，运行相关测试、类型检查、构建和安全扫描，再由人核对需求与高风险变化。测试通过只覆盖已有断言；模型也可能通过删除断言或偏离需求让测试变绿。

模型见过大量公开代码，不表示理解当前项目的私有依赖、版本、配置和约定。项目上下文必须从当前仓库读取，易变 API 要查当前文档。

## 速度要看完整交付周期

生成更快可能节省输入时间，也可能带来审查、返工和集成成本。评估 AI Coding 应看从需求到经过验证的交付，而不只统计生成行数。

权限同样重要。模型输出命令不等于已经执行；拥有终端和仓库写权限的 Agent 会扩大副作用，需要沙箱、最小权限和确认。

## LLM / Coding Engineer 面试为什么不只考 API

模型 API 调用只是系统入口。实际岗位还可能要求解释 Attention 与上下文成本，设计 RAG 或 Agent，建立离线和在线评测，定位延迟与显存瓶颈，并处理数据、权限、监控和回退。

一份合理的系统设计回答应先澄清用户、质量门槛、数据和流量，再选择模型与架构；给出评测集、失败分类、延迟成本预算和发布验证。背出框架名称却没有验收与故障恢复，不能证明能交付真实系统。

不同岗位侧重点不同：研究岗可能深入训练和实验，平台岗强调推理与分布式系统，应用岗强调产品、检索、Agent 与评测。招聘题目本身不是行业统一知识清单。
