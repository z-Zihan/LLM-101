# Claude Code 产品案例：终端里的 Agent 多了一层什么？

> 最后核验：2026-08-21 · 易变产品案例
>
> 本页依据 Anthropic 官方仓库、官方文档入口与核验当天的 CLI 帮助编写，不固化价格、模型版本、上下文长度或临时开关。

Claude Code 是 Anthropic 的 Agentic Coding Tool。官方说明把终端作为主要入口，同时支持 IDE 与 GitHub 场景。它不是“在 Shell 里直接调用一次 Claude API”：产品还负责会话、项目规则、文件和 Bash 工具、权限模式、插件、MCP、子 Agent 与结果输出。

一条真实 issue 描述了非交互任务的权限死锁：分类器拒绝命令，又拒绝用户用产品提供的路径放行该命令。这个案例揭示了关键边界——用户在自然语言里说“都允许”，不等于运行时已经改变工具策略；反过来，策略系统也必须给用户一条可理解、可审计的授权出口。

## 从终端命令看到完整系统

| 观察角度 | Claude Code 中的职责 | 需要额外核验的地方 |
|---|---|---|
| 交互入口 | 交互式终端、非交互输出、IDE 与 GitHub 工作流 | 不同入口是否暴露同一批准与恢复控件 |
| 项目上下文 | 当前目录、允许目录、`CLAUDE.md`、会话历史和工具结果 | 规则是否适用于当前子目录，摘要是否漏掉约束 |
| 工具 | 文件读写、Bash、Git、MCP、插件与可配置 Agent | 工具声明是否真的执行成功 |
| Agent Loop | 搜索代码、编辑、运行命令、读错误并继续 | 是否陷入重复搜索、重试或权限循环 |
| 权限 | Permission Mode、允许/禁止工具和环境本身的隔离 | “跳过权限”是否在外部沙箱内使用 |
| 验证 | 测试、静态检查、diff、结构化输出与预算/退出状态 | 最终文本是否与真实仓库状态一致 |

## 项目规则、会话和工具怎样组合

进入项目目录后，Claude Code 会围绕当前工作区读取和修改文件、执行命令并保存会话状态。`CLAUDE.md` 可提供持续项目说明；`--add-dir` 明确增加允许访问的目录；交互会话可继续或恢复，非交互模式则能把结果输出给脚本。

这些入口服务不同职责。`CLAUDE.md` 适合记录构建命令、约定和验收方式，不适合存放密钥；当前 Prompt 说明本次任务；工具输出提供环境事实；测试才判断改动是否满足可执行约束。把所有信息塞进一份规则文件，会让上下文变长，却不会自动提高权威性。

插件、Skills、MCP 和自定义 Agent 能扩展方法与工具，但扩展越多，越要知道哪些内容来自仓库、个人配置、组织策略或第三方服务。出现异常时，可用最小配置或安全诊断方式区分模型问题、项目规则冲突和扩展故障。

## Permission Mode 不是一句“自动运行”

核验当天的 CLI 同时提供 Permission Mode、允许工具、禁止工具和跳过权限等选项。它们控制的是运行时怎样处理工具请求，不会改变操作系统文件权限，也不会把不受信任目录变成安全环境。

CLI 对跳过权限选项的说明明确建议只在没有互联网的外部沙箱中使用。这是两层防护：产品可以少问确认，真正的损害范围仍由容器、虚拟机、账户权限、网络策略和备份约束。把两层同时关闭，意味着错误命令、Prompt Injection 或误判都可能直接产生副作用。

非交互模式尤其需要预先设计授权。用户不在场时，任务若遇到未允许动作，应该失败并返回可诊断状态，或通过明确的预授权规则运行；不能靠 Agent 在对话里自行宣布获得权限。

## 权限死锁怎样安全处理

真实 issue 中，分类器阻止了业务命令，也阻止了原本用于调整设置的路径。用户连续发送授权话语仍无法解锁，因为文字没有进入运行时策略层。

正确恢复顺序是：确认被拒动作没有执行；记录具体工具和策略来源；在有权限的交互界面或外部配置层做最小范围调整；重新启动一项可幂等验证的任务。不要为了“让它继续”直接扩大到所有命令，也不要在不确定旧任务状态时重复有副作用的操作。

产品若支持“本次、当前项目、长期”不同授权范围，应选择最小范围。团队环境还要区分个人设置与管理员策略：用户本地文件能表达偏好，不保证能覆盖组织门禁。

## 怎样验收 Claude Code 的结果

终端入口天然适合保存命令和退出码，但日志很长不等于证据充分。验收时只需要回答：改动范围是什么；哪些测试在什么目录运行；是否有失败、跳过和超时；Git diff 是否含无关内容；需要人工批准的动作是否有记录。

使用子 Agent 或后台任务时，还要检查它们拿到的仓库路径、任务约束和依赖是否正确。主 Agent 的一句“子任务完成”不能代替对子任务产物的合并检查。

## 回答真实问题

**我已经在消息里说“允许”，为什么命令仍被拒绝？** 因为消息是任务输入，Permission Mode 与工具规则才是运行时授权。两者必须通过产品提供的明确机制连接。

**能不能直接跳过所有权限？** 只有在外部环境已经可靠隔离、任务可恢复且你接受风险时才考虑；产品自己的提示也把它限定为危险选项，不应作为日常排错捷径。

**非交互任务怎样避免卡死？** 预先允许最小工具集合，让拒绝以明确错误退出，并把需要人工升级的动作交回可操作界面。
