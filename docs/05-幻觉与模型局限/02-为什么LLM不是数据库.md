# 为什么 LLM 不是数据库？

> Level: `Core` · Path: `Main`

## 一个小白真的会怎么问？

> 模型学了那么多资料，不就是把互联网装进参数了吗？
>
> 为什么它不能像数据库一样把正确记录查出来？

## 先说人话

数据库把数据按明确结构保存，并按照查询规则读取或修改记录；LLM 则使用训练得到的参数，根据当前 Context 计算接下来哪些 Token 更可能出现。

LLM 可以回答许多知识问题，但这不表示事实以一行行可寻址记录存放在参数里。

## 举个例子

数据库里可以有一条明确记录：

```text
订单号：A1024
状态：已发货
更新时间：2026-08-18 10:30
```

程序按订单号查询时，可以返回这条记录，也可以在发货状态变化后更新对应字段。

LLM 没有一个可以用“订单号”精确打开的参数格子。它可能根据 Prompt 生成一个听起来合理的订单状态，但如果没有连接真实订单系统，就不应把这个回答当作当前记录。

## 严格来说

典型语言模型学习的是：在给定 Token 序列后，后续 Token 的概率如何分布。训练数据中的规律会影响大量参数，模型再通过这些参数计算输出。

典型数据库则定义数据结构、记录和查询操作。它强调可定位、可更新、可筛选与一致性约束。

```text
LLM
Context + 参数
   ↓
计算候选 Token 的分数
   ↓
生成回答

Database
结构化查询
   ↓
定位明确记录
   ↓
返回或更新数据
```

具体数据库有很多类型，LLM 系统也可能连接数据库。这里比较的是两类系统的核心职责，不是说它们不能组合。

## “知识在参数里”是什么意思？

模型训练后，参数会形成能支持事实问答、语言使用和其他任务的模式，所以研究中常用 Parametric Knowledge（参数化知识）描述这种现象。

但这是一种功能性简称，不应理解成：

```text
一个事实 = 一条参数记录
一个参数地址 = 一个可直接读取的答案
```

信息往往分布在许多参数及其计算关系中。同一个问题换一种问法，模型可能给出不同答案；修改一条事实也可能影响其他行为。

## 模型会不会记住原文？

可能。模型可能记忆并在特定条件下复现训练片段，尤其是重复或独特内容。但记住部分文本不等于获得数据库的完整能力：

- 无法保证每条训练内容都被保存；
- 无法可靠列出“存过哪些记录”；
- 无法保证按字段精确查询；
- 无法像更新一行数据那样简单修改某条事实；
- 复现还可能涉及隐私与版权风险。

泛化和记忆也可以同时存在，不能把模型所有回答都解释成原文查表。

## 为什么事实会过时或不一致？

模型参数反映训练过程形成的模式。普通推理不会自动把今天发生的新事实写回参数。

此外，训练数据可能包含不同时间、不同来源和互相冲突的说法。Prompt 写法、Context 和生成过程也会影响最终答案。因此，模型可能：

- 不知道训练截止后发生的变化；
- 对同一事实换个问法就回答不一致；
- 把相关但不同的信息组合在一起；
- 在缺少证据时生成一个看似合理的答案。

## RAG 能把 LLM 变成数据库吗？

不能。RAG 会先从外部资料中检索相关内容，再把结果提供给模型生成回答：

```text
问题 → 检索外部资料 → 加入 Context → 模型生成答案
```

它让知识更容易更新，也让来源更容易检查，但数据库或知识库仍是外部组件。检索可能漏掉或找错资料，模型也可能误读资料，所以 RAG 不自动保证答案正确。

完整原理会在 RAG 章节单独解释。

## 最容易搞混的东西

### LLM ≠ Search Engine

搜索引擎主要查找并排序外部页面；LLM 主要根据输入生成内容。带搜索功能的 AI 产品是两者组合，不表示底层模型本身就是搜索引擎。

### 参数 ≠ 数据记录

参数是训练调整出的数值，数据记录是可按结构读取或修改的内容。两者不能逐条换算。

### Context ≠ 永久数据库

放进 Context 的资料可以影响当前计算，但不会自动成为永久参数，也不保证产品以后一直保存。

## 常见误区

### 误区 1：模型能答对事实题，就证明它是数据库

答对描述的是一次输出结果；数据库描述的是数据保存、查询和更新机制。相同结果不等于相同机制。

### 误区 2：参数越多，能存的事实条数就有固定比例地增加

参数量不是“知识条目容量”。能力还受架构、数据、训练和任务影响，也没有通用的参数到事实条数换算公式。

### 误区 3：接入数据库后，模型答案就必然正确

系统还要正确生成查询、执行权限检查、读取结果并忠实表达。每一步都需要验证和错误处理。

## 为什么我要知道它？

如果把 LLM 当数据库，就容易让它猜订单、库存、政策或最新数字。正确的系统设计通常是：让权威数据源保存事实，让模型负责理解需求、组织语言或选择工具，并对关键结果进行验证。

## 你只需要记住

1. LLM 根据 Context 和参数生成 Token；数据库按明确结构保存、查询和更新记录。
2. “参数化知识”不表示事实以可寻址记录逐条存进参数。
3. 模型可能记忆文本、回答事实题，但仍可能过时、不一致或产生幻觉。
4. RAG 和数据库可以与 LLM 组合，却不会自动让生成结果永远正确。
