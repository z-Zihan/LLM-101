# 怎么验证 AI 的回答？

> 你现在的位置：[幻觉](./01-幻觉是什么.md) → **验证** → [API](../06-工具与Function-Calling/01-API到底是什么.md)
>
> 课程导航：[上一篇：为什么 LLM 不是数据库](./02-为什么LLM不是数据库.md) · 第 19 / 28 篇 · [下一篇：API 到底是什么](../06-工具与Function-Calling/01-API到底是什么.md)

AI 给出三篇论文、两个链接和一个精确数字，看起来已经很可信。真正的验证（Verification）却刚刚开始：把答案拆成可以检查的主张，找到适合该主张的独立证据，打开原文核对支持范围，再记录仍不确定的部分。

让同一个模型再说一次，或者要求它“保证真实”，都不能构成独立证据。验证的目标不是增加可信语气，而是让结论可以被复查、重复和推翻。

## 先按风险决定查多深

“给我五个标题灵感”和“这个药能不能停”不该使用同一套流程。前者错误代价低，可以快速浏览；后者涉及健康，必须以专业指南、患者具体情况和有资格的人员为准，模型不能承担决策责任。

可以先问三个问题：答案会触发什么行动？错了会伤害谁、损失什么？错误是否容易撤销？风险越高，来源要越接近事实产生位置，复核者要越专业，自动操作权限也要越小。

## 把一整段答案拆成主张

模型说：“某公司在 2026 年 5 月发布产品 X，基础版每月 20 美元，并支持离线使用。”这里至少有三条独立主张：发布日期、当前价格、离线能力。它们还可能需要不同页面和不同核验日期。

```text
完整回答
  ↓ 拆分
事实 / 数字 / 因果 / 引用 / 建议
  ↓ 分别选择证据
官方记录 / 原始论文 / 可重复计算 / 专家审查
  ↓
支持、反驳、证据不足或已经过时
```

这张图想避免“找到一个相关链接就整段通过”。读图时注意，结论可以是证据不足；验证不是逼自己在信息缺失时选真或假。

## 什么来源更适合证明什么

产品功能、价格和版本优先查厂商当前官方文档；法律与政策查主管机构正式文本；论文结论读原始论文的方法、实验和限制；开源项目行为看源代码、测试、发布配置和实际运行；业务状态查询拥有该记录的系统。

第三方教程、媒体和论坛适合发现线索或理解争议，但关键事实如果能拿到第一手来源，就不应只靠转述。多个网页若都复制同一篇错误文章，也不叫独立交叉验证。

易变事实要记录核验日期、地区、套餐和版本。一个去年正确的价格今天可能已经失效；官方文档也可能描述最新版本，而用户仍在运行旧版。

## 引用要过四道关

引用检查可以固定成四个问题：

1. **存在性**：标题、作者、链接和发布日期是否真实？
2. **相关性**：来源真的在讨论当前问题吗？
3. **支持性**：原文是否支持这句结论，还是只提到相似主题？
4. **时效与范围**：结论适用于哪个版本、人群、数据和时间？

论文标题真实，不代表模型转述的实验数字真实；链接能打开，也可能指向没有这句话的页面。最好定位原文段落、表格、代码行或正式记录，让别人能沿同一路径复查。

## 数学、代码、总结和建议怎么分别查

数学与数据结果要重做计算，检查单位、输入和舍入。代码先运行最小可复现测试，再覆盖边界、失败路径和真实环境；“能编译”只证明语法和部分依赖成立，不代表业务行为正确。

总结或 RAG 回答要逐句追到提供的材料。检查模型有没有把可能写成确定、把相关写成因果，或把两段来源拼成原文不存在的结论。材料本身也要核验来源和日期。

建议要先分出事实、预测与价值选择。事实可以查证，预测只能评估假设和不确定性，价值选择最终属于承担后果的人。医疗、法律、财务和安全建议需要相应专业流程。

## 模型自检能帮什么，不能帮什么

要求模型列出假设、找反例、重新计算或比较多次回答，常能暴露矛盾和漏项。一些方法也用多次采样之间的不一致，作为可能出错的信号。

但同一模型可能稳定重复同一错误，不同模型也可能学习了同一网络传言。模型生成的“置信度 95%”若没有校准证据，只是又一段输出。自检适合发现可疑点，外部证据才负责确认现实。

```text
模型自检：寻找矛盾、假设和待查项
独立验证：确认事实、计算和真实状态
```

这张图给两者分工。读图时最重要的是箭头没有闭环回同一个模型：高风险主张必须离开生成文本，接触原始来源、工具或责任人。

## Benchmark 分数为什么也要验证

Benchmark（基准测试）把一组任务、评分方法和运行条件固定下来，便于比较模型。它能证明模型在**这套题和这套条件**下的表现，不能自动代表你的用户、数据、语言、工具和失败成本。

如果测试题、近似改写、答案或解题讨论进入训练数据，模型可能靠记忆或熟悉模板得分，这就是数据污染的一类表现。网页公开题库尤其难完全排除；模型开发者若反复查看测试结果再调整系统，也可能把评测集逐渐变成隐性训练目标。高分仍然是真实测得的数值，但对未见任务的外推意义会变弱。

污染检查不能只问厂商一句“是否训练过”。可以使用有明确时间边界的新题、保密或私有测试集、对题目做受控变体，并观察关键条件改变时答案是否相应变化。还要核对评测脚本、Prompt、采样、工具、尝试次数和是否挑选最佳结果；不同运行条件下的分数不能直接横比。

最终选型应把公开 Benchmark 当作线索，再用自己的真实任务做盲测：覆盖常见输入、困难边界、无答案场景、延迟、成本和安全失败。平均分相同的两个模型，可能在你最在意的少数错误上完全不同。

## 一套可以直接使用的最小流程

先保存原问题、模型版本、回答和时间。圈出会影响决策的主张，为每条主张写下需要的证据类型。打开第一手来源，不只看搜索摘要；对高风险或易变信息，再找独立来源或运行可重复测试。

记录结果时使用“已支持、已反驳、证据不足、已过时”这类状态，并附来源位置和核验日期。若答案将触发写入、付款、删除、发布等操作，在执行前加入权限校验和人工确认。

最后保留失败记录。今天发现的假引用、错单位和边界条件，会成为下一次评测用例。验证不是回答末尾的一次仪式，而是可持续改进系统的证据循环。

## 回答最常见的确认

**AI 给了链接，怎么判断是真的？** 打开链接，先确认来源存在，再检查原文是否讨论并支持具体主张，同时核对日期、版本和适用范围。

**再问模型一遍算验证吗？** 只能算自检线索。重复一致不等于现实正确，仍需独立证据或可重复方法。

**用了搜索或 RAG 还要查吗？** 要。检索可能找错、漏掉或返回旧资料，模型也可能错误转述；至少检查关键结论与原文的对应关系。

**是不是所有回答都要逐字审计？** 不需要。验证强度应与错误后果匹配，但任何会触发现实高风险行动的事实都不应只凭模型语气通过。

**Benchmark 为什么可能被训练数据污染？** 公开题目、答案或近似变体可能进入训练与调参流程，使分数混入记忆和测试适配。应使用时间切分、私有题、受控变体和真实任务评测降低风险。

**榜单第一就最适合实际使用吗？** 不一定。榜单只覆盖特定数据、评分和运行条件；实际选择还要测自己的语言、任务、工具、延迟、成本和高风险失败。
