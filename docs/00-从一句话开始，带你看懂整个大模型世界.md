# 从一句话开始，带你看懂整个大模型世界

你打开一个聊天 AI，输入：

> 帮我写一封请假邮件。

几秒后，一段自然、完整的文字出现在屏幕上。它看起来只是一次对话，背后却连着今天 AI 世界里最常见的一串概念：模型、Token、训练、Transformer、幻觉、RAG、Tool、Agent、MCP、Skill、Memory，甚至 GPU。

这篇文章不要求你记住它们的完整定义。我们只做一件事：跟着这句话从输入到输出走一遍，看清每样东西为什么会出现、彼此怎样连接。碰到你真正感兴趣的部分，再进入对应专题。

看完以后，你应该能自己画出这样一张地图：

```text
AI 产品
  ↓ 使用
大语言模型
  ↓ 处理文字
Token 与上下文
  ↓ 多层计算
Transformer
  ├─ 训练：从错误中调整参数
  └─ 推理：逐个生成 Token
       ↓
幻觉与验证
  ↓ 需要外部信息和行动
RAG / Tool
  ↓ 围绕目标持续工作
Agent
  ↓ 连接与复用能力
MCP / Skill / Memory
  ↓ 进入真实软件工程
Coding Agent
```

## 一、你正在使用的是产品，不是一块孤零零的模型

聊天框、账号、历史消息、联网搜索、文件上传和语音按钮，属于一个 AI 产品。大语言模型（Large Language Model，LLM）是这个产品里最重要的计算部件之一，但不是整个产品。

```text
你看到的界面
  ↓
负责组织数据和功能的 AI 应用
  ↓
根据输入计算输出的模型
```

“AI”是更大的目标和领域：让机器完成过去需要人类智能的任务。“模型”是从数据中学到的一套计算规律。“大语言模型”则主要处理语言，并且规模很大。ChatGPT、Claude、Kimi 这类名字常指面向用户的产品；产品背后可以接一个或多个模型，也可以随时间更换模型。

所以，当一个聊天产品会保存对话、搜索网页或执行代码时，不要把所有能力都归到模型本身。很多能力来自模型外面的应用系统。

## 二、你的句子要先变成模型能计算的东西

你输入“帮我写一封请假邮件”，模型不会像人一样直接看见汉字。文字先经过 Tokenizer，被切成一组 Token。Token 可以暂时理解为模型处理文本时使用的基本单元：它可能是一个字、一个词的一部分、标点，甚至更细的字节片段。

每个 Token 会在词表里对应一个 Token ID。ID 只是编号，本身没有“更大就更重要”的含义。模型再根据编号查到一串可计算的数字，也就是向量表示。

```text
文字 → Token → Token ID → 模型能计算的向量表示
```

为什么不直接用汉字？因为模型要同时处理中文、英文、代码、数字、标点和各种罕见字符，还要在词表大小与序列长度之间折中。不同模型使用不同 Tokenizer，所以同一句话的 Token 数也可能不同。

想亲手走一遍这段转换，读：[从一句“中国的首都是北京”，看文字怎么进入模型](./02-聊天Token与上下文/04-Token到底是什么.md)。

## 三、模型的核心动作，是继续写下一个 Token

先换一个更短的例子：

```text
中国的首都是……
```

主流自回归大语言模型会根据前面的 Token，为词表里的每个候选计算一个分数。“北京”的分数可能最高，但“上海”“城市”或其他候选也都会有分数。系统按生成策略选出一个 Token，把它接回已有内容，然后再算下一步。

```text
已有内容 → 预测下一个 Token → 选出一个候选并接回去 → 再次预测
```

这就是长答案可以从一个很小的重复动作里长出来的原因。模型不是先写好全文再播放打字动画；未来的每一步都会受已经生成内容影响。

“只预测下一个 Token”听起来很窄，却要求模型从大量文本中学会语法、事实关联、文体、代码结构和解决问题的模式。它能产生复杂能力，不等于所有能力都已经被彻底解释，也不等于模型会像人一样理解。

## 四、它为什么可能知道“北京”

因为模型训练过。

训练开始前，人先决定模型的大致结构，并创建一组初始参数。参数可以理解为模型内部大量可调整的数字。最初这些数字还没有形成有用规律；训练程序让模型反复做“根据前文预测下一项”的练习，再根据错误调整参数。

```text
模型结构 + 初始参数
  ↓
读取大量训练文本
  ↓
预测下一 Token
  ↓
和文本中真实出现的下一项比较
  ↓
小幅调整参数，再重复许多次
```

训练数据不是塞进模型里的一个可搜索文件夹，参数量也不是“记住了多少条资料”。训练数据提供学习样本，参数保存学习后形成的数值规律。训练结束后，普通聊天请求通常只使用固定参数做计算，这叫推理；它不会因为你纠正一句话就现场重训整个模型。

想看完整生命周期，读：[一个大模型怎样诞生？](./03-模型原理与训练/01-一个大模型到底是怎么诞生的.md)；容易混淆参数和数据时，读：[参数量和训练数据有什么区别？](./03-模型原理与训练/07-参数量和训练数据有什么区别.md)

## 五、Transformer 让上下文里的信息彼此发生作用

一句话被切成许多 Token 后，模型不能把它们当作互不相关的编号。它需要结合位置和上下文，判断哪些信息对当前位置重要。

例如：“小明把苹果给了小红，因为她很饿。”理解“她”更可能指谁，需要参考前面的名字、动作和语义。Transformer 是今天主流 LLM 常用的模型架构；其中的 Attention 可以先理解成一种信息读取机制：每个位置根据当前需要，从其他允许看到的位置取回不同分量的信息。

Attention 不是整个 Transformer，也不是一张会直接给出人类解释的“思维图”。它只是多层计算里的关键组件之一。多层处理后，每个位置的表示已经结合当前上下文，模型才据此计算下一个 Token 的候选分数。

## 六、为什么它看起来会思考

当模型在大量不同文本上学习后，它不只是记住固定句子，也可能学到能够迁移到新输入的模式。这种把学到的规律用于新情况的能力叫泛化。上下文让模型临时看到当前任务、例子和约束；多层计算把这些信息重新组合；逐步生成又让后面的内容建立在前面的结果上。

这些机制能产生翻译、总结、写代码和多步解题等复杂表现。但“表现得像在推理”“内部存在某种计算过程”和“它以人的方式理解”不是同一个判断。模型能力从哪里来，有些机制已经较清楚，有些现象仍在研究和争论。

## 七、会生成合理文字，不等于永远说真话

模型擅长生成符合上下文、看起来连贯的文字，但训练目标不会自动要求每句话都能找到可靠出处。遇到知识缺口、模糊问题、错误前提或需要实时信息的任务时，它仍可能很流畅地给出错误答案，这通常被称为幻觉。

```text
模型参数里的规律 ≠ 可逐条查询的数据库
聊天时的上下文 ≠ 永远更新的实时互联网
语言流畅、格式完整 ≠ 事实已经核验
```

因此，重要结论要检查原始资料、时间、适用条件和不同证据是否相互印证。产品也会通过搜索、知识库或专门工具把新资料交给模型，但这些办法只能降低某些错误，不能自动保证答案正确。

想学会识别与核验，读：[幻觉是什么？](./05-幻觉与模型局限/01-幻觉是什么.md) → [怎么验证 AI 的回答？](./05-幻觉与模型局限/04-怎么验证AI的回答.md)

## 八、RAG 让模型在回答前先找资料

假设你问的是公司今天刚更新的报销制度。模型训练时可能根本没见过，也不应该靠猜。RAG（Retrieval-Augmented Generation，检索增强生成）会先从指定资料中找出相关内容，再把这些内容连同问题一起交给模型。

```text
用户提问 → 检索相关资料 → 把资料放进本次上下文 → 模型结合资料回答
```

RAG 的关键不是重新训练模型，而是回答前给它补充当前可用的材料。Embedding、向量数据库、关键词检索、切块和重排都可能参与检索，但它们是下一层细节，不需要现在一次学完。

## 九、Tool 让模型从“说怎么做”走向“真的做”

如果模型只生成文字，它可以告诉你怎样查天气，却不能凭空知道此刻的温度。应用给它接入天气 API 后，模型可以表达“需要查询上海今天的天气”；应用检查参数和权限，真正调用服务，再把结果交还给模型整理。

这里要分清职责：模型产生调用建议，应用控制工具是否执行。Function Calling 规定模型怎样用结构化内容表达调用意图，Tool 是可以被调用的外部能力，API 则是软件之间常用的通信接口。

```text
用户目标 → 模型提出调用 → 应用检查并调用 Tool → 结果回到上下文 → 模型继续回答
```

想知道一次调用怎样落地，读：[AI 工具是什么？](./06-工具与Function-Calling/02-AI工具到底是什么.md) → [Function Calling 是什么？](./06-工具与Function-Calling/03-Function-Calling是什么.md)

## 十、Agent 让模型围绕一个目标持续做事

有了 Tool，一次回答可以产生一次外部动作。但“整理这份项目、修改代码、运行测试、根据错误继续修”通常不止一步。Agent 可以先理解成一个围绕目标运行的系统：它让模型观察当前状态、决定下一步、调用工具、读取结果，再判断是否继续。

```text
目标 → 观察 → 决定下一步 → 调用工具 → 读取结果 → 继续或停止
```

Agent 不是一种更大的模型。一个完整 Agent 还需要权限、状态、停止条件、失败恢复和验证机制。能连续调用工具也不等于一定能完成任务；错误动作还可能在循环中被放大。

想理解它真正由什么组成，读：[Agent 到底是什么？](./07-Agent/01-Agent到底是什么.md) → [Agent Loop 是什么？](./07-Agent/03-Agent-Loop是什么.md)

## 十一、MCP、Skill 和 Memory 各自补哪块拼图

当 Agent 能力越来越多，很快会遇到三个不同问题。

**MCP** 关心连接：AI 应用怎样用较统一的方式发现和使用外部工具、资源与提示。

**Skill** 关心复用方法：可以先理解成给 Agent 准备好的任务说明、步骤和配套资源，让它知道某类工作应怎样完成。

**Memory** 关心保留信息：长任务或跨对话时，哪些内容值得保存，之后怎样取回并重新放进当前上下文。

它们不是三个互相替代的“插件名”。MCP 可以连接能力，Skill 可以组织做事方法，Memory 可以保存以后还会用到的信息；一个 Agent 可能同时使用三者，也可能一个都不需要。

## 十二、Coding Agent 把这条链带进软件项目

普通聊天模型可以告诉你某段代码应该怎么改。Coding Agent 则可能自己搜索项目、读取文件、修改代码、运行测试、分析错误，再继续修复。

```text
LLM + 项目上下文 + Tool + Agent Loop + 规则与可选 Memory
  ↓
Coding Agent
```

真正困难的地方不只是“会不会写代码”，还包括是否找对文件、是否越过权限边界、改动是否破坏其他功能、测试是否真的覆盖目标，以及失败后能不能安全恢复。模型提供推理和生成能力，外围系统负责把它约束在真实工程流程中。

## 十三、这些计算最后运行在哪里

模型文件通常先存放在硬盘或远程存储中，运行时加载到内存和 GPU 附近的显存。GPU 擅长并行完成大规模矩阵计算；显存容量影响能放多大的模型、多少上下文和多少并发请求。模型太大或训练量太高时，多张 GPU 甚至多台机器会协同工作。

```text
硬盘 → 内存 → GPU 显存 → GPU 计算
```

到这里知道职责就够了。并行策略、通信、显存带宽和训练框架属于工程深入路线。

## 把整张地图重新画一遍

现在回到最初那句“帮我写一封请假邮件”：

1. 你通过 AI 产品把目标交给应用。
2. 应用整理系统规则、历史消息和你的 Prompt，形成本次上下文。
3. Tokenizer 把文字变成 Token ID，模型把它们变成向量并交给 Transformer 处理。
4. 模型根据训练形成的参数，计算下一个 Token 的候选分数。
5. 系统选择一个 Token，接回上下文，再继续生成，直到回答结束。
6. 如果需要新资料，应用可以先用搜索或 RAG 把资料放进上下文。
7. 如果需要真实行动，应用可以在权限检查后调用 Tool。
8. 如果任务需要多步推进，Agent Loop 会反复观察、行动和验证。
9. MCP、Skill 和 Memory 分别帮助连接能力、复用方法和保留信息。
10. 所有这些计算最终都要在 CPU、GPU、内存、显存和网络组成的系统里运行。

这不是每个 AI 产品唯一的实现方式，却足以让你第一次看见这些名词时，知道它们位于哪一层、为什么出现。
