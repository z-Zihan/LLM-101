# Agent Loop 是什么？

> Level: `Core` · Path: `Main`

## 一个小白真的会怎么问？

> Agent 为什么能自己连续做很多步？
>
> 它会不会一直循环，或者越错越远？

## 先说人话

Agent Loop（Agent 循环）是一种运行方式：系统把当前目标和状态交给模型，执行模型选择的下一步，再把结果放回状态中，让模型继续判断。

循环必须有明确停止条件，否则可能重复调用、消耗预算或持续执行错误操作。

## 举个例子

任务是：“找到测试失败原因。”

```text
目标：定位失败原因
   ↓
决定：先运行测试
   ↓
行动：调用终端
   ↓
观察：得到报错与文件位置
   ↓
决定：读取相关代码
   ↓
行动：调用文件工具
   ↓
观察：获得新信息
   ↺
直到给出有证据的结论或停止
```

每一轮的新结果会影响下一轮，所以它不只是提前写死的一串命令。

## 严格来说

Agent Loop 常可概括成：

```text
Observe：读取目标、状态与最新结果
   ↓
Decide：模型决定下一步
   ↓
Act：执行回答、工具调用或请求确认
   ↓
Update：记录结果并更新状态
   ↺
```

不同系统可能把 Planning、Reasoning、Acting、Reflection 等阶段拆开或合并。这些名称不是所有 Agent 必须遵守的固定标准。

## 状态里通常有什么？

状态可能包含：

- 原始目标与完成标准；
- 已执行步骤和工具结果；
- 当前计划或待办项；
- 文件、页面或外部系统的最新状态；
- 剩余步骤、时间和费用预算；
- 用户确认与权限信息；
- 已知错误和重试次数。

状态不一定全部塞进一次模型 Context。系统可以把部分信息保存在数据库、文件或 Memory 中，再按需取回。

## Loop 什么时候停止？

至少要考虑：

- Success：达到可验证的完成标准；
- Failure：无法完成或关键依赖失败；
- Human Input：需要用户选择、凭证或高风险确认；
- Limit：达到最大步骤、时间、Token 或费用；
- Cancel：用户或系统请求取消；
- Safety Stop：操作违反权限或安全策略。

“模型觉得完成了”可以是信号，但重要任务还应由程序检查结果、测试或证据。

## 错误会怎样累积？

如果一轮误读工具结果，下一轮可能基于错误前提继续行动。重试也可能重复发送消息、创建资源或修改文件。

因此 Agent Loop 常需要：

- 对工具输入输出做验证；
- 对有副作用的操作设置确认；
- 使用幂等设计，避免同一请求重复造成额外影响；
- 保存日志和检查点；
- 限制重试次数与总预算；
- 支持取消、回滚或转交人工。

“幂等”可以先理解成：同一个请求重复执行时，不会不断制造新的副作用。

## Loop 和 Planning 是一回事吗？

不是。Planning 决定准备怎样推进；Loop 负责让系统反复执行、观察和更新。

Agent 可以先生成完整计划，也可以每轮只决定下一步。即使有好计划，工具结果变化后仍可能需要调整。

## 最容易搞混的东西

### Agent Loop ≠ 无限循环

Loop 表示允许多轮反馈，不代表可以不设上限地运行。

### Agent Loop ≠ 对话历史

对话历史只是可能的状态来源。Loop 还包括执行、观察、权限、预算与终止控制。

### Agent Loop ≠ Workflow

Workflow 的分支多由程序预先定义；Agent Loop 中的下一步更多由模型根据状态动态选择。实际系统常组合两者。

### 重试 ≠ 修复

在原因不变时盲目重试可能只会重复失败。系统应读取错误、改变策略或停止升级处理。

## 常见误区

### 误区 1：循环次数越多，答案越好

不对。更多步骤也会增加延迟、费用、上下文噪声和错误传播。

### 误区 2：模型可以独自判断所有停止条件

预算、权限和超时应由外部程序强制执行，不能只写在 Prompt 中。

### 误区 3：工具成功返回就代表任务完成

工具调用成功只说明一个步骤完成。系统还要核对它是否满足最终目标。

## 为什么我要知道它？

Agent Loop 是 Agent 能连续做事的核心，也是许多风险出现的位置。理解它以后，你能看出为什么长任务需要状态、预算、恢复、验证和人工介入，而不只是“给模型一个更长 Prompt”。

## 你只需要记住

1. Agent Loop 把“观察 → 决定 → 行动 → 更新”重复起来，让新结果影响下一步。
2. 状态可以包含历史、工具结果、预算、权限与错误，不等于单纯聊天记录。
3. 成功、失败、确认、预算、取消和安全策略都应成为停止条件。
4. 多轮执行会累积错误与成本，需要验证、限制、日志和恢复机制。
