# Workflow 和 Agent 有什么区别？

> Level: `Core` · Path: `Main`

## 一个小白真的会怎么问？

> 只要流程里用了大模型，就叫 Agent 吗？
>
> Workflow 和 Agent 到底应该选哪个？

## 先说人话

Workflow（工作流）的主要步骤和分支通常由程序预先规定；Agent 则让模型根据当前状态动态决定下一步怎样推进。

两者不是“旧技术”和“新技术”的关系，也不是绝对二选一。很多可靠系统会用 Workflow 管住整体边界，在局部使用 Agent 处理不确定任务。

## 举个例子

处理报销单可以写成固定 Workflow：

```text
读取表单
  ↓
检查必填字段
  ↓
金额超过阈值？── 是 → 经理审批
  │
  否
  ↓
进入付款流程
```

步骤和分支由业务规则决定。模型可以负责识别票据，但不能自行改写审批规则。

如果任务是“研究竞争产品并形成报告”，系统可能让 Agent 根据搜索结果决定继续查什么、比较哪些资料和何时补充证据。

## 严格来说

可以从“谁控制下一步”来区分：

| 方式 | 下一步主要由谁决定 | 适合的任务 |
|---|---|---|
| Workflow | 程序预先定义的步骤与条件 | 稳定、可预测、强合规流程 |
| Agent | 模型结合目标与当前状态动态选择 | 路径难以提前穷举的开放任务 |

这是教学上的重点，不表示 Workflow 完全不能有动态分支，也不表示 Agent 没有外部规则。

## Workflow 可以使用模型吗？

可以。例如：

```text
固定步骤 1：提取合同字段（调用模型）
固定步骤 2：规则校验
固定步骤 3：人工审批
固定步骤 4：写入系统
```

模型参与某一步，不会自动把整个流程变成 Agent。关键要看主要控制路径是否由模型持续动态决定。

## Agent 可以放在 Workflow 里吗？

可以。常见组合是：

```text
固定接收与权限检查
        ↓
局部 Agent 研究或处理不确定任务
        ↓
固定验证、审批与发布
```

这样既利用 Agent 的适应性，又让权限、预算和高风险操作留在可预测边界内。

## 应该怎么选？

先问四个问题：

1. 主要步骤能否提前明确？
2. 错误后果有多严重？
3. 是否必须审计每个决策路径？
4. 动态探索带来的价值是否值得额外成本和风险？

如果固定代码和一次模型调用已经足够，就没有必要增加 Agent Loop。只有当路径确实依赖中间结果、难以预先写完时，Agent 才更有价值。

## 最容易搞混的东西

### Workflow ≠ 完全没有 AI

Workflow 可以在固定节点调用模型、搜索或其他工具。

### Agent ≠ 没有流程

Agent 仍受循环、权限、工具、停止条件和外部审批控制，只是局部步骤更动态。

### 动态 ≠ 随意

模型选择下一步，也必须在允许的工具、数据、预算和策略范围内。

### Agent ≠ 一定更高级

对于付款、权限变更等稳定高风险流程，明确 Workflow 往往更容易测试和审计。

## 常见误区

### 误区 1：分支很多就是 Agent

程序预先写好的复杂条件树仍然是 Workflow。复杂度不是判断标准。

### 误区 2：Agent 可以替代所有业务规则

不应如此。合规、授权、金额阈值和数据边界等规则通常需要由程序强制执行。

### 误区 3：Workflow 永远比 Agent 可靠

固定流程更可预测，但错误规则、坏数据和外部服务失败仍会造成问题。可靠性需要测试和监控，而不是只看名称。

## 为什么我要知道它？

理解这个区别，能避免把所有自动化都包装成 Agent，也能帮助系统设计者把“需要模型判断的部分”和“必须固定执行的部分”放在正确位置。

## 你只需要记住

1. Workflow 的主要路径由程序预先定义；Agent 更依赖模型动态选择下一步。
2. Workflow 可以调用模型，Agent 也可以被包在 Workflow 中。
3. Agent 不一定更高级，应按任务不确定性、风险、成本和审计要求选择。
4. 权限、审批和关键业务规则应由外部系统强制执行。
