# 什么是模型？

> Level: `Core`

## 读完你应该明白

1. 模型是训练后形成的一套计算关系，能把新输入转换成输出。
2. 模型不等于训练数据、训练算法、参数、文件或最终产品。
3. 训练前先有模型的结构和初始状态，训练后才得到可用的具体模型。
4. 模型是理解 LLM、参数、训练和推理的共同起点。

## 一个小白真的会怎么问？

下面的问题来自真实聊天记录：

> 一个模型是怎么诞生的？
>
> 你说“把数据喂给模型”，但是这个模型原本是怎么诞生的？
>
> 我是不是可以理解：每个模型一开始就是一堆参数，先定好参数量，然后根据学习资料训练？

这些提问很好地暴露了一个常见的循环解释：如果说“训练就是让模型学习数据”，那训练开始前的“模型”到底是什么？

## 先说人话

模型可以先理解成：**从许多例子中调整出来的一套计算规则，用来处理没见过的新输入。**

你给它一个输入，它按照训练后形成的关系，给出预测、分类、文字或其他输出。

## 举个例子：估算二手房价格

假设我们收集了许多已经成交的房子：

```text
面积、位置、楼龄等信息 → 实际成交价
```

训练方法会利用这些例子，调整“不同信息应当怎样影响估价”。训练完成后，我们得到一个模型：

```text
新房子的面积、位置、楼龄
            ↓
          模型
            ↓
        预测价格
```

模型不是那张历史成交表。它是从历史例子中形成、可以用于新房子的计算关系。

你也可以暂时把它类比成一份调试过的“配方”：给定材料，按照配方得到结果。

但这个类比有边界：真实机器学习模型是数学和程序可以执行的计算结构，不是一段人能直接读懂的自然语言配方。

## 严格来说

在机器学习中，模型是**从训练数据或其他训练信号中得到的计算表示，用于把输入映射成输出**。

不同模型可以完成不同任务：

- 输入一封邮件，输出“垃圾邮件”的可能性；
- 输入一张图片，输出图片中物体的类别；
- 输入一段文字，输出接下来可能出现的 Token；
- 输入一段音频，输出识别出的文字。

对于许多常见模型，可以先把它分成两部分理解：

```text
模型结构：允许信息按照什么方式流动和计算
      +
训练得到的参数：具体计算时使用的可调整数值
      =
一个训练后的具体模型
```

“结构 + 参数”是理解神经网络模型的实用框架，但不是对世界上所有模型形式的唯一划分。

## 训练开始前，模型从哪里来？

更准确的顺序是：

```text
1. 明确任务
   输入是什么？希望输出什么？
        ↓
2. 选择或设计模型结构
   允许它用什么方式完成计算？
        ↓
3. 建立初始状态
   可调整的部分先有初始值，此时通常还不会做好任务
        ↓
4. 训练
   用数据和训练方法反复调整可学习的部分
        ↓
5. 评估
   检查它处理新数据时是否达到要求
        ↓
6. 保存与部署
   把训练结果保存，并放进能对外工作的系统
```

所以，“训练前有没有模型”有两个不同答案：

- **有模型结构和初始状态**：计算方式已经被选定或设计出来。
- **还没有训练好的可用模型**：具体参数还没有通过训练形成有效行为。

这就像先搭好一台可调的机器，再通过许多示例逐步校准它。这里的“机器”和“校准”都只是类比；真实过程由代码、数据和数学计算完成。

## 参数量是一开始拍板定的吗？

不宜理解成“先随便写下一个参数量，再往里面塞数据”。

对神经网络来说，设计者会先选择模型结构，例如有多少层、每一层怎样连接、每层处理多宽的信息。这个结构通常决定了需要多少个可调整参数。

```text
结构设计
   ↓
可调整数值放在哪里、共有多少个
   ↓
参数量
```

设计者当然会根据计算成本和目标规模反复调整结构，但参数量通常是结构设计的结果之一，不是一只独立的“知识容量旋钮”。

参数到底是什么、参数量又能说明什么，会在后续文章单独展开。

## 为什么需要“模型”这个概念？

如果每种情况都能写成明确规则，普通程序就足够了。

但许多任务很难穷举规则。例如，要靠人写出“所有猫在所有角度和光线下长什么样”，几乎不可能。

```text
现实情况太多
   ↓
人无法写完所有规则
   ↓
用大量示例训练一个模型
   ↓
让模型把学到的关系用于新输入
```

模型让系统可以根据数据形成计算行为，而不要求开发者手写每一种输入对应的答案。

## 最容易搞混的东西

| 概念 | 它负责什么 | 为什么不等于模型 |
|---|---|---|
| 训练数据 | 提供学习用的示例或信号 | 数据是学习材料，模型是训练后形成的计算关系 |
| 训练算法 | 规定怎样调整模型 | 它是“怎么学”的方法，不是“学完后的结果” |
| 参数 | 模型中可由训练调整的数值 | 参数是许多模型的重要组成部分，但单说参数没有说明完整结构和用法 |
| 模型文件 | 在硬盘上保存结构信息和参数等内容 | 文件是模型的一种存储形式 |
| API | 让其他程序按约定请求某项能力的接口 | API 可以提供模型服务，也可以提供完全不含模型的服务 |
| 产品 | 用户真正使用的完整应用 | 产品还包含界面、服务器、规则、工具和数据等部分 |

### 模型 ≠ 训练数据压缩包

模型可能从训练数据中学到统计关系，但通常不能被当作一张可以逐条找回原文的资料表。

它有时也可能记住训练样本的片段；这不改变模型和数据库是不同系统这一点，也会带来隐私与安全问题。

### 模型 ≠ 算法

日常讨论中，人们有时会宽松地把算法和模型混用。为了后续学习，本项目采用更清楚的区分：

```text
训练算法：怎样根据反馈调整
模型：调整后拿来处理新输入的计算关系
```

### 模型 ≠ 产品

当你打开一个聊天应用时，面对的通常不是裸模型：

```text
聊天界面
 +
服务程序
 +
提示与安全规则
 +
一个或多个模型
 +
搜索、文件等工具
```

模型是核心部件之一，但不能代表完整产品。

## 常见误区

### 误区 1：模型就是一堆参数

对神经网络模型来说，参数非常重要，但参数必须放在某种结构中参与计算。更稳妥的理解是：结构规定怎样计算，训练得到的参数决定具体怎样算。

### 误区 2：参数越多，模型一定越聪明

参数量只是影响模型能力、成本和容量的因素之一。结构、数据、训练方法、评估方式和运行条件同样重要。这个问题会在“参数”文章中展开。

### 误区 3：和模型聊天，就是在训练它

大多数普通使用场景是在做“推理”：模型使用已经训练好的参数处理当前输入。

应用可以保存聊天记录或用户记忆，但这不等于底层模型的训练参数在每次对话后自动改变。

## 为什么我要知道它？

“模型”是后面许多概念的中心：

- LLM 是处理语言的一类大型模型；
- 训练是在调整模型；
- 参数是许多模型中可被训练调整的数值；
- 推理是用训练好的模型处理新输入；
- API 可以把模型能力提供给其他程序；
- Agent 可以调用模型来判断下一步行动。

如果没有先分清模型和产品、数据、算法，后面的每一层都会混在一起。

## 它和前后知识是什么关系？

```text
AI：希望机器完成智能任务
 ↓
机器学习：从数据中学习规律的方法
 ↓
模型：训练后形成、用于新输入的计算关系
 ↓
大语言模型：主要处理和生成语言的一类大型模型
 ↓
参数与训练：模型具体怎样被调整出来
```

## 你只需要记住

1. 模型是训练后形成的、把新输入转换成输出的计算关系。
2. 训练前先有结构和初始状态，训练后才得到可用的具体模型。
3. 模型不等于训练数据、训练算法、参数文件或完整产品。
4. 对常见神经网络，可以先用“结构规定怎样算，参数决定具体怎样算”来理解。
