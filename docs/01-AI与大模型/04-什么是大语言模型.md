# 大语言模型到底是什么？

> 你现在的位置：[模型](./03-模型到底是什么.md) → **语言模型 → 大语言模型** → [GPT 与 ChatGPT](./05-GPT和ChatGPT有什么区别.md)
>
> 课程导航：[上一篇：模型到底是什么](./03-模型到底是什么.md) · 第 4 / 32 篇 · [下一篇：GPT 和 ChatGPT 有什么区别](./05-GPT和ChatGPT有什么区别.md)

“大语言模型”这几个字看起来像是在说一种很大、很会说话的 AI，但里面其实叠了三层概念：它先是一个模型，再是一个语言模型，最后才因为规模与训练范围被称为“大语言模型”。如果这三层没有拆开，LLM、聊天机器人、Transformer、基础模型很快就会混成一团。

两个追问最容易暴露概念边界：语言模型究竟在对什么建模？大语言模型和基础模型是不是同一个东西？把它们分清，比先记各种模型名称更重要。

## 它建模的不是“语言知识清单”

先看一句没有写完的话：

```text
请把窗户关上，外面开始____
```

“下雨”“刮风”“降温”都可能接在后面，“吃饭”通常就不太合适。语言模型要做的核心工作，是根据前面已经出现的内容，为接下来可能出现的语言单位分配概率。这里的语言单位在现代模型里通常是 [Token](../02-聊天Token与上下文/04-Token到底是什么.md)，它可能是一个字、词的一部分、标点或其他片段，并不固定等于一个汉字或一个英文单词。

更严格地说，语言模型描述的是语言序列的概率规律。它不只需要知道某个词常不常见，还要结合前面的内容判断：在**这个位置、这个语境**里，哪些后续更合理。序列越长，前文提供的条件越多，模型要捕捉的关系也越复杂。

早期语言模型可以数“几个词经常连续出现”，现代神经网络语言模型则会把前文转换为数值表示，再通过大量计算得到后续 Token 的概率分布。方法变化很大，但“对语言序列中的可能性建模”这条主线没有变。

## 一次生成是怎样继续下去的

许多今天用于聊天和写作的 LLM 采用自回归生成：每次根据已有内容预测下一个 Token，把选中的 Token 接回去，再预测下一次。它看起来像一次写出整段回答，底层却是一个不断循环的过程。

这张图想帮你看懂：一段回答为什么会从同一个预测动作逐步长出来。

```text
用户输入与已有文本
        ↓
模型计算下一个 Token 的概率
        ↓
按生成规则选出一个 Token
        ↓
把新 Token 接回已有文本
        ↓
未结束？回到上一步继续
```

读图时最重要的是循环箭头。模型不是先在内部找到一段完整答案，再像复制文件一样吐出来；后面每一步都会受到前面已经生成内容的影响。也正因为如此，一次较早的错误可能继续影响后文。

“预测下一个 Token”很容易被误解成手机输入法。两者确实有表面相似之处，但规模、训练范围和要利用的上下文并不相同。要在小说、代码、问答、说明书等大量文本里持续减少预测错误，模型会被迫学习词语搭配、语法结构、文本中的事实关联、任务格式以及许多可复用模式；这些模式经过 [训练](../03-模型原理与训练/18-训练和推理有什么区别.md) 写入模型的[参数](../03-模型原理与训练/06-参数到底是什么.md)中。

这仍不意味着“只要猜词就必然获得可靠推理”。训练目标、数据、模型结构和训练过程共同影响最后形成什么能力；模型也可能只是复现表面规律、记住片段，或在没把握时生成听起来顺畅的错误内容。后面的[为什么预测下一个 Token 能学到能力](../03-模型原理与训练/10-为什么预测下一个Token能学到能力.md)会专门处理这层问题。

## Large 没有一条永远不变的及格线

语言模型前面加上 Large，通常是在同时描述几种规模：可训练参数很多，训练数据与计算投入很大，训练覆盖的语言和任务范围较广。它往往因此能用同一组参数处理续写、摘要、翻译、问答和代码等多种任务，而不必每个任务从零训练一套模型。

但行业里没有一条跨年代、跨架构都有效的规则，说“超过 X 个参数才准叫 LLM”。参数数量很醒目，却不是唯一尺度。训练数据是否充分、架构怎样使用参数、训练目标是什么、计算预算怎样分配，都会改变同样参数量所能达到的效果。

因此，Large 更像一个相对于同时代同类模型的描述，不是技术认证。今天被称为小模型的规模，放到更早的时期可能已经很大；不同研究或产品文档也可能采用不同边界。看到“7B”“70B”之类数字时，应把它理解成具体模型的参数量，而不是判断它是不是 LLM 的唯一开关。

## LLM、Transformer 和基础模型各管一层

很多概念会在这里同时出现，因为它们观察的是同一个系统的不同侧面。

| 名称 | 它主要在描述什么 | 不能据此直接推出什么 |
|---|---|---|
| 语言模型 | 对语言序列的可能性进行建模 | 不代表规模一定很大 |
| LLM | 规模与训练范围较大的语言模型 | 不代表它就是完整聊天产品 |
| [Transformer](../03-模型原理与训练/03-Transformer到底是什么.md) | 信息怎样流动和计算的一类模型架构 | 不只用于语言，也不等于 LLM |
| 基础模型 | 在广泛数据上训练、可适配多种下游任务的模型 | 不一定只处理语言 |

许多现代 LLM 使用 Transformer，因此两个词经常一起出现，但语言模型早于 Transformer 存在，Transformer 也能处理图像、音频等其他类型的信息。一个词回答“模型在处理什么、规模如何”，另一个词回答“内部计算结构怎样组织”。

“基础模型”强调的是广泛训练后还能适配许多任务。很多 LLM 同时是基础模型，因为它们能通过提示、微调或其他方式服务于多种语言任务；基础模型的范围却更广，也可以以图像、音频或多模态为主要对象。所以两者有很大交集，却不是同义词。

## 会聊天的是模型，还是一整套产品？

LLM 接收当前[上下文](../02-聊天Token与上下文/07-上下文和上下文窗口是什么.md)，使用已经训练好的参数做推理，再逐步生成输出。普通的一次推理不会自动把这次聊天永久写回参数。产品若要保存历史、搜索网页、读取文件或记住用户偏好，还需要在模型外增加存储、工具、权限和上下文管理。

```text
聊天界面
  ↓
产品整理系统规则、历史消息和用户输入
  ↓
LLM 根据当前上下文生成内容
  ↓
产品可能继续调用搜索、文件或其他工具
  ↓
把最终结果展示给用户
```

所以“LLM 会不会联网”和“某个聊天产品能不能联网”是两个问题。模型本身的参数不会因为界面上多了搜索按钮就改变；产品可以把搜索结果放进上下文，再让模型据此回答。下一篇会用 GPT 和 ChatGPT 把模型层与产品层彻底分开。

## 语言概率也解释了它为什么会犯错

一个后续 Token 在语言上很合理，不代表它在现实世界中为真。模型可以学会论文引用通常长什么样，也可能据此拼出一条格式完美、实际不存在的引用；它可以生成像法律条文的句子，却没有数据库那样的逐条存在性检查。

这类看似合理但缺乏事实依据的输出通常被称为[幻觉](../05-幻觉与模型局限/01-幻觉是什么.md)。规模扩大、训练改进和外部资料可以降低某些错误，却不能把“生成最合适的后续”自动改造成“每句话都经过事实核验”。遇到医疗、法律、财务、当前新闻或精确引用时，仍要使用适当来源验证。

这也划出了“大语言模型”的能力边界：它可以压缩和重组训练中学到的广泛模式，也能根据当前上下文完成新任务；但它不是知识条目的完整副本，不会仅凭流畅语气就获得事实保证，更不能由会说“我理解了”推断出人的意识或主观体验。

## 回到开头的两个真实问题

**语言模型究竟在对什么建模？** 它对语言序列中的概率关系建模：给定已有内容，计算后续语言单位出现的可能性。现代生成式 LLM 常把这个过程实现为逐 Token 预测与生成，但语言模型这个大类并不限于某一个具体架构。

**LLM 和基础模型是一回事吗？** 不是。LLM 强调它是一种大规模语言模型；基础模型强调广泛训练后可以适配许多任务。许多 LLM 同时满足两种描述，但基础模型还可以面向图像、音频或多模态。

如果还想判断一个东西是不是 LLM，可以依次问：它是否在建模语言序列？规模与训练范围是否足以支撑广泛语言任务？你现在看到的是模型本身，还是一个把模型、工具和界面组合起来的产品？这三问比只盯着参数量更可靠。
