# NLP 和 Computer Vision 是什么关系？

> 所属专题：AI 与大模型 · 前置：[AI 到底是什么](./01-AI到底是什么.md) · 相关：[多模态模型是什么](../04-模型能力/05-多模态模型是什么.md)

有人在公开社区问：[计算机视觉和数字图像处理算不算人工智能的一部分？](https://ai.stackexchange.com/questions/8846/are-computer-vision-and-digital-image-processing-part-of-artificial-intelligence) 还有人想把人的语言、表情和动作一起交给系统，于是追问：[NLP 和 CV 到底怎样组合？](https://ai.stackexchange.com/questions/35878/current-state-of-the-art-and-datasets-for-combining-nlp-and-cv) 这两条中文问题是对原帖的转述。

它们背后有同一个认知卡点：NLP、CV、模型、算法和数据类型经常被当成同一层。实际上，NLP 与 CV 更像两片会交叉的任务领域；它们可以使用相同的机器学习方法，也可以被一个多模态系统连接起来。

## 一个处理快递单的例子

假设系统收到一张快递单照片，要回答：“收件地址在哪里，是否缺少省份？”

它可能依次完成：

```text
照片
  ↓ 识别版面、文字区域和字符
“收件地址：朝阳区……”
  ↓ 理解字段、地点与句子含义
结构化地址 + 缺失项判断
  ↓
给用户的回答
```

前半段主要涉及计算机视觉（Computer Vision，CV）和光学字符识别（OCR）：系统要从像素、位置和版面中找到文字。后半段主要涉及自然语言处理（Natural Language Processing，NLP）：系统要处理词语、句子、实体和语义。

真实流程不会永远切得这么整齐。表格行列、印章遮挡和字段名称同时包含视觉结构与语言信息；现代文档模型可能一次联合处理图像、文字与坐标。这个例子不是要画死部门边界，而是帮助你先区分“看到了什么”和“这些符号表达什么”。

## NLP 是处理人类语言的一组问题

NLP 研究怎样让计算系统处理、分析和生成人类语言。输入可以是文字，也可以是语音识别后得到的文本；任务包括分类、检索、信息抽取、翻译、摘要、问答与生成。

NLP 不是某一个模型，也不等于大语言模型。早期与今天的系统都可能使用：

- 字典、语法和人工规则；
- 统计模型与传统机器学习；
- 神经网络、Transformer 与大语言模型；
- 检索、知识库和程序规则组成的混合系统。

LLM 是 NLP 领域里影响很大的一类模型，却没有覆盖语言技术的所有问题。例如精确关键词匹配、敏感词规则、搜索索引和结构化解析，仍可能由更简单、更可控的方法完成。

## CV 是让系统处理视觉信息的一组问题

计算机视觉研究怎样从图像、视频和其他视觉信号中提取、组织或生成有用信息。常见任务包括图像分类、目标检测、分割、跟踪、姿态估计、OCR 和视觉生成。

CV 也不是“一个会看图的模型”。一个交通系统可能用相机标定、几何算法、目标检测网络和跟踪器共同处理视频；图像编辑软件可以调整亮度和裁剪尺寸，却未必涉及学习或语义理解。

这就是“数字图像处理是否属于 AI”无法只答是或否的原因。图像处理按规则改变像素，例如去噪、锐化、缩放；计算机视觉更关心从视觉信号得到对象、位置、动作或语义。二者大量重叠，但不是每个图像处理算法都需要 AI，也不是每个 CV 系统都只有深度学习模型。

## 它们和 AI、机器学习是什么层级

可以把关系画成一张有重叠的地图，而不是一棵严格的树：

```text
人工智能及相关计算领域
├─ 自然语言处理：重点处理语言
├─ 计算机视觉：重点处理图像与视频
├─ 语音、规划、机器人、推荐……
└─ 多模态系统：让多种信息在同一任务中协同

机器学习 / 深度学习 / Transformer
└─ 是上面多个领域都可以采用的方法
```

这张图想帮你分清“问题领域”和“实现方法”。读图时注意 Transformer 没有只挂在 NLP 下面：同一种架构思想可以处理文本，也可以经过适配处理图像、音频或多种输入。

[机器学习](./02-AI机器学习和深度学习是什么关系.md)解决“怎样从数据中调整模型”，NLP 和 CV 更常回答“系统在处理哪类信息、解决哪类任务”。因此一句“这个项目用 NLP 还是机器学习”通常问错了层级；它完全可能是“用机器学习方法完成 NLP 任务”。

## 为什么两边都能用 Transformer

模型不能直接看到“句子”或“猫”，首先接收到的是数值表示。文本可以被 Tokenizer 编码成 Token 序列；图像可以切成小块、提取视觉特征，再转成一系列向量。只要架构能处理这些表示，注意力等机制就可以在不同位置之间交换信息。

这不表示文本 Token 与视觉 Token 完全相同。它们来自不同编码过程，保留的信息和训练目标也不同。语言有离散符号与顺序，图像还有二维空间、纹理、尺度和颜色。把两种输入都排成序列，只是提供了一种共同计算接口，不会消除模态差异。

视觉 Transformer 展示了 Transformer 架构可以直接用于图像块序列；CLIP 则通过图像—文本配对数据学习可比较的视觉与语言表示。后来的多模态模型还可能使用独立视觉编码器、连接层和语言模型，或采用更统一的架构。具体产品怎样做属于易变的模型设计，不能从“能看图”反推出唯一结构。

## NLP 和 CV 怎样组合

最直观的组合方式是让两个模块先各自处理输入，再在后面合并：

```text
文字 ──语言编码──┐
                 ├─ 对齐 / 融合 ─→ 联合判断或生成
图像 ──视觉编码──┘
```

图像问答、图片描述、文档理解、视频字幕、根据文字找图，都需要视觉与语言建立联系。系统可以在较早阶段让两种特征交互，也可以先独立编码、在较晚阶段对齐；选择取决于任务、数据、延迟和训练成本。

组合并不自动保证理解更准确。语言可能说“左边那个杯子”，视觉模块必须保留位置；讽刺、表情与动作需要合适的时间和语境数据；OCR 读错一个数字，后面的语言模型可能把错误补成一段很流畅的解释。评估时必须分别检查视觉识别、跨模态对齐和最终生成，不能只看最后一句是否自然。

## 用输入和任务判断，而不是看产品名字

| 问题 | 主要涉及 | 还可能依赖 |
|---|---|---|
| 判断评论情绪 | NLP | 领域词表、分类模型 |
| 找出照片里的车辆 | CV | 检测模型、相机条件 |
| 从发票照片提取金额 | CV + NLP | OCR、版面、字段规则 |
| 根据图片回答问题 | CV + NLP / 多模态 | 对齐、推理、生成 |
| 按文字描述生成图片 | 生成式视觉 + NLP | 文本编码、图像生成 |

“主要涉及”不是排他标签。真实产品还会加入数据库、权限、工具、人工复核与普通软件。领域名称帮助团队组织问题，却不能替代完整系统图。

## 回答开头的两个问题

**计算机视觉属于 AI 吗？** 计算机视觉通常被视为 AI 的重要相关领域，大量任务使用机器学习；但数字图像处理与 CV 也包含不需要学习或智能判断的算法。更准确的说法是看具体任务与方法，而不是把所有像素操作都叫 AI。

**NLP 和 CV 是什么关系？** 它们分别以语言和视觉信息为重点，是可以重叠的任务领域，不是上下级模型。两者可以使用相同的深度学习与 Transformer 方法，也可以在多模态系统中通过表示对齐和信息融合共同完成任务。

**多模态是不是把 NLP 模型和 CV 模型简单拼起来？** 拼接两个模块是一种实现，但不是唯一方式，也不会自动解决对齐。系统仍要决定怎样编码、何时交互、如何训练，并分别验证各阶段错误。
