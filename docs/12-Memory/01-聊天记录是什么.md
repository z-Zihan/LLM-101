# Conversation History 是什么？

> Level: `Core` · Path: `Main`

## 先说人话

Conversation History（对话历史）是产品保存的一系列用户消息、助手回复和相关事件。

它不等于模型能在本次计算中看到的全部 Context，也不等于模型参数里的长期记忆。

## 举个例子

一个聊天页面可能显示过去 200 条消息，但本次请求实际发送给模型的可能是：

```text
System instructions
 + 最近若干消息
 + 更早对话的摘要
 + 当前检索到的相关记录
```

“界面还能翻到”不保证每个字都再次进入模型 Context。

## 产品怎样使用历史？

应用可以：

- 原样发送最近消息；
- 截断过旧内容；
- 把早期对话总结后发送；
- 只检索与当前问题相关的片段；
- 把工具调用和结果也保存为事件；
- 完全不保存某些临时会话。

具体行为取决于产品设计、隐私设置和容量限制。

## History、Context、Memory 的区别

```text
Conversation History：保存过的对话记录
Context：本次模型计算实际可用的信息
Memory：系统跨会话保存并在未来取回的信息机制
```

History 可以成为 Context 或 Memory 的来源，但三者不是同义词。

## 为什么会丢失早期细节？

- Context Window 有容量上限；
- 系统可能截断或总结旧消息；
- 摘要会丢失细节；
- 检索可能没有选中相关历史；
- 内容进入窗口也不保证被正确利用。

因此重要事实不应只依赖很久以前的一句聊天。

## 保存聊天会训练模型吗？

不会自动发生。保存记录是产品数据状态；训练模型需要独立的数据处理和训练流程。

某些服务可能依据其政策使用部分数据改进模型，但这属于具体产品的数据政策，不能从“有历史记录”直接推出。

## 隐私与控制

Conversation History 可能包含个人信息、文件内容和凭证。产品需要定义保存期限、访问权限、删除能力和是否用于其他目的。用户也不应在不可信会话中发送秘密。

## 常见误区

### 误区 1：聊天窗口里可见，模型就一定看得见

界面状态与模型请求 Context 是不同层。

### 误区 2：模型提到旧消息，就永久记住了

它可能只是当前 Context 包含历史或摘要。

### 误区 3：删除界面消息就一定删除所有副本

具体删除范围取决于产品存储、备份和政策，需要查看官方说明。

## 你只需要记住

1. Conversation History 是产品保存的消息与事件记录。
2. 本次 Context 可能只包含部分历史、摘要或检索片段。
3. History 不等于长期 Memory，也不等于训练参数。
4. 保存、使用和删除历史属于产品数据与隐私设计。
