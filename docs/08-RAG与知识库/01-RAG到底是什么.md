# RAG 到底是什么？

>
> 课程导航：[上一篇：Agent 到底是什么](../07-Agent/01-Agent到底是什么.md) · 第 27 / 32 篇 · [下一篇：知识库是什么](./02-知识库是什么.md)

常见问题是：“RAG 检索增强是什么，为什么说它能让模型先查资料再回答？”RAG（Retrieval-Augmented Generation，检索增强生成）就是一条“检索外部资料，再依据资料生成”的流程。它让模型在当前请求中使用私有或更新的信息，不需要每次资料变化都重新训练参数。

“开卷考试”是不错的入门类比，但开卷不保证找对页，也不保证读懂。RAG 的检索和生成都需要单独评估。

## 一条公司政策如何进入回答

用户问“今年差旅住宿上限是多少”，模型参数未必包含内部政策。系统先在有权限的资料范围里检索相关段落，把原文、标题和位置放入上下文，再让模型根据证据回答。

```text
问题
  ↓ 生成检索请求
知识库 / 搜索 / 数据库
  ↓ 返回相关片段和来源
把证据加入 Context
  ↓
模型生成答案与引用
  ↓
验证结论是否受证据支持
```

这张图想说明 RAG 没有把资料永久写进模型。读图时注意，模型通常只看到本次检索出的有限片段；知识库里其他内容不会自动进入上下文。

## 建库和回答是两个阶段

准备阶段收集资料、解析格式、清理重复与旧版本、切分内容、保存元数据并建立索引。回答阶段接收问题、检索、重排、组织上下文、生成并返回来源。

索引可以使用关键词、向量、SQL、知识图谱或混合方法。RAG 不等于向量数据库，也不要求所有资料都先做 Embedding。选什么检索方式，应由数据结构和问题类型决定。

原始 RAG 研究强调把生成模型的参数化能力与可检索的外部信息结合；今天产品语境里的 RAG 范围更宽。说明系统时最好把实际数据源、检索方式和验证流程写出来，而不是只贴一个标签。

## RAG 解决什么，不解决什么

它适合模型训练时没见过的私有资料、频繁更新的政策，以及需要引用出处的知识任务。更新外部资料通常比重新训练整个模型快，也更容易做权限与版本管理。

RAG 不负责把模型训练成新的写作风格，也不会自动获得业务操作权限。它在请求时改变上下文，不改变底层参数；微调则通过训练更新参数。两者可以组合，但解决的问题不同。

RAG 也不依赖 Agent。固定 Workflow 完全可以执行“检索—生成—返回”；Agent 只在需要根据结果继续搜索、换数据源或追问用户时增加动态循环。反过来也一样：一个只会读文件、调用计算器或操作业务 API 的 Agent，可以完全没有 RAG。

二者不是“基础版和高级版”的关系。RAG 解决的是**怎样把外部资料带进本次回答**，Agent 解决的是**怎样围绕目标根据新状态继续选择行动**。需要查资料的 Agent 可以把 RAG 当作一种能力，普通问答系统也可以只用 RAG 而没有 Agent Loop。

## 为什么给了正确资料仍会答错

知识库可能缺失、过时或权限标记错误；查询可能没有表达真正意图；切片可能把条件与结论分开；检索排序可能把相似但错误的版本放在前面。即使正确片段进入上下文，模型仍可能忽略限定条件、混入参数记忆或写出证据没有支持的内容。

因此至少要测两层：检索是否找到支持答案的证据，生成是否忠实依据证据。只看最终回答，很难判断应该修索引、查询、上下文组织还是模型提示。

引用也不能自动证明正确。应确认引用真实存在、对应段落相关，并确实支持旁边的主张。高风险回答还需查询权威记录或人工复核。

## 检索越多越好吗

过少可能漏证据，过多会占用上下文并增加冲突。系统需要平衡相关性、覆盖、多样性、时效和权限。重排器可以把候选结果重新排序，但也会犯错。

答案找不到证据时，系统应允许拒答、说明缺口或请求更多信息，而不是把“最相似片段”强行改写成确定答案。无答案场景是 RAG 评测中不可缺少的一部分。

## 能运行的示例离实用系统还差什么

“固定长度切块—生成向量—取 Top-k—拼进 Prompt”能说明基本原理，却没有覆盖一条实用管线的全部责任。资料进入系统前要处理解析错误、版本、权限和元数据；查询进入后可能需要澄清、改写或拆分；召回可以组合关键词、向量和结构化过滤，再由重排器缩小候选。

进入生成阶段时，系统还要控制上下文顺序、去除重复和冲突，要求回答能回到具体来源。没有证据时要允许拒答。上线后则要记录每次查询、候选、最终上下文、模型版本、延迟和费用，否则一次错误回答很难复现。

这并不表示每个项目都要一次装齐所有组件。先建立一组真实问题和应命中的证据，用最简单方案跑出基线；观察失败发生在解析、召回、排序还是生成，再增加对应环节。组件越多，调试和运维的接口也越多。

## 回答几个真实问题

**RAG 是搜索、数据库还是训练方法？** 它是检索与生成组合的流程；搜索或数据库可以是其中的数据与检索组件，通常不通过当前请求更新模型参数。

**为什么模型没学过公司资料也能回答？** 因为相关资料被检索并放入当前上下文，模型依据这次输入生成。

**RAG 能消灭幻觉吗？** 不能。它能提供证据并降低部分知识风险，但检索和生成都会失败。

**必须使用向量数据库吗？** 不必须。关键词、SQL、图查询和混合检索都可能适合。

**Agent 一定需要 RAG 吗？** 不需要。只有任务确实要检索外部知识时才需要 RAG；计算、发消息、改文件等 Agent 任务可能只使用工具。RAG 也可以存在于完全固定的非 Agent 流程中。

**实用 RAG 管线除了固定切块、向量 Top-k 和生成还要什么？** 至少要考虑资料治理、权限和版本、查询处理、混合召回或过滤、重排、上下文组织、引用、无答案处理、分层评测与运行记录；具体组件由失败证据决定。
