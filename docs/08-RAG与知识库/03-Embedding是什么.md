# Token ID 怎样变成向量，Embedding 又为什么能用于检索？

> 所属专题：RAG 与知识库 · 前置：[知识库是什么](./02-知识库是什么.md) · 后续：[向量数据库是什么](./05-向量数据库是什么.md)

“退款要多久到账”和“退货后什么时候返钱”没有多少相同词，人却能看出它们在问相近的事。Embedding（嵌入表示）让程序获得一种可计算的表示：模型把文字、图片或其他对象转换成一组数字，使某些相关关系能够通过向量运算比较。

它不是把“意思”完整装进数字，也不是一张天然存在的语义地图。向量里的关系由特定模型、训练数据和训练目标塑造，只在相应任务和使用方式下有意义。

## 先分清两类常被叫作 Embedding 的东西

输入 Embedding 是生成模型内部的一张可训练参数表。Tokenizer 产生 Token ID 后，Embedding Lookup 用 ID 选择对应行，得到固定宽度的起始向量，再交给 Transformer。ID 只是离散索引，真正参与神经网络乘加的是向量。

```text
Token → Token ID → Embedding Lookup → 初始向量 → Transformer
```

这张表通常与模型一起训练。它让每个词表项拥有可调整的起点，但不意味着单独一行已经包含该 Token 在所有句子里的完整意义。经过 Attention、前馈网络和多层变换后，同一 Token 才会因上下文形成不同的 Hidden Representation。

检索 Embedding 则通常把一段查询、句子或文档压成固定长度向量，用于相似性搜索。二者都把离散对象变成数值向量，输出粒度、训练目标与使用位置却不同：

| 类型 | 输入与输出 | 主要用途 |
|---|---|---|
| Token Embedding | 一个 Token ID → 一个起始向量 | 送入生成模型内部继续计算 |
| Contextual Representation | 某位置经过多层后的向量 | 表示当前上下文中的该位置 |
| Retrieval Embedding | 一段查询或文档 → 一个固定长度向量 | 比较相似度并检索候选 |

本页后半主要讨论检索 Embedding；文本如何切成 ID 见[模型不认识文字，那“你好”怎样变成数字](../02-聊天Token与上下文/04-Token到底是什么.md)。

## 一串数字怎样参与检索

向量可以先理解为按顺序排列的一组数：

```text
[0.12, -0.37, 0.81, 0.04, ...]
```

Embedding Model 接收一段文本，输出固定维数的向量。RAG 建库时为资料片段生成文档向量；查询时为用户问题生成查询向量，再用点积、余弦相似度或距离函数寻找较接近的候选。

```text
资料片段 ─→ Embedding Model ─→ 文档向量

用户问题 ─→ Embedding Model ─→ 查询向量
                              ↓ 比较
                         相近候选片段
```

这张图想说明 Embedding 只负责表示与比较。读图时注意，检索系统还要做权限过滤、排序和取回原文；最终答案仍由后续生成与验证完成。

## 为什么语义相近的内容往往靠近

模型训练时会收到“哪些对象应该接近、哪些应该拉远”的信号。早期词向量从相似上下文中学习词语关系；句子检索模型常利用相似句、问答对或正负样本，优化向量空间，使相关查询与文档得分更高。

因此，“退款多久到账”和“退货后什么时候返钱”可能靠近天气问题之外。这里的“空间”只是理解高维向量的类比；每一维通常不能稳定翻译成“退款”“时间”这样的单一概念，信息分布在许多维度和组合中。

训练目标决定“相似”偏向什么。为问答检索训练的模型可能重视问题与答案的匹配，不只是两句话字面同义；商品推荐模型则可能把经常被同类用户选择的商品拉近。不存在脱离任务的万能相似度。

## 相似为什么不等于正确

向量模型可能抓住主题，却漏掉否定、数字、时间和地区。“允许退款”和“不允许退款”共享大量词语；2025 年旧政策与 2026 年新政策也可能非常接近。若只按向量分数排序，错误版本可能排在前面。

因此检索通常要结合关键词、元数据过滤和重排。产品型号、订单号和法规编号适合精确匹配；地区、权限、有效期等条件更应由结构化字段强制过滤。

向量接近也不能证明两条陈述事实一致，更不能判断来源可靠。它提供候选信号，不是事实验证器。

## Token ID、内部向量和检索 Embedding

Token ID 是词表中的离散编号，编号相邻没有语义含义。模型会把 Token ID 查成内部向量，经过多层计算形成上下文相关表示。用于检索的 Embedding 通常是模型为句子或文档输出的固定长度表示。

这些概念都涉及数字，但用途不同。生成式 LLM 也不必天然适合检索；专门训练的 Embedding Model 主要输出向量，而不是后续 Token。

## 为什么不同模型的向量不能随便混用

每个模型学到自己的坐标空间。维数相同，只表示数字个数相同，不表示坐标含义一致。使用模型 A 生成文档向量、模型 B 生成查询向量，距离通常没有可靠解释。

更换 Embedding Model 后，已有资料通常需要重新向量化并重建索引。还要重新评估真实查询，因为新模型即使总体更强，也可能在某个语言、领域或长度上退化。

Embedding 不是可无损解压的压缩包。知识库必须保留原文、来源和权限；向量用于找到证据，不替代证据。

## 回答真实问题

**文字为什么能变成数字？** 模型通过训练学会把输入映射成向量，使对任务有用的关系能用数值运算比较。

**为什么语义相近的内容往往靠近？** 因为训练目标奖励相关对象获得更相似的表示；具体“相似”由数据和目标决定。

**向量靠近就代表意思完全一样吗？** 不代表。它可能漏掉否定、数字、时间、权限和来源差异。

**每一维都对应一个明确词义吗？** 通常不能这样解释，信息往往分布在许多维度中。
