# 知识库是什么？

> 你现在的位置：[RAG](./01-RAG到底是什么.md) → **知识库** → [Embedding](./03-Embedding是什么.md)
>
> 课程导航：[上一篇：RAG 到底是什么](./01-RAG到底是什么.md) · 第 24 / 28 篇 · [下一篇：MCP 到底是什么](../09-MCP/01-MCP到底是什么.md)

知识库（Knowledge Base）不是“装了很多 PDF 的文件夹”，也不是向量数据库的另一种叫法。它是为了查询、回答或完成任务而组织和治理的一组资料，包含原文、来源、元数据、权限、版本以及可用的检索入口。

不同领域对知识库的结构定义不完全一样。对 RAG 项目，最重要的是知道哪些资料属于可信范围、谁可以访问、当前有效版本是哪一份，以及怎样回到原文核验。

## 文件夹为什么还不够

客服团队可能收集产品手册、退换货政策、常见问题和故障处理步骤。若只是把文件放在一起，新旧政策可能冲突，扫描件可能无法搜索，也不知道某位用户是否有权读取内部文档。

```text
原始文档与业务记录
  + 来源、作者、更新时间
  + 产品、地区、语言、版本
  + 权限与保密等级
  + 关键词 / 向量 / 结构化索引
  ↓
可治理、可检索、可追溯的知识库
```

这张图想说明知识库的价值不只在存储。读图时注意元数据和权限与正文同样重要；缺少它们，系统很难过滤旧版本、限制访问或给出可靠引用。

## 数据库、知识库和向量数据库的边界

数据库强调按结构保存、查询和更新记录；知识库强调哪些资料被组织为可供查询和回答的知识范围。知识库可以建立在数据库、文件系统、对象存储和搜索引擎之上。

向量数据库负责保存向量并按相似性查找。它可以承载知识库的一种索引，但通常还要保留切片原文或指向原文的标识、元数据和权限。只有向量而没有可审查内容，模型无法获得最终要阅读的证据。

```text
知识库
├── 原文或权威记录
├── 元数据、版本与权限
└── 检索索引
    ├── 关键词索引
    ├── 向量索引
    └── 结构化查询入口
```

这张图想帮助你看懂“向量库属于哪里”。读图时注意，它是一种检索基础设施，不代表知识库只能用向量，也不自动包含完整治理流程。

## 一份资料怎样进入可用状态

系统先确认来源和使用权限，再解析 PDF、网页、表格或扫描件。随后处理重复和版本，按语义结构切分，附上原文位置与元数据，建立索引并测试典型查询。

更新时要能撤下过期内容、重建受影响索引，并保留审计记录。删除原文却遗漏向量索引，会造成旧资料继续被召回；权限只在生成阶段靠 Prompt 过滤，也可能泄露片段。

知识库质量应从准确性、覆盖率、时效性、可检索性和权限正确性评估。文件数量不是质量指标，重复、冲突和低质量文档反而会增加噪声。

## 建好知识库，RAG 就完成了吗

没有。RAG 还要把用户问题转成检索请求，召回并排序片段，组织上下文，让模型生成，并验证结论与引用。知识库回答“资料从哪里来”，RAG 还要解决“怎样找到并使用”。

模型通常只看到本次检索结果，不会浏览整个知识库。没召回的内容等于没有进入当前请求；这也是为什么知识库覆盖良好，最终回答仍可能失败。

## 回答真实问题

**知识库就是 PDF 文件夹吗？** 文件夹可以保存原始资料，但完整知识库还需要来源、版本、权限、元数据、索引和维护流程。

**知识库和数据库一样吗？** 知识库描述面向知识任务的资料与治理范围，可以使用数据库实现；数据库则是一类数据存储和查询系统。

**向量数据库会保存切片原文吗？** 实现方式不同。RAG 最终必须能取回模型可读的内容，因此常在向量记录中保存原文与元数据，或保存指向外部原文的 ID。

**资料做了向量化，原文还能删吗？** 通常不应只留下向量。向量适合检索，不足以替代可展示、可引用和可审核的原始内容。
