# Prompt 是什么？

> Level: `Core` · Path: `Main`

## 一个小白真的会怎么问？

> Prompt 就是我发给 AI 的问题吗？
>
> 为什么换一种说法，回答会不一样？

## 先说人话

Prompt（提示）是提供给模型、用来影响当前输出的输入内容。它可以包含问题、任务、背景资料、示例、约束和希望的输出格式，不一定只是一句话。

```text
目标 + 必要背景 + 具体要求
              ↓
            模型
              ↓
            输出
```

## 举个例子

模糊的 Prompt：

> 帮我总结。

更明确的 Prompt：

> 把下面会议记录总结成三条决定和三项待办；每项待办写负责人，没有出现负责人就标“待确认”。

第二种写法告诉模型任务、范围、格式和缺失信息怎样处理，因此更容易得到可用结果。

## 严格来说

Prompt 是模型推理时用于条件化输出的输入。对聊天系统来说，模型最终接收的内容可能不只有用户消息，还可能包括系统规则、应用指令、历史对话和工具结果。

因此，日常所说的“我写的 Prompt”通常只是完整 Context 的一部分。

```text
系统 / 应用指令
      +
历史与资料
      +
用户 Prompt
      ↓
完整输入 Context
```

具体消息角色和拼接方式取决于产品或 API，不能把某个平台的实现当作所有模型的永久定义。

## Prompt 为什么能改变输出？

语言模型根据已有 Token 计算后续 Token 的可能性。Prompt 改变了已有内容，也就改变了模型生成后续内容时所依据的条件。

给出任务类型、相关资料或示例，能帮助模型识别当前应延续哪种模式。但 Prompt 不是程序中的绝对命令，模型仍可能误解、遗漏或无法完成要求。

## 怎样写得更清楚？

根据任务需要，可以说明：

1. **目标**：最终要完成什么？
2. **背景**：模型必须知道哪些信息？
3. **输入边界**：哪些内容是待处理材料？
4. **约束**：不能做什么，遇到缺失信息怎么办？
5. **输出形式**：列表、表格、代码还是短文？
6. **示例**：是否需要展示一个期望结果？

这是一份检查思路，不是每个 Prompt 都必须填满的公式。简单任务往往一句清楚的话就够。

## 最容易搞混的东西

### Prompt ≠ Context

Prompt 是为了引导输出而提供的内容；Context 是本次计算中模型能利用的全部信息。产品规则和历史消息可能属于 Context，却不是用户亲自写的 Prompt。

### Prompt ≠ Training

Prompt 改变当前请求的输入，通常不更新模型参数。训练才会根据数据和目标调整参数。

### Prompt ≠ Tool

Prompt 可以要求系统使用工具，但真正执行搜索、代码或 API 的是外部程序，不是文字指令本身。

### Prompt ≠ 保证

清晰 Prompt 可以降低歧义，但不能保证事实正确，也不能让模型获得它本来没有的数据、权限或工具。

## 常见误区

### 误区 1：越长越专业，效果越好

不一定。无关背景、冲突要求和重复内容会增加噪声。Prompt 应提供完成任务所需的信息，而不是追求长度。

### 误区 2：必须使用某个“万能咒语”

不存在适用于所有模型与任务的固定咒语。清楚表达目标、材料与验收标准通常比堆砌角色设定更重要。

### 误区 3：模型说“明白了”就一定理解一致

应检查实际输出是否满足要求。高风险任务还需要来源核验、测试或人工审核。

## 你只需要记住

1. Prompt 是提供给模型、用于影响当前输出的输入内容。
2. 用户 Prompt 通常只是完整 Context 的一部分。
3. 清楚的目标、必要背景、约束和输出格式能减少歧义。
4. Prompt 不会自动训练模型，也不能保证答案正确。
