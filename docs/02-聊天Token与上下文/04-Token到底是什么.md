# 从一句“中国的首都是北京”，看文字怎么进入模型

上一层我们还在讨论人类写下的句子。从这一章开始，沿着同一句话走进模型：

> 中国的首都是北京。

模型不能直接拿这串汉字做神经网络计算。我们先看它怎样变成 Token、编号和向量；下一章再接着问，已经看到“中国的首都是”时，模型怎样预测“北京”。

看完这一篇，你应该能自己解释：Token 为什么不等于汉字，Token ID 为什么只是编号，以及编号为什么还要变成向量。

## 电脑能保存文字，为什么模型还不能直接“看字”

电脑当然能保存“中国的首都是北京”。文件和程序通常先按 Unicode 等字符标准确定文字身份，再用 UTF-8 等编码把它写成字节。这解决的是**怎样无歧义地存取文字**，没有规定神经网络应把哪段文字当作一个计算单位，也没有给出这些单位之间的可学习关系。

神经网络的层主要接收固定形状的数值张量。若直接把 Unicode 编号当大小使用，编号接近不代表意思接近，编号更大也不代表文字更重要；若每次输入长度都不同，批量计算也需要额外约定。因此语言模型先用 Tokenizer 把文本按一套固定词表和规则编码，再用 Token ID 查到可训练向量。

```text
人类文本“中国的首都是北京”
  ↓ 字符编码只负责存取
计算机中的字节
  ↓ Tokenizer 按自己的词表与规则切分
Token
  ↓ 查 Vocabulary
Token ID
  ↓ Embedding Lookup
模型能计算的向量
```

这两层编码不能混为一谈。UTF-8 让不同程序知道哪些字节代表“你”；Tokenizer 决定目标模型把“你好”整体处理，还是拆成“你”“好”或更细的字节片段。

## Token 是模型词表中的一个离散单元

人看到的是文字，模型内部首先需要的是数字。Tokenizer（分词器）按照自己的词表和规则，把输入编码成一串 Token，再把每个 Token 映射为整数编号，也就是 Token ID。

```text
原始文本
  ↓ Tokenizer 编码
Token 序列
  ↓ 查词表
Token ID 序列
  ↓ 模型参数参与计算
内部数值表示
```

这张图想帮你区分三样东西：文本片段、词表单元和数字编号。读图时最重要的是 Token ID 只是索引；编号 50,000 不表示它比编号 20 更重要，也不表示它包含更多信息。

一个 Token 可能对应一个常见短词、单词的一部分、一个汉字、标点、前导空格，甚至某种字节片段。具体是什么，取决于 Tokenizer 怎样训练词表和处理无法直接匹配的文本。**Token 不固定等于字符、汉字或单词。**

## 为什么不干脆一个字或一个单词算一个

如果把每个完整单词都放进词表，英文的时态、复数、拼写变体、专有名词和新词会让词表迅速膨胀；没见过的词还会无处可放。如果永远按单个字符或字节处理，词表可以很小，但同一段文字会变成更长的序列，模型需要走更多位置才能处理一个常见词。

子词方法在两者之间折中。高频片段可以作为一个 Token，低频词则由更小片段拼起来。例如下面只是示意，不对应某个真实模型：

```text
unbelievable → un | believ | able
```

另一 Tokenizer 完全可能切成 `unbelievable` 一个 Token，或切成更多片段。中文词组、英文前导空格、代码缩进、Emoji 和生僻字符也会因词表与编码方案不同而产生不同结果。准确计数必须使用目标模型配套的 Tokenizer，而不是凭肉眼猜。

**试一试**：主流模型厂商都会提供官方 Tokenizer 的在线试玩页面。把同一句中文、同一句英文分别粘进去，看它们各自被切成什么——你会直观看到“Token 不等于汉字或单词”，也会看到不同词表切分方式的差异。注意试玩页展示的是该厂商自己的词表结果，不能当作所有模型的通用标准。

## BPE 怎样从小单位逐步得到常见片段

BPE（Byte Pair Encoding）最初是一种数据压缩方法，后来被用于构建子词词表。训练 Tokenizer 时，可以先把训练语料表示成较小单位，再反复统计相邻单位中最常出现的组合，把高频组合合并成新符号。

下面只是为了展示过程的小语料：

```text
初始：l o w   l o w e r   n e w e r
发现 l + o 很常见       → 合并为 lo
发现 lo + w 很常见      → 合并为 low
继续统计并合并，直到达到词表预算或停止条件
```

训练结束后会留下 Vocabulary（词表）和合并规则。真正编码新文本时，Tokenizer 使用这套固定结果切分，不会每收到一句话就重新训练 BPE。高频组合有机会成为一个 Token，低频或新词仍可由更小单位拼出，这就是它在“巨大整词词表”和“序列过长”之间的折中。

词表大小不是越大越好。词表大可以缩短部分序列，却会扩大输入 Embedding 和输出词表投影，稀有 Token 也可能缺少足够训练样本；词表小更容易覆盖新组合，却让序列更长。语料语言、代码比例、特殊 Token、字节回退和模型预算都会影响最终选择。

## BPE、Unigram 和 SentencePiece 不是三个同层概念

BPE 很常见，但**并非所有现代 LLM 都严格使用同一种 BPE 实现**。Unigram Language Model 是另一种子词算法：它通常从较大的候选词表出发，逐步移除贡献较小的片段，选择能较好解释语料的切分。

SentencePiece 则更像一个可直接在原始文本上训练和编码的工具包，支持 BPE、Unigram 等模型。把“用了 SentencePiece”直接等同于“用了 BPE”并不准确。WordPiece、字节级 BPE、纯字节或字符方案也有各自实现。

因此，不同模型即使都写着“子词 Tokenizer”，也可能因为算法、训练语料、词表大小、Unicode 规范化、空格处理和特殊 Token 不同而得到完全不同的切分。模型训练与部署必须使用兼容的 Tokenizer；否则同一个 ID 会指向错误词表项。

## Token、Token ID 和 Embedding 到底差在哪

Vocabulary 是 Token 与整数编号之间的固定映射表。Token ID 只是查表索引：编号 `420` 与 `421` 相邻，不说明两个 Token 意思相近。

模型内部还有一张可训练的 Embedding 表。输入 ID 后，Embedding Lookup 取出对应的一行向量。例如词表有 50,000 项、隐藏宽度为 4,096，输入 Embedding 可以理解为一张 `[50000, 4096]` 的参数表；某个 Token ID 选择其中一行。训练会更新这些数值，让它们成为后续 Transformer 可使用的起始表示。

```text
Token       “北京”这样的词表单元
Token ID    它在 Vocabulary 中的整数索引
Embedding   用这个 ID 查到的可训练向量
```

初始 Token Embedding 还没有完整上下文含义。同一个 Token 出现在“苹果公司”和“吃苹果”中，查表得到的起始向量相同或相近，但经过多层 Transformer 与其他位置交换信息后，会形成不同的上下文化表示。用于 RAG 检索的句子 [Embedding](../08-RAG与知识库/03-Embedding是什么.md) 又是另一种输出和训练用途，不能把三者混成一种向量。

## 一段文字怎样走进模型，又怎样出来

以“天气不错”为例，Tokenizer 可能把它编码为三个 Token ID。模型先用参数表把每个 ID 转成一组连续数值，也就是 Token 的初始向量表示；经过多层计算后，模型在词表中为“下一个 Token”产生一组分数和概率。

生成程序根据概率和采样设置选出一个 Token ID，Tokenizer 再把它解码成人能看到的文字。新 Token 会接回已有序列，模型继续预测下一步。

```text
文字 → Token ID → 向量与多层计算
                         ↓
                 下一个 Token 的概率
                         ↓
              选出 ID → 解码成文字
                         ↓
                    接回去继续
```

这张图想解释为什么聊天回答常常逐步出现。读图时注意 Tokenizer 负责“文字与 ID 的转换”，模型参数负责“根据 ID 序列计算后续概率”；把两者都叫“模型在分词”会遮住职责边界。

模型每一步实际生成的是 Token，不保证屏幕每次刚好增加一个汉字。流式界面还可能把几个 Token 合并后显示，或等待字节组成合法字符再展示，所以肉眼看到的刷新节奏也不能反推真实切分。

## K、M、B、T 到底怎样换算

这些字母是数量级前缀。在模型参数、Token 数和一般技术文档中，通常按十进制使用：

| 写法 | 数量 | 中文常用说法 |
|---|---:|---|
| 1K | 1,000 | 一千 |
| 1M | 1,000,000 | 一百万 |
| 1B | 1,000,000,000 | 十亿 |
| 1T | 1,000,000,000,000 | 一万亿 |

所以 `1.5B = 1,500,000,000 = 15 亿`。常见追问中“1040 亿大概就是 10B 吗”的答案是否定的：`1B` 是 10 亿，1040 亿应写作 `104B`，约等于 `0.104T`。中文“亿”与英文 billion 之间差一个 10，最容易在这里少算一位。

大小写在非正式资料里经常混用，但正式写作最好保留 `K / M / B / T`，并把计数对象写全：

```text
1.5B parameters  = 15 亿个参数
1.5B tokens      = 15 亿个 Token
```

两个数字一样，所数的东西完全不同。模型名称里的 `7B` 常用于参数量；“用 2T tokens 训练”是在描述训练数据经过 Tokenizer 后的 Token 数。只看到 `B` 或 `T` 时，必须回到前后文找名词。

计算机存储中还会看到 KiB、MiB、GiB 等二进制单位，它们以 1024 为倍数，不要与这里常见的十进制模型规模写法混淆。LLM 文档若没有特别说明，参数和 Token 数量级通常使用 K/M/B/T 的十进制含义。

## 1K Token 能装多少中文

能确定的只有：`1K Token = 1,000 个 Token`。它不能稳定换算成某个固定汉字数、英文词数或页数。

同一段内容的 Token 数会受到语言、词表、空格、标点、数字、代码、生僻字符和 Emoji 影响。同一句中文在两套 Tokenizer 中可能切得不同；同一篇文章换成代码或表格，Token 密度也会变化。网上的“一个 Token 约等于几个字符”只能用于非常粗的预估。

如果你要判断一段材料能否放进上下文窗口，或估算 API 用量，应使用目标模型官方提供的计数工具或兼容 Tokenizer 实测。还要同时考虑系统说明、历史消息、工具结果和计划生成的输出，因为它们也可能占用 Token 配额。

这个结论也回答了“最长 Token 有多长”。不存在跨所有模型的唯一最长 Token；问题必须限定某个 Tokenizer 和某个版本，然后检查它的固定词表。一个词表可以包含很长的常见字符串，另一个可能把同一字符串拆开。即使找到了某词表里的最长项，也不能据此定义 Token 的普遍长度。

## Token 为什么同时影响窗口、速度和费用

[上下文窗口](./07-上下文和上下文窗口是什么.md)通常以 Token 数表示，因为模型处理的是 Token 序列，不是“页”或“汉字”。输入经过编码后如果太长，应用就要截断、摘要、检索或换用其他策略；输出每多生成一步，也会增加序列长度。

序列更长通常意味着更多计算和运行中间状态，但具体成本怎样增长取决于模型架构、注意力实现、缓存和服务系统。不能把某个简单公式套到所有模型上。Token 数是重要输入规模指标，不是完整硬件账单。

API 常把输入 Token 和输出 Token 作为用量单位，因为服务端可以按模型实际处理和生成的序列计数。不同模型、缓存方式和服务可能有不同价格与规则，所以“每个 Token 多少钱”属于易变事实，必须查当时的官方价格页。Token 不是为了收费才发明的；计费只是利用了这个已有的技术单位。

Token 数也不等于语义信息量。两种语言表达同一意思，可能需要不同数量的 Token；一个长而重复的字符串可能 Token 很多，却没有更多有用信息。拿 Token 数直接比较语言“效率”或内容“价值”，很容易得出错误结论。

## 三个容易踩中的边界

**Token 与 Token ID。** Token 是词表单元，Token ID 是它在词表里的整数索引。ID 大小没有语义排序。

**Tokenizer 与模型参数。** Tokenizer 决定怎样编码和解码；模型参数学习 Token 序列中的规律。它们配套工作，但保存格式、训练方式和职责不同。

**训练 Token 与一次请求 Token。** “训练用了多少 Token”是在累计训练数据被模型处理的规模；“本次请求用了多少 Token”是在计算当前输入与输出。两者都叫 Token，因为编码单位相同，时间范围与用途却不同。

## 现在你应该能分清

**1K、1M、1B、1T 分别是多少？** 它们依次是一千、一百万、十亿、一万亿。`1.5B` 是 15 亿；后面写 parameters 还是 tokens，决定它在数参数还是数据单位。

**一个 Token 是一个汉字或一个单词吗？** 不固定。它是特定 Tokenizer 词表里的离散单元，可能是字、子词、标点、空格组合或字节片段。

**一个 Token 固定约四个字符吗？** 不是。那只是特定语言和数据上的粗略平均经验，不能用于精确计数，更不能推出全局最长 Token。

**BPE 是所有模型统一使用的分词方法吗？** 不是。BPE 是常见的子词词表构建方法；Unigram、WordPiece、字节或字符方案也存在，SentencePiece 还可以承载不同算法。

**Token ID 和 Embedding 有什么区别？** ID 是词表索引，本身没有距离语义；Embedding Lookup 用 ID 选择一行可训练参数，得到神经网络可以继续计算的向量。

**怎样知道一段文本的准确 Token 数？** 选择实际要调用的模型，使用它配套或官方兼容的 Tokenizer 编码并计数。模型或 Tokenizer 版本变化后，应重新测量。
