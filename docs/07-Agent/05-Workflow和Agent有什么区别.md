# Workflow 和 Agent 有什么区别？

> 所属专题：Agent · 前置：[Agent Loop 是什么](./03-Agent-Loop是什么.md) · 后续：[RAG 到底是什么](../08-RAG与知识库/01-RAG到底是什么.md)

只要流程里用了大模型，就叫 Agent 吗？不叫。区分 Workflow（工作流）和 Agent，最有用的问题是：**下一步主要由预先写好的程序规则决定，还是由模型根据运行中的状态动态选择？**

Workflow 更适合路径清楚、规则稳定、需要审计的任务；Agent 适合中间结果难以预料、路径无法提前穷举的任务。两者不是新旧技术之争，可靠系统常把它们组合起来。

## 报销流程为什么更像 Workflow

报销单必须检查字段、金额阈值和审批人。即使模型负责读取票据，业务路径仍由程序规定：

```text
读取票据（可以调用模型）
  ↓
校验必填字段
  ↓
金额超过阈值？── 是 → 经理审批
  │
  否
  ↓
进入付款流程
```

这张图想说明“使用模型”和“由模型控制流程”是两回事。读图时注意金额阈值和审批路径仍由确定性规则执行，模型不能因为觉得合理就跳过。

如果任务改成“研究三家竞争产品并找出值得继续调查的差异”，系统很难预先写出所有搜索路径。Agent 可以根据第一轮资料决定查定价、技术文档还是用户反馈，再根据证据继续调整。

## 固定分支很多，也不自动成为 Agent

一个程序可以包含几百个条件分支，只要路径都由开发者预先定义，仍是 Workflow。反过来，Agent 也不等于毫无流程；模型只能在允许的工具、数据、预算和停止条件内选择。

可以把两者放在连续谱上：固定代码处理确定步骤，模型在某个节点分类或提取，再到局部 Agent 处理开放问题。分类名称不如控制边界重要，设计文档应说明哪些决定由谁做。

## 为什么组合往往更可靠

常见结构是固定入口做身份和权限检查，中间让 Agent 搜索或分析，出口再用固定验证、审批和发布流程收口。这样既利用动态探索，也不会把合规和高风险操作交给不可预测的生成结果。

```text
固定接收、认证与范围限制
          ↓
局部 Agent 处理开放任务
          ↓
固定验证、人工审批与写入
```

这张图想展示 Agent 可以只是 Workflow 中的一段。读图时注意两端的边界：进入前限制输入和权限，退出后验证证据与副作用。

## 怎样选择，不靠追逐名词

先问主要步骤能否提前明确，中间结果是否真的会改变路径，错误后果是否严重，以及每个决定是否需要审计。如果固定代码、搜索加一次模型调用就够，不必增加 Agent Loop。

动态决策会增加模型调用、延迟、费用、状态管理和失败模式。它带来的适应性必须超过这些成本。付款、权限变更和法规检查等任务，通常应把硬规则保留在 Workflow；开放研究和复杂排障更可能从 Agent 获益。

Workflow 也不会天然可靠。错误规则、坏数据和外部服务失败仍需测试与监控。Agent 也不是天然不可靠；在小权限、可验证和有停止条件的范围内，它可以安全承担局部判断。

## 回答开头的问题

**流程用了大模型，就是 Agent 吗？** 不是。固定流程在某一步调用模型，整体仍可以是 Workflow。

**分支很多就是 Agent 吗？** 不一定。预先写好的复杂条件树仍由程序控制。

**Workflow 和 Agent 应该选哪个？** 能预先定义且高风险的部分优先固定；路径依赖未知中间结果时，再引入受限 Agent。

**两者能组合吗？** 可以，而且常是更实际的方案：Workflow 管边界，Agent 处理局部不确定性。
