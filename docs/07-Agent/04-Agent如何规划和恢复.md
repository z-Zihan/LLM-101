# Agent 如何规划和恢复？

> 所属专题：[Agent](./01-Agent到底是什么.md) · [Agent Loop](./03-Agent-Loop是什么.md) · [AI 工具](../06-工具与Function-Calling/02-AI工具到底是什么.md)
>
> 这是一篇 Agent 工程扩展页，不改变 32 篇主路线顺序。

一次模型调用可以请求一个工具，但只有当系统围绕目标保存状态、根据结果继续选择行动，并处理失败与停止时，才体现更完整的 Agent 行为。Planning 不是让模型先写一篇漂亮计划，而是决定怎样把目标转成可执行、可检查、可调整的步骤。

## 一次工具调用为什么不自动等于 Agent

“查询天气后回答”可以是固定 Workflow。若系统能发现城市缺失后追问、根据天气调整路线、工具超时后切换来源，并在预算耗尽时停止，它才具备更明显的状态与循环。

边界不是行业统一认证。实用判断可以看五项：

- 是否有跨步骤目标与完成条件；
- 是否读取并更新外部状态；
- 是否能在多个行动中选择；
- 是否依据 Observation 调整；
- 是否有权限、预算、恢复和停止边界。

系统名称不重要，能力与风险应按实际行为描述。

## 先完整规划，还是边做边规划

稳定、已知、错误成本高的任务适合先计划。例如数据库迁移可先列备份、兼容变更、验证和回滚。环境未知、需要搜索的任务更适合滚动规划：先做低成本探查，再依据结果决定下一步。

```text
已知依赖多、顺序严格 → 先形成可审查 Plan
信息不足、环境会变化 → 短计划 + 执行 + 重规划
高风险动作             → 无论哪种都加审批与回滚
```

任务拆分应让每一步都有输入、输出和验证方式。按“研究一下、实现一下、优化一下”拆得太空；按每个文件拆又可能失去业务闭环。更好的边界通常对应可验证的中间成果，例如“复现 401 并保存请求证据”“修改认证刷新逻辑”“运行回归测试”。

## ReAct 的价值与代价

ReAct 把推理、行动和观察交替组织。系统不必在看见真实环境前猜完整路径，工具结果可以纠正下一步。它适合搜索、排障和开放环境。

代价是循环可能漂移：模型重复查询、过度相信一条 Observation、在局部线索上改目标，或花费大量 Token。生产实现应把“Thought”理解为内部决策过程，不要求向用户暴露完整隐藏推理；真正需要保留的是行动理由、输入输出、证据和状态变化。

限制最大轮数、费用、时间和重复调用，检测无进展，并允许固定 Workflow 接管可预测步骤，能减少无限循环。

## 十几个工具怎样选择

工具描述是第一层：名称、用途、参数、权限和失败方式必须清楚。工具多到相似描述互相干扰时，可以：

- 先按任务域路由到一个小工具集合；
- 对工具说明建立检索，只注入候选工具；
- 使用分层菜单，先选能力类别再选具体操作；
- 为高风险工具设置显式策略和人工确认；
- 用历史轨迹评测误选与漏选，而非只看最终答案。

模型输出的 JSON 只是调用建议。运行时必须做 Schema 校验、类型和范围检查、权限判断，再由外部程序执行。

## 错误发生后怎样恢复

错误类型应先区分：

1. 参数格式非法：根据 Schema 修正，限制重试；
2. 可重试外部错误：使用退避、超时与幂等键；
3. 权限或策略拒绝：不能通过换措辞绕过，应请求授权或停止；
4. 结果为空或不可信：交叉验证、换来源或明确证据不足；
5. 已产生部分副作用：读取真实状态，按事务或补偿动作恢复。

把同一请求盲目重放可能重复付款、发消息或删数据。系统要记录每次行动的唯一标识和结果，在重试前确认是否已经生效。

恢复也包括回到最近检查点，而不是把整段对话重新喂给模型。长任务应把已完成步骤、产物、未决风险和外部资源 ID 写进结构化状态。

## Agent 不能只按最终答案评分

最终结果正确可能掩盖危险过程，例如读了无权访问的数据、调用十次昂贵工具或碰巧从错误证据得到正确答案。评测可拆成：

- 任务成功率和边界案例；
- 工具选择、参数和调用顺序正确率；
- 步骤数、Token、延迟与费用；
- 失败检测、重试和恢复成功率；
- 权限违规、不可逆副作用和停止行为；
- 轨迹可审计性与结果证据。

离线模拟适合覆盖大量失败，真实沙箱能发现环境差异，高风险生产动作仍需门禁。单一平均分不能替代逐类错误分析。

## 本地小模型能否做 Planner

聊天流畅不等于稳定规划。工具选择需要遵守 Schema、维持长程状态、区分不可信 Observation 并在失败后修正；量化误差可能对某些窄分布影响小，却在相近工具选择或长链约束中放大。

是否可用应在真实工具集上测，而不是按参数量或量化位数猜。可以让小模型负责低风险路由和格式化，让更强模型处理开放规划；也可以用固定 Workflow 限制决策空间。失败成本越高，越需要验证和回退。

## 回答七个真实追问

**调一次工具算 Agent 吗？** 不一定。目标状态、循环调整、恢复和权限边界比一次调用更能说明系统性质。

**任务怎样拆？** 按可验证中间成果拆；已知依赖先规划，未知环境用短计划滚动更新。

**ReAct 好在哪里、又有什么风险？** 它用真实 Observation 修正行动，但可能循环、漂移和积累成本。

**工具多时怎样选？** 结合清晰描述、候选检索、分层路由、策略约束与误选评测。

**工具失败怎样避免死循环？** 分类错误、限制重试、保证幂等、检查真实状态并在无进展时停止。

**Agent 效果只看答案吗？** 还要看轨迹、工具正确率、成本、恢复、权限和证据。

**量化本地模型适合 Planner 吗？** 只有目标工具集实测能回答；保留聊天能力不保证规划和结构化调用稳定。
