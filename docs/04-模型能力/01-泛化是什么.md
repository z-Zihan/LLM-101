# 泛化是什么？

模型训练时接触的是有限数据，真正上线后遇到的输入却很难完全重复。它为什么能判断一封从未见过的垃圾邮件，或者回答一种新写法的问题？这中间需要的能力叫泛化（Generalization）：**从训练样本中学到可复用规律，并在没有用于训练的新样本上继续有效。**

“新样本”不等于“世上从未出现过任何相似内容”，泛化也不是一种覆盖所有任务的总分。我们必须同时说明：什么任务、怎样的新数据、采用什么指标、训练与测试环境有多大差别。

## 从背题到处理新题

想象一批垃圾邮件训练样本，其中常出现中奖诱导、可疑链接和催促点击。新邮件写着：“您的积分今晚清零，请立即登录陌生网址兑换。”训练集里没有这句原文，模型仍根据组合特征判断为垃圾邮件，这就是在该任务上的泛化表现。

若模型只会认出训练集里一模一样的句子，换个数字或语序就失败，它更接近[记忆训练样本](./02-记忆训练数据和泛化有什么区别.md)。现实模型通常同时包含两类行为：记住部分具体片段，也学习能迁移到新组合的模式。它们不是非此即彼。

```text
训练样本
  ↓ 调整参数
学到具体片段 + 可复用模式
  ↓ 面对未参与训练的输入
在明确任务上评估表现
```

这张图想把“训练得好”和“用起来也好”分开。读图时注意，最后一步必须使用未参与参数更新的数据，否则只能说明模型适合训练题，不能可靠估计泛化。

## 训练集、验证集和测试集各做什么

机器学习项目常把数据分成三部分。训练集用来更新参数；验证集用来比较方案、调超参数或选择停止时机；测试集留到开发决策基本完成后，用来估计最终方案在未见数据上的表现。

如果团队反复看测试结果再改模型，测试集也间接参与了开发。分数可能越来越好，却不再代表真正陌生的数据。这就是为什么严谨评估要保存独立测试集，记录试验次数，并在重要场景中使用更新或外部数据复核。

LLM 的数据量巨大，训练语料又常不完全公开，数据污染尤其难排除。一个 Benchmark 的题目或近似解法若出现在训练数据里，高分可能混合了记忆与泛化。不能因为模型答对一道“没在当前对话里出现过”的题，就断言它从未在训练中见过。

## “来自同一分布”是什么意思

训练和测试常假设数据来自相近的数据分布。零基础可以先把“分布”理解为输入通常有哪些类型、各自多常见，以及答案规则是什么。训练集主要是清晰的英文客服邮件，实际用户却用中文口语、截图和行业缩写，输入环境已经变了。

轻微换词、换数字仍答对，可以说明一定的局部泛化。跨语言、跨领域、跨任务还能保持表现，要求更强。若现实数据与训练条件相差很大，称为分布偏移（Distribution Shift）；原测试分数可能不再适用。

泛化因此总带有范围：

- 在同类题目的新数值上有效，不代表能迁移到全新规则；
- 在公开 Benchmark 上有效，不代表能处理企业内部脏数据；
- 对平均用户有效，不代表每个语言、人群和边缘场景都可靠。

这三项是真正需要并列比较的边界。报告“模型泛化很好”却不说明范围，就像只说“这双鞋很合脚”却不说是谁穿、走什么路。

## 参数更多、训练 Loss 更低，泛化就更好吗

训练 Loss 下降说明模型更符合训练目标，不保证新数据同步变好。模型可能容量太小，连训练规律都没学好；也可能对训练样本拟合得很细，却抓住了无法迁移的偶然特征。后一类失败通常叫过拟合（Overfitting）。

在深度学习里，参数量、训练误差与泛化的关系并不总符合最简单的“小模型防止背题”直觉。大型网络可能既能拟合训练数据，又在测试集上表现良好；数据规模、优化方式、正则化、任务结构和预训练都会影响结果。因此，不能只看参数数量判断泛化，也不能用一句“模型太大所以一定过拟合”代替实验。

真正有用的证据来自独立数据上的表现、不同切分的稳定性、分布变化后的退化程度，以及对污染和重复样本的检查。高分只是某组条件下的测量结果，不是永久属性。

## LLM 的新回答从哪里来

[下一 Token 训练](../03-模型原理与训练/10-为什么预测下一个Token能学到能力.md)让模型在大量上下文中学习可复用表示。推理时，当前 Prompt 提供一种新组合，模型依据固定参数和上下文生成后续 Token。句子没有逐字出现过，并不神秘；有限 Token 也能组合出极多序列。

但“输出是新句子”仍不足以证明强泛化。它可能只是把熟悉模板换了几个词，也可能通过 RAG 读取了答案，或借助工具完成计算。评估时应说明测的是模型参数里的能力、当前上下文学习，还是整个产品系统的效果。

泛化与[推理能力](./03-推理能力是什么.md)也不同。泛化问的是模型能否把表现延伸到新样本；推理能力问的是它能否根据给定信息和约束推进到结论。一道新题可能需要两者，但通过新样本测试不等于已经证明了可靠多步推理。

## 怎样在真实项目里判断

先定义你真正关心的任务和失败代价，再准备与未来输入相符、没有参与开发的数据。不要只测“最像演示”的成功案例；应覆盖不同长度、语言、格式、歧义、异常输入和关键子人群。

如果系统包含 Prompt、RAG、工具或人工复核，就按实际流程一起评估，同时记录组件版本。模型更新、知识库变化或用户分布变化后，旧结论可能失效，需要持续监测。

最后要看失败分布，而不只看平均分。平均准确率 95% 可能掩盖某一类高风险输入几乎全错。泛化的目的不是赢得一个漂亮数字，而是知道模型离开训练环境后，在哪些条件下仍值得信任。

## 回答几个容易混在一起的问题

**没见过完全相同的问题还能回答，是泛化吗？** 可能是，但要排除训练污染、近似模板和外部工具，并在一组独立样本上测量。单次成功只是线索。

**模型是在背答案，还是学规律？** 两者可以同时发生。研究者会用去重、训练数据审计、改写题、成员推断和受控测试，尝试区分具体记忆与可迁移行为。

**参数量能决定泛化能力吗？** 参数量影响容量和计算成本，却不能单独决定结果。数据、训练预算、目标、架构、优化和任务条件共同作用。

**通过 Benchmark 就代表能在现实中用吗？** 不代表。它只支持“在该数据、指标和版本下达到某结果”，真实环境还要做贴近业务的独立测试。
