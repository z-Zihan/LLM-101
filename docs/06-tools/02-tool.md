# AI Tool 是什么？

> Level: `Core` · Path: `Main`

## 一个小白真的会怎么问？

> 模型不是只会生成文字吗，为什么还能搜索、查天气和发邮件？
>
> Tool 和 API 是一回事吗？

## 先说人话

在 AI 应用里，Tool（工具）是系统提供给模型选择使用的一项外部能力，例如搜索网页、读取文件、查询数据库或运行代码。

模型通常负责提出“要用哪个工具、输入什么”，应用或工具服务才负责真正执行。

## 举个例子

用户问：“北京现在天气怎么样？”底层模型的参数不包含实时天气。应用可以提供一个天气工具：

```text
用户问题
   ↓
模型选择 weather 工具，并给出城市=北京
   ↓
应用验证参数并调用天气服务
   ↓
工具返回当前天气数据
   ↓
模型根据结果组织回答
```

看起来像“AI 自己查了天气”，实际是模型与外部程序协作完成。

## Tool 通常怎样描述？

不同平台格式不同，但一项工具通常需要告诉模型：

- Name：工具名称；
- Description：它能做什么、什么时候使用；
- Input Schema：输入字段、类型和必填条件；
- 有时还包括输出结构、权限或其他元数据。

Schema（模式）可以先理解成“数据必须长什么样的规则”。清晰描述有助于模型正确选择工具和填写参数，但不能保证每次都正确。

## Tool 可以连接什么？

Tool 是应用层的能力包装，背后可以是：

- 一个网络 API；
- 本地函数或命令；
- 搜索引擎或数据库；
- 文件系统；
- 浏览器与计算机操作；
- 代码执行沙箱；
- 通过 MCP Server 暴露的能力。

因此，Tool 不等于某一种协议或实现。不同 AI 平台对“Tool”“Function”“Action”等词的具体定义也可能不同。

## 模型到底做了什么？

模型收到用户请求和工具描述后，生成一个结构化的调用意图，例如：

```json
{
  "tool": "get_weather",
  "arguments": {
    "city": "北京"
  }
}
```

这段内容只是模型输出的请求，不是天气已经被查询。Host（宿主应用）需要读取它、检查权限和参数，然后决定是否执行。

## 为什么模型需要 Tool？

模型参数不适合承担所有外部能力：

- 实时数据会变化；
- 私有数据不一定参与过训练；
- 精确计算更适合计算器或代码；
- 发邮件、下单和修改文件属于现实操作；
- 权限与审计需要由应用系统管理。

```text
Model：理解请求、选择步骤、组织结果
Tool：获取信息或执行外部操作
Host：连接两者并实施安全边界
```

## 谁负责安全？

不能把模型输出直接当作已授权命令。宿主应用至少要考虑：

- 当前用户是否有权限；
- 参数是否合法、是否超出范围；
- 操作是否需要用户确认；
- 工具能访问哪些数据和系统；
- 超时、重试和失败怎样处理；
- 返回内容是否可能包含恶意指令或敏感信息。

读取天气和删除生产数据显然不应使用同样的确认与权限策略。

## 最容易搞混的东西

### Tool ≠ API

API 是软件交互接口；Tool 是提供给模型选择的一项能力。Tool 可以包装 API，也可以调用本地代码或浏览器。

### Tool ≠ Skill

Tool 更像“可以执行什么”；Skill 更偏向“怎样完成一类任务的做事方法”。两者会在 Skill 章节正式比较。

### Tool ≠ Agent

一次工具调用不等于 Agent。Agent 通常还包含目标、循环、状态和根据结果继续行动的机制。

### Tool ≠ 工具结果

模型提出调用、工具执行、工具返回结果、模型解释结果是不同阶段。任何阶段都可能失败。

## 常见误区

### 误区 1：模型决定调用，就说明操作安全

不对。模型不应成为最终授权系统，真实执行必须经过应用的权限和策略检查。

### 误区 2：工具结果一定可信

工具可能返回错误、过时或恶意内容。模型也可能误读结果，关键数据仍需验证。

### 误区 3：工具越多，AI 就越强

工具过多或描述重叠可能让选择更困难，也扩大权限和攻击面。应提供完成任务所需的最小能力。

## 为什么我要知道它？

理解 Tool 后，你就能把“模型能力”和“系统能力”分开：模型不必在参数里知道实时天气，也不必亲自拥有数据库权限；应用可以在受控边界内临时提供所需能力。

## 你只需要记住

1. Tool 是 AI 应用提供给模型选择使用的外部能力。
2. 模型通常生成调用意图与参数，Host 或 Tool Server 才真正执行。
3. Tool 可以包装 API、本地函数、数据库、浏览器或其他系统，不等于 API。
4. 权限、确认、参数验证和错误处理必须由执行系统落实。
