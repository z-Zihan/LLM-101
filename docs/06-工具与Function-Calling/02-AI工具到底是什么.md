# AI 工具到底是什么？

> 你现在的位置：[API](./01-API到底是什么.md) → **AI 工具** → [Function Calling](./03-Function-Calling是什么.md)
>
> 课程导航：[上一篇：API 到底是什么](./01-API到底是什么.md) · 第 21 / 28 篇 · [下一篇：Agent 到底是什么](../07-Agent/01-Agent到底是什么.md)

模型按 Token 生成内容，为什么一个 AI 产品还能查天气、读文件、运行代码，甚至修改日历？这些能力通常来自工具（Tool）：宿主应用提供给模型选择的一项外部能力。模型负责表达调用意图，程序负责验证和执行。

“AI 查到了天气”是一句产品层的简称。底层至少包含模型、宿主和真实数据服务，任何一层都可能失败。

## 一次天气工具调用经过哪些角色

用户问“北京现在多少度”，训练参数不能保证包含实时天气。应用把 `get_weather` 的用途和输入规则告诉模型；模型选择它并生成 `city=北京`；宿主检查参数后调用天气服务，再把结果交给模型组织回答。

```text
用户问题
  ↓
模型：选择工具并填写参数
  ↓
宿主：校验、授权、执行
  ↓
工具 / API：返回结果或错误
  ↓
模型：依据结果生成回答
```

这张图想拆开“建议调用”和“已经执行”。读图时注意宿主这一层，它掌握凭证、权限、确认和超时，不应把模型输出直接当成命令。

## 工具描述为什么需要 Schema

一项工具通常包含名称、用途说明和输入 Schema。Schema 可以规定 `city` 是字符串、`date` 使用什么格式、哪些字段必填。描述越清晰，模型越容易选对工具并生成可解析参数。

结构合法不等于业务合法。`order_id` 是字符串，只能证明数据形状正确；它是否存在、是否属于当前用户、能否取消，要由业务系统继续验证。工具输出也应有明确结构，便于宿主判断成功、失败和需要重试的情形。

## Tool 和 API 为什么不是同义词

API 是软件交互契约；Tool 是 AI 系统提供给模型的一项可选能力。工具背后可以调用 Web API，也可以执行本地函数、读取文件、查询数据库、操作浏览器或运行受控代码。

同一个 API 可以被包装成多个权限更窄的工具，例如把庞大的邮件 API 分成“搜索邮件”和“创建草稿”，不直接暴露“立即发送”。反过来，一个工具也可能串联多个 API 才完成工作。

MCP Server 也可以暴露工具，但 MCP 是连接与发现这些能力的一套协议，不等于工具本身。Function Calling 则是模型按结构请求某项能力的常见机制。

## 工具为什么扩大了风险

纯文本错误通常停留在回答里；带工具的错误可能变成现实副作用。模型可能选错工具、误填金额、受到网页中恶意指令影响，或把另一个用户的数据放进参数。

宿主需要按工具风险建立不同边界：只读查询可以自动执行，发送、付款、删除和发布通常需要更严格授权和确认。路径、域名、数量和资源范围要做白名单或约束，工具凭证只授予完成任务所需的最小权限。

返回内容也不能默认可信。网页、文件和工具结果可能含恶意提示或过时数据；宿主应把它当外部数据，而不是更高优先级指令。关键结果还要经过[验证](../05-幻觉与模型局限/04-怎么验证AI的回答.md)。

## 工具越多，系统越强吗

工具增加能力，也增加选择难度、延迟、费用和攻击面。两个描述重叠的搜索工具可能让模型反复选错；几十个大而全的接口会占用上下文，还难以制定细粒度权限。

较稳妥的做法是按任务提供最小、边界清晰的工具集。记录每次调用的模型请求、校验结果、实际执行和返回状态，才能在失败后知道问题发生在哪一层。

工具失败不应被模型偷偷改写成成功。超时、拒绝、部分完成和用户取消都需要显式状态，Agent 才能安全决定重试、换方案或停止。

## 和 Skill、Agent 的边界

Tool 更接近“能执行什么”；Skill 更接近“怎样完成一类任务的可复用方法”；Agent 则围绕目标维护状态，根据结果多轮选择模型和工具。一次天气调用有 Tool，不必构成 Agent。

三者可以组合：Skill 告诉 Agent 先查什么、如何验证；Agent 选择工具；宿主执行并把结果带回循环。分清职责，才能知道错误应该修改提示、流程、权限还是工具实现。

## 回答真实问题

**模型只会生成文字，为什么能做现实操作？** 它生成结构化调用意图，外部宿主和工具执行真实操作。

**Tool 和 API 是一回事吗？** 不是。Tool 是面向模型的一项能力包装，API 是软件交互接口；Tool 可以包装 API，也可以使用本地能力。

**模型选择了工具，是否代表操作安全？** 不代表。授权、参数校验、确认和审计必须由执行系统落实。

**工具结果一定比模型记忆可靠吗？** 不一定。它可能过时、错误或恶意，模型也可能误读；要按来源和风险验证。
