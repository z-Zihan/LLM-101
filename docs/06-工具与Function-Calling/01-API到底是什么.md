# API 是什么？

> Level: `Core` · Path: `Main`

## 一个小白真的会怎么问？

> API 是一个网址，还是一段代码？
>
> “调用模型 API”和打开聊天产品有什么区别？

## 先说人话

API（Application Programming Interface，应用程序编程接口）是一套让软件之间按约定交互的接口。

你可以把它类比成服务窗口：调用方按规定提交信息，提供方按规定返回结果。但这只是类比；API 实际上是由请求格式、操作规则、返回格式和错误约定等组成的技术契约。

## 举个例子

一个天气应用不必自己测量每座城市的气温。它可以向天气服务的 API 发送请求：

```text
请求：查询上海当前天气
        ↓
天气服务读取数据
        ↓
响应：温度、天气状况、更新时间
```

应用再把这些数据展示给用户。用户看见的是界面，两个软件之间使用的是 API。

## 严格来说

API 定义一方可以请求哪些操作、需要提供什么输入、会得到什么输出，以及失败时怎样表达错误。

API 不一定通过网络。操作系统接口、程序库函数和设备接口也可以是 API。现代互联网产品常说的 API，通常特指通过网络访问的 Web API。

## Web API 一次调用发生了什么？

以常见的 HTTP API 为例：

```text
Client（调用方）
   ↓ 发送 Request
Server（服务方）
   ↓ 处理请求
Client
   ↑ 收到 Response
```

请求常包含：

- Endpoint：要访问的地址；
- Method：希望执行的操作类型，例如读取或提交；
- Headers：认证、内容类型等附加信息；
- Body：需要发送的具体数据。

响应常包含状态码、返回数据和错误信息。具体字段由该 API 的文档和版本决定，不能把一种服务的格式当成所有 API 的通用标准。

## 调用模型 API 是什么？

开发者把 Prompt、模型选择和其他配置按 API 约定发送给模型服务，服务执行推理后返回文本或结构化结果。

```text
你的程序
   ↓ Prompt 与配置
模型 API
   ↓ 推理
返回结果
   ↓
你的程序继续处理
```

聊天产品则通常还包含界面、账号、历史记录、系统规则、工具和其他产品逻辑。调用某家模型 API，不等于获得该公司聊天产品的全部功能。

## 为什么需要 API？

如果每个软件都必须了解另一个系统的内部实现，系统会很难连接和升级。API 把内部细节藏在边界后面，只暴露约定好的交互方式。

这带来几个好处：

- 调用方不必直接操作服务内部数据库或代码；
- 服务方可以在保持接口兼容时调整内部实现；
- 权限、限额、版本和错误可以在边界上管理；
- 多个应用可以复用同一项能力。

## API Key 是什么？

API Key 是服务用来识别调用方的一种凭证。它可能关联权限、限额和费用。

API Key 不能证明每次操作都安全，也不应写进公开代码、网页前端或日志。高风险操作还需要更细的授权、参数校验和审计。

## 最容易搞混的东西

### API ≠ URL

URL 可能只是 Web API 的一个访问地址。完整 API 还包含操作、输入输出、认证、错误和版本等约定。

### API ≠ UI

UI 面向人操作；API 主要面向程序交互。一个产品可以同时提供两者。

### API ≠ SDK

SDK（Software Development Kit，软件开发工具包）是帮助开发者调用 API 的代码库与工具。SDK 封装 API，但不是 API 本身。

### API ≠ Model

模型负责计算；API 提供访问方式。同一个模型可能通过多个 API 或产品使用，一个 API 也可能路由到不同模型和服务。

## 常见误区

### 误区 1：API 返回成功，就说明内容正确

请求成功只表示接口完成了相应处理，不证明模型回答、业务数据或输入假设一定正确。

### 误区 2：知道 API 地址就能随便调用

服务通常还需要认证、权限和有效参数，并可能有配额、费用与使用政策。

### 误区 3：API 永远不会变化

API 可能增加版本、弃用字段或改变限制。生产系统需要锁定版本、处理错误并关注官方变更说明。

## 为什么我要知道它？

API 是 AI 应用连接模型、数据库、搜索、支付和企业系统的基础。理解 API 后，才能继续区分“模型提出调用”“程序真正执行”和“外部系统返回结果”。

## 你只需要记住

1. API 是软件之间按约定交互的接口，不只是一个网址。
2. Web API 常通过 Request / Response 工作，具体格式由服务文档定义。
3. 模型、API、SDK、UI 和产品是不同层次。
4. API 调用仍需要认证、授权、参数校验和错误处理。
