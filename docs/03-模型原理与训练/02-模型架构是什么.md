# 模型架构是什么？

原始聊天问出了一串非常具体的问题：

> “设计时定的是架构（多少层、每层多宽、几个专家）”这句话是啥意思？什么架构？多少层、多宽又是什么？这是框架自带的吗？专家也是框架自带的吗？

这串追问比“架构就是图纸”更接近真正的认知卡点。图纸类比只能说明先有结构设计，不能告诉你设计对象是什么、代码和框架分别做什么，也不能解释为什么改一下宽度就会改变几十亿参数和运行成本。

## 架构规定一份输入要经过哪些计算

模型架构（Model Architecture）是一套计算结构设计：模型由哪些模块组成，模块怎样连接，数据在每一步变成什么形状，哪些信息可以互相影响，最终怎样得到输出。

先想象两个都用于图片分类的极简模型：

```text
模型 A：像素 → 一次线性计算 → 分类结果

模型 B：像素 → 局部特征模块 → 多层组合 → 分类结果
```

两者可以读取同样的图片，也可以用同一批标签训练，却因为信息流动方式不同而拥有不同能力、参数布局和成本。架构不是最后训练出的数字，而是这些数字被放在哪里、怎样参与运算的规则。

对于语言模型，架构还要规定 Token 表示怎样进入网络，不同位置怎样交换信息，中间表示经过哪些变换，怎样输出下一个 Token 的分数。Transformer 就是一类解决这些结构问题的架构，下一篇会拆开它的主要模块。

## “多少层”不是楼房层数

神经网络中的层，是一组从输入表示计算出新表示的操作。前一层的输出会成为后一层的输入；多层堆叠让模型能连续重组信息。

```text
输入表示 x
   ↓ 第 1 层：变换并组合
中间表示 h1
   ↓ 第 2 层：再次变换
中间表示 h2
   ↓ ……
输出表示
```

这张图想帮你理解“深度”：不是把同一答案重复算很多遍，而是每一层都在前一层结果上继续计算。读图时也要注意，现实中的一层通常包含多个子模块、残差连接和归一化，不能简单等同于一个“神经元”。

层数增加会延长信息经过的计算路径，也通常增加参数与计算量。更多层可能提供更强的表示能力，却会带来训练稳定性、通信、延迟和收益递减等问题。一个模型有 32 层、另一个有 80 层，并不能单靠数字判断后者在所有任务上更好。

## “多宽”是在说中间表示能容纳多少维

模型不会把一个 Token 只表示成单个数字，而是用一组数值描述它当前的内部状态。这组数值有多少维，常被称为隐藏维度、隐藏大小或宽度（Hidden Size / Model Dimension）。

假设某层输入宽度是 4、输出宽度也是 4，那么其中一个全连接变换可能需要 `4 × 4` 的权重矩阵。把宽度从 4 增加到 8，相应矩阵可能从 16 个权重变成 64 个；这就是为什么宽度增加常让参数量和计算量增长得很快。

真实 Transformer 的参数分布在多个矩阵中，前馈网络内部宽度也可能与主隐藏维度不同，所以不能用“层数 × 宽度”直接得到总参数。精确数量要按照词表、注意力、前馈网络、偏置、归一化和共享方式逐项计算。

宽度可以粗略理解为每个位置携带内部信息的维度，但不要把每一维想成一个有明确中文名称的知识槽。训练会让许多维度和参数共同形成分布式表示，单独一维通常没有稳定的一对一解释。

## “专家”是架构里的可选择计算模块

混合专家（Mixture of Experts，MoE）架构会准备多组可训练子网络，并用路由机制为每个 Token 选择其中一部分参与计算。这里的“专家”是技术命名，不是先请来法律、数学、文学等人类专家，再把知识分别装进部门。

```text
Token 的当前表示
      ↓ 路由器计算选择
专家 1  专家 2  专家 3  ……
   \      ↑ 被选中的少数模块参与计算
      组合结果
```

这张图想说明总参数与激活参数为什么可能不同。读图时注意未被选中的专家参数仍属于模型、也要存储，但本次 Token 不一定经过它们；于是模型可以拥有很大的总参数量，同时控制每次前向计算使用的部分。

专家数、每次选择几个、路由怎样训练、怎样平衡不同专家负载，都属于架构和训练设计。框架可以提供 MoE 组件或通信工具，却不会自动知道你的任务需要多少专家，更不会保证专家自然形成清晰的人类学科分工。

路由器通常也是带参数、参与训练的计算模块。它根据当前 Token 表示给专家打分，再按 Top-k 等规则选择少数专家；训练信号会同时影响路由与专家参数。系统往往还加入负载均衡目标，避免大量 Token 永远挤到同一个专家，让其他专家闲置。

专家分工是训练过程中形成的统计专门化，不是工程师先贴上“数学”“代码”“中文”标签。研究中有时能观察到某些专家偏好特定 Token、语言或模式，但这种偏好可能重叠、变化，也不能保证一个专家单独拥有某类完整知识。

## 架构最后确实要变成代码，但代码不等于架构

研究论文或设计文档会先用数学、图和文字描述结构。工程师再用代码定义模块、参数形状、前向计算和连接方式，用配置记录层数、宽度、词表大小等可调选择。程序运行后，框架按这些定义创建参数张量和计算图。

```text
架构思想
   ↓
具体配置：层数、宽度、头数、专家数……
   ↓
代码实现：模块和前向计算
   ↓
框架：张量、自动求导、设备与分布式运行
   ↓
硬件执行训练和推理
```

这张图最该看的是层级。PyTorch 和 JAX 是框架，提供构建与训练模型的通用能力；`torch.nn.Module` 之类抽象可以组织网络组件，但“采用 Transformer、堆多少层、是否使用 MoE”仍由模型设计和实现决定。

同一架构思想还可以有多个代码实现。实现可能在数值精度、算子融合、并行方式和细节默认值上不同，产生不同速度甚至细小数值差异。说两家公司“都用 Transformer”远不足以说明它们的模型完全相同。

## 架构、配置、参数、训练方法和框架怎样分工

| 名称 | 它回答的问题 | 例子 |
|---|---|---|
| 架构 | 信息经过哪些模块，模块怎样连接？ | Transformer、混合专家结构 |
| 配置 | 这次实例具体多深、多宽、多大？ | 32 层、隐藏维度 4096 |
| 参数 | 每个可学习位置最后是什么数值？ | 权重矩阵、偏置 |
| 训练方法 | 参数怎样根据目标被更新？ | 反向传播、优化器、训练目标 |
| 框架 | 用什么软件实现并在硬件上执行？ | PyTorch、JAX |

这些层会互相制约，但不能互换。架构和配置决定参数张量的布局与数量，训练方法改变具体数值，框架执行运算；最终保存下来的[模型](../01-AI与大模型/03-模型到底是什么.md)还需要把结构约定和训练后的参数配在一起。

“算法”这个词范围更宽，可能指训练算法、搜索算法或模型中的某段计算方法。只说“模型用了什么算法”容易含糊，最好继续问是在谈架构、训练目标、优化器还是生成策略。

## 为什么没有“全部拉满”的最佳架构

层数更多、宽度更大、专家更多，通常意味着更多参数、计算、存储或通信。它们可能提高某些能力，也可能让训练更困难、推理更慢、设备利用率更差。数据量和质量不足时，更大结构还可能没有得到充分训练。

不同维度的成本也不同。加宽某些矩阵会让参数接近平方增长；加深会增加串行层数；增加专家会扩大总参数并带来路由与跨设备通信。团队要在训练预算、推理延迟、显存、吞吐、数据、目标任务和可靠性之间寻找可接受方案。

架构研究因此不是比赛谁的数字最大。注意力改进、参数共享、稀疏计算、位置表示和归一化变化，都可能在相近预算下改变效果。最终判断要依靠受控实验和目标任务评估，不能从营销页的一项规模数字直接推出优劣。

## 同一架构为什么不会自动得到同一模型

架构只给出计算结构。即使两家公司采用完全相同的层数、宽度和模块，初始随机数、数据顺序、数据清洗、训练目标、优化器、数值精度、并行实现和停止时机都可能不同，最后得到的参数也会不同。

在大型分布式训练中，硬件并行与浮点运算还可能引入非确定性。严格控制随机种子、软件版本、数据顺序和确定性算子，可以提高复现程度；但“架构一样”本身远远不够。这也是为什么开源一张结构图不等于开源完整模型，更不等于能复现原始训练结果。

## 回答原始聊天的追问链

**设计架构是在写代码吗？** 架构先是一套计算设计，最终需要用代码和配置实现。代码是实现载体，不是架构概念本身。

**多少层、多宽是什么意思？** 层数表示连续堆叠多少组计算模块，宽度表示各位置内部表示的维度。两者会影响参数布局、容量和成本。

**框架是哪来的，架构是框架自带的吗？** PyTorch、JAX 等框架由软件社区和组织开发，提供张量、自动求导和硬件执行能力。它们可能内置常用模块，但完整架构与配置仍由模型设计者选择和实现。

**专家是框架自带的吗？** 框架或扩展库可以提供 MoE 组件，是否使用、使用多少、怎样路由是架构决策。“专家”是可选择的子网络，不是预装知识领域。

**MoE 的专家究竟是什么？** 通常是架构中并列的可训练子网络，常见于前馈模块。它们不是预先指定职业的独立模型。

**Router 怎样知道 Token 去哪个专家？** 路由器根据 Token 当前表示计算分数并选择专家，通常与模型一起训练；负载均衡等约束帮助避免路由塌缩。

**是不是层越多、宽度越宽、专家越多越好？** 不是。规模扩大只有在数据、计算和训练匹配时才可能转化为收益，还要承担内存、通信、延迟和稳定性成本。
