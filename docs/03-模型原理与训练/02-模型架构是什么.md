# 模型架构是什么？

> Level: `Core` · Path: `Main`

## 一个小白真的会怎么问？

> “设计模型架构”是在写代码吗？
>
> 架构、框架、参数和模型到底有什么区别？

## 先说人话

模型架构（Architecture）是模型的**计算结构设计**：有哪些组件、怎样连接、信息按什么路径流动和变换。

可以把它类比成建筑图纸，而训练得到的参数像按图纸安放并调好的具体部件。类比的边界是：模型架构最终由可执行的数学运算与代码实现，不是真正的房屋。

## 举个极简例子

两个模型都接收相同输入，但结构可以不同：

```text
结构 A：输入 → 一层计算 → 输出

结构 B：输入 → 多层计算 → 中间连接 → 输出
```

结构决定参数放在哪里、数据形状怎样变化以及哪些部分能互相交换信息。训练则调整这些位置中的具体参数值。

## 严格来说

架构描述模型所使用的计算组件及其组合方式，例如：

- 由哪些层或模块组成；
- 每个模块接收和输出什么形状的数据；
- 模块如何连接；
- 是否重复堆叠某类模块；
- 信息能否跨层或跨位置传递。

具体配置——例如堆叠多少层、每层多宽——会进一步决定参数张量的形状和数量。因此，仅知道“Transformer 架构”还不能得出一个模型的全部参数量。

## 架构是怎样实现的？

研究者和工程师通常：

```text
提出或选择计算结构
        ↓
用代码和配置描述模块
        ↓
框架建立计算与参数
        ↓
在硬件上训练和运行
```

PyTorch、JAX 等框架提供张量运算、自动求导、设备执行等工具。它们可以带有常用模块，但不会自动替团队决定适合任务的完整架构。

## 为什么架构重要？

架构为模型加入“怎样处理信息”的设计偏好。不同任务可能需要不同的信息连接方式、计算成本与输入输出形式。

架构会影响：

- 模型能表示哪些计算关系；
- 参数量和计算量怎样随配置变化；
- 是否容易并行训练；
- 能处理哪些数据形式；
- 推理时的速度与内存需求。

但架构名称不能单独决定最终能力。数据、训练、参数规模和评估同样重要。

## 最容易搞混的东西

### 架构 ≠ 框架

Transformer 是架构；PyTorch、JAX 是实现和训练模型的工具框架。

### 架构 ≠ 参数

架构规定参数在哪里、怎样参与计算；参数是训练得到的具体数值。同一架构配置可以训练出不同参数的模型。

### 架构 ≠ 训练方法

架构描述“模型怎样算”，训练方法描述“参数怎样学”。两者相互影响，但不是同一层概念。

### 架构 ≠ 产品

产品可能调用一个或多个不同架构的模型，并加入界面、工具和安全规则。

## 常见误区

### 误区 1：层数越多、宽度越大一定越好

不对。增加规模会改变容量和成本，但收益取决于数据、训练稳定性、计算预算和任务。

### 误区 2：框架自带一个最佳架构

框架提供组件和执行能力；结构选择仍需要研究、实验和工程权衡。

### 误区 3：同一架构会得到相同模型

训练数据、初始值、训练顺序和实现细节等都可能让最终参数不同。

## 你只需要记住

1. 架构是模型组件、连接与信息流动方式的设计。
2. 架构由代码和配置实现，框架提供实现与训练工具。
3. 架构决定参数的位置和形状，训练决定具体参数值。
4. 架构名称不能单独决定模型能力或参数量。
