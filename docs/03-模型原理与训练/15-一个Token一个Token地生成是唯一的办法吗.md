# 一个 Token 一个 Token 地生成，是唯一的办法吗？

> 所属专题：模型原理与训练 · 前置：[为什么 ChatGPT 的字是一个一个蹦出来的](./14-为什么ChatGPT的字是一个一个蹦出来的.md) · 后续：[GPU、显存和推理瓶颈](./19-GPU显存和推理瓶颈.md)

用 ChatGPT 写一段长文时，字是逐个蹦出来的。你已经知道这是自回归生成：模型每一步只预测下一个 [Token](../02-聊天Token与上下文/04-Token到底是什么.md)，选出来，接回输入，再预测下一步。一万个字的回答，就是一万次这样的循环。

于是有个很自然的问题：都 2026 年了，GPU 一次能并行算完整个矩阵，为什么模型还得一个 Token 一个 Token 地憋？就不能像画画那样，先铺个草稿再逐步细化，一口气把整段文字"倒"出来吗？

> 有没有模型能一次生成一整段文字？扩散模型不是也能写东西了吗？号称快十几倍的方法，到底怎么绕开逐 Token 生成的，又付出了什么代价？

这一篇就沿着这个问题走下去。答案不是"能"或"不能"，而是让你看清逐 Token 生成为什么如此顽固、挑战它的两条路线各自卡在哪里，以及 2026 年 10 月刚发表的一种新做法——粗到细生成（Coarse-to-Fine Generation）——怎样在两条路线之外找了第三条道。

## 为什么逐 Token 生成这么顽固

先把对手看清楚。逐 Token 生成的固执，不是工程上的偷懒，而是模型训练目标直接决定的。

自回归语言模型的训练目标是：给定前缀，预测下一个 Token 的概率分布。推理时，"前缀"必须包含**已经实际选出的**那些 Token——后一步的条件分布依赖前一步的结果。训练时没有这个问题，因为前缀来自真实文本，所有位置可以并行算 Loss（这靠的是[因果遮罩](./03-Transformer到底是什么.md)在注意力里挡住未来位置）；但生成时未来尚不存在，没有东西可以并行。

这带来三层连锁代价：

- **串行步数等于序列长度**。生成 1024 个 Token 就是 1024 次前向计算，每步都依赖上一步的结果，节奏完全串行。[KV Cache](./14-为什么ChatGPT的字是一个一个蹦出来的.md) 解决的是每步内部"重算历史"的浪费，但解决不了"步数本身"——缓存让每步变快了，步数没变少。
- **错误没有回头路**。第 500 步选错了方向，第 501 步只能在这个错误的基础上继续。自回归生成没有"先看看整体再修改"的机会。
- **无法先规划后填充**。有些任务天然需要全局布局——先想好结构，再填细节。逐 Token 生成逼着模型"边说边想"，想到哪写到哪。

如果能并行生成，这三个问题都有机会缓解。于是就有了第二条路线。

## 第一条挑战路线：扩散语言模型

图像领域早就给出了启发。Stable Diffusion 这类扩散模型从一团噪声出发，反复"去噪"，几十步后得到一张完整图像——每一步都在并行修改整张图的所有像素。

把同样的思路搬到文字上，就是扩散语言模型（Diffusion Language Model, DLM）。主流做法是掩码扩散：把文本的一部分 Token 换成 `[MASK]`，模型学习一次性预测出所有被遮住的位置，反复几轮，整段文字逐渐清晰。

这条路在 2025 到 2026 年间真正走出了实验室。开源的 LLaDA 把扩散语言模型做到了百亿参数级别；商业公司 Inception Labs 的 Mercury 把扩散模型部署成了商用推理服务，主打每秒上千 Token 的生成速度。扩散生成不再是纸上谈兵。

但它的账没有想象中划算，问题出在三个地方：

**步数省得不够狠**。扩散模型每步确实并行处理全部位置，但它需要很多步反复去噪才能收敛。实验里一个稳定的规律是：把采样步数压得太低，生成质量会断崖式下跌。并行是并行了，步数还是几十步起步。

**每一步都不便宜**。每步去噪都要对**完整序列**做一次完整计算——哪怕大部分 Token 已经确定下来了。而且扩散模型通常用双向注意力（看全局上下文才能判断每个位置该填什么），这让 AR 时代最有效的 KV Cache 几乎派不上用场：双向注意力的每一步都可能需要读取任何位置的信息，缓存谁都不保险。省掉步数优势后，单步成本反而比自回归更高。

**训练代价大**。扩散语言模型要学会"同时补全所有位置"，这个目标比"预测下一个"难收敛得多。论文里常见的数字是：一个不大的基线模型，要在公开网页语料上反复处理超过 5000 亿 Token 才达到像样的质量——同等规模的自回归模型用的数据量通常少得多。

所以到 2026 年，扩散语言模型的处境是：能用，速度快得也有吸引力，但质量和训练成本对比自回归仍没有整体优势，主要卖点集中在特定场景的吞吐率上。

有没有可能不走"从噪声里抠出全文"这条路，也不走"一个字一个字往外蹦"这条路？

## 第三条路：先粗略，再细化

2026 年 10 月，斯坦福 Hazy Research 实验室（Christopher Ré 团队）发表了一篇论文，提出 Next-Concept Modeling（NCM，按概念生成）。他们的出发点是一个观察：

**人类写作也是先搭骨架再填肉的。** 先定下这段话的主旨，再拆成几个论点，然后才是逐字成句。词是最后的细节，不是思考的起点。

NCM 把这个直觉做成了完整的生成框架，分两个阶段训练。

### 阶段一：把文本压成"从粗到细"的层级

第一个问题是怎么表示"骨架"和"细节"。NCM 的做法是训练一个多尺度残差 VQ-VAE——名字吓人，工作原理不复杂：

1. 编码器把一段 1024 个 Token 的文本，映射成一串连续向量；
2. 这些向量被**逐级量化**成离散码（Code）：第一级只有很少几个码，概括全文主旨；第二级稍多，补充段落结构；越往后的层级码越多，直到最后一层恰好对应全部 1024 个位置；
3. 关键在"残差"二字：每一级编码的不是全文，而是**前面所有级没表达完的那部分信息**。像剥洋葱——第一层抓住最粗的结构，剩下的细节留给下一层。

[Tokenizer](../02-聊天Token与上下文/04-Token到底是什么.md) 你已经熟悉：把文本切成 Token ID。NCM 的多尺度 tokenizer 干的是相反方向的事——它把整段文本压缩成一棵由粗到细的离散码树。原文本可以完全从这棵树恢复出来（论文实测重建准确率在 99% 以上），但树的前几层 alone 就已经承载了文本的核心结构。

怎么保证"前面的层真的装着最重要的信息"？训练时用了一个叫 Nested Dropout 的技巧：每次训练随机只保留前 k 层，强迫前面的层在不依赖后层的情况下就能单独恢复出像样的文本。这就像反复训练一个摘要作者："只给你一句话的预算，也必须写出最有信息量的那句话。"

### 阶段二：逐层并行生成

有了这棵码树，生成过程就完全变了样：

```text
自回归：  1024 步 × 每步 1 个 Token     （步多、每步小）
扩散：    几十步 × 每步全部 1024 位置    （步较多、每步大）
NCM：     32 步 × 每层 ℓk 个码，逐层加码 （层级长度指数增长）
```

NCM 的生成器（一个普通的 [Transformer](./03-Transformer到底是什么.md)）从第一级开始，一次前向**并行预测出这一层的全部码**；这些码经解码后累加到已有重建上，作为下一层的条件输入；循环往复，直到最细一层生成完毕，最后用 tokenizer 的解码器把完整重建翻译回文字。

这个设计的精妙之处在于**步数的增长速度**。层级长度设计成大致指数增长（比如 1、2、4、8……1024），32 个层级就能覆盖 1024 个 Token。而且每步处理的"有效长度"在前期非常短——第一层只有 1 个码，第二层只有 2 个——早期步骤的计算量几乎可以忽略。串行依赖只存在于层级之间（下一层要看上一层的重建结果），层级内部完全并行。

### 效果：一份 2026 年 10 月的成绩单

NCM 论文报告的数字（在同参数量级、约 1 亿参数的生成器上对比最强扩散基线）：

- **LM1B 数据集**：生成质量（用生成困惑度衡量）更好，单张 H100 上壁钟时间快 **21 倍**；
- **OpenWebText**：质量相当，快 **10 倍**；
- **XSum 摘要**：ROUGE-L 相当，快 **31 倍**；
- **训练成本**：把 tokenizer 和生成器都算进去，所需训练 Token 仍只有扩散基线的约 **1/4 到 1/5**；
- **Sudoku 推理**：在需要全局满足约束的数独任务上，NCM 超过了自回归和扩散两类基线——难题（30 提示数）上解出率 86.1%，扩散基线最高 81.3%，自回归基线只有 1.0%。

Sudoku 这行数字值得多说两句。它暗示"先定全局结构、再填细节"的生成顺序可能天然适合需要规划的任务——粗层级先锁定了整体布局，细节填充不会破坏它。而自回归模型填到第 30 格时，可能已经和第 5 格的约束冲突了。

## 代价与边界

如果 NCM 全面占优，这篇教程的标题就不用问了。它同样有明确的代价，有些还是结构性的：

**质量上限受制于 tokenizer。** 生成文本的一切信息都要过一遍离散码的瓶颈。重建准确率 99% 听起来很高，但那 1% 的误差落在关键词上就是实打实的错误——一个数字、一个实体名错了，句子就废了。论文自己也承认，生成的文本总体流畅，但在层级切换处会出现"粗糙层带来的伪影"。图像量化误差人眼难察觉，文本量化误差读者一眼就能看出来——这是文本离散生成绕不开的难题。

**层级是写死的。** 每个训练好的模型，层级数 K 和每层长度 ℓk 都固定。生成一句话也要走完全部层级，短输出享受不到"按需分配"的计算节省。让模型学会自己决定"这段够细了，可以停"，论文列为未来工作。

**表示学习和生成是两张皮。** tokenizer 先训练、生成器后训练、互不相通。生成器只能对着一个已经冻死的码表学生成，没法反过来要求"这个码表更方便我生成"。联合训练两阶段是公认的改进方向，但还没做进这一版。

**规模还小。** 主实验是 1 亿参数级别的生成器，scaling 研究做到 7.25 亿。它能否撼动百亿、千亿参数的自回归大模型，2026 年 10 月的答案还是未知数。LLaDA 花了一年才把扩散模型推到百亿级，NCM 还没有同量级的验证。

所以更准确的结论是：NCM 在"小模型、快生成、需要全局结构的任务"这个象限里，展示了第三条路线的可行性。它是**挑战者**，不是**替代者**——自回归模型在开放-ended 长文生成、复杂指令跟随上的统治地位，2026 年仍没有被任何非自回归方法动摇。

## 三条路线放在一起看

把三种范式并排放，差异一目了然：

| 维度 | 自回归（GPT、Claude、Qwen…） | 扩散（LLaDA、Mercury…） | 粗到细（NCM） |
|---|---|---|---|
| 每步生成什么 | 1 个 Token | 全部位置的修正 | 一层的全部码 |
| 步数量级 | 序列长度（千级） | 几十步 | 层级数（十几到三十几） |
| 生成顺序 | 从左到右 | 全局并行去噪 | 从粗到细 |
| KV Cache | 核心优化，必用 | 双向注意力下基本失效 | 不适用（每层条件是重建向量） |
| 全局规划能力 | 弱（边写边想） | 中（迭代全局调整） | 强（先锁结构再填细节） |
| 工程成熟度 | 全行业基础设施 | 少数商用部署 | 实验室阶段 |
| 典型代价 | 串行步数多、错误不回头 | 步数×全序列成本、训练贵 | tokenizer 瓶颈、层级固定 |

（这张表里"KV Cache 不适用"是 2026 年 10 月的现状：NCM 的层级间依赖走的是重建向量而非注意力 KV，无法复用为自回归设计的缓存体系。它的加速来自步数少、前期层级短，不需要缓存。）

如果只记一件事，记这个：**生成范式的本质区别在于"串行依赖链有多长、每步的并行度有多大、错误在哪个粒度上被修正"**。自回归把串行链拉到最长（每个 Token 一环），换来了最简单的训练目标和最灵活的工程生态；扩散把并行度拉到最大，付出了训练成本和步数下限；粗到细在两者之间切了一刀——串行链只有层级数那么长，每层内部完全并行，还顺手把"全局结构先定下来"变成了生成过程的天然属性。

## 回到开头的问题

"有没有模型能一次生成一整段？"——严格说，没有哪个主流方法真正"一次"生成：扩散需要几十步去噪，NCM 需要十几到三十几层逐步细化。真正的差别不是"一次 vs 多次"，而是**串行步数从"序列长度"降到了"远小于序列长度"的某个量级**。

"号称快十几倍，怎么绕开逐 Token 的？"——不靠硬并行全部位置，而是先把文本表示成一棵由粗到细的离散码树，串行依赖只存在于树的层与层之间，层内全部并行。代价是生成质量被 tokenizer 的重建能力封顶，且层级调度无法按输入难度自适应。

"扩散模型不是也能写东西吗？"——能，而且已经商用。但它每步都在修正全部位置，步数压低了质量崩，加上双向注意力让 KV Cache 失效，速度优势和训练成本一直没有拉开决定性差距。

最后回到你正在用的模型。下一次看着字一个个蹦出来时，你现在知道：这不是技术的懒惰，而是训练目标与工程生态互相锁定的结果；打破它的尝试一直都在，而且刚刚在 2026 年 10 月拿到了第一阶段的成绩单。你用的下一个模型，未必还是逐 Token 生成的。
