# 规模定律是什么？

> 所属专题：[参数](./06-参数到底是什么.md) · [训练数据](./07-参数量和训练数据有什么区别.md) · [训练与推理](./18-训练和推理有什么区别.md)
>

为什么有时扩大模型有效，有时只是更贵？规模定律（Scaling Laws）研究的是：在一组明确的模型、数据和训练条件下，参数量、训练 Token、计算预算与 Loss 或任务表现怎样随规模呈现可拟合的趋势。

它不是一条保证“大十倍就聪明十倍”的自然法则，也不是厂商模型排名公式。研究者先做多组训练实验，再用经验函数拟合观测范围内的关系；换架构、数据分布、目标、后训练和评测，系数与适用范围都可能改变。

## 参数、数据和计算必须一起看

粗略地说，训练计算会随参数量、训练 Token 数和每 Token 运算量共同增长。固定预算下，把模型做得更大意味着能训练的 Token 可能减少；把同一个模型训练更久，又可能遇到数据重复、质量下降或收益递减。

```text
固定训练预算
  ├─ 更多参数：单个 Token 的计算更贵
  ├─ 更多 Token：模型能接触更多训练信号
  └─ 数据与系统效率：决定预算是否真正转成有效学习
```

Kaplan 等人的工作展示了语言模型 Loss 随模型、数据和计算扩展的幂律趋势。Hoffmann 等人的 Chinchilla 研究进一步比较固定计算预算下的配置，指出许多早期大模型相对“参数多、训练 Token 少”，更平衡地扩大两者可能更有效。

所谓“计算最优”只是在指定目标和成本约束下寻找较优组合。它不表示参数与 Token 永远必须按一个固定比例增长，也不保证这个组合最适合部署。

## 为什么后来有模型训练得比 Chinchilla 更久

训练最优与生命周期最优不是同一道题。一个模型训练一次，却可能被部署调用数十亿次；较小模型即使多花训练 Token，也可能在每次推理的显存、延迟和吞吐上更便宜。数据受限、硬件利用率、模型家族复用、长上下文和目标能力也会改变选择。

Llama 3 等公开报告采用了远多于早期 Chinchilla 经验点的训练 Token。正确理解不是“Chinchilla 被推翻”，而是优化目标变了：团队会同时考虑训练资源、推理成本、数据可得性、目标模型尺寸和大量下游使用。

因此比较两份 Scaling Law 结论时，先问四件事：

1. 优化的是训练 Loss、某个 Benchmark，还是训练加未来推理的总成本？
2. 模型架构、Tokenizer、数据混合和训练方法是否相同？
3. 拟合覆盖了哪些规模，结论是否在外推？
4. 预算按 FLOPs、GPU 时间、金钱还是真实服务成本计算？

## 数据质量怎样进入关系

“训练 Token 数”把每个 Token 当作一个计数单位，却不表示每个 Token 提供同样的学习价值。重复、错误、乱码、泄漏测试题和单一分布会浪费预算；去重、过滤、配比和课程式安排会改变同样 Token 数的效果。

高质量数据可能让较小数据集胜过更大的低质量集合，但不能无限抵消规模。质量不是一个跨领域统一的标量：对代码模型有用的数据，未必适合多语言对话；过度过滤还可能丢掉长尾知识、方言和真实噪声。团队仍需用独立验证集和目标任务评测数据混合。

数据受限时，重复训练相同数据可能继续带来收益，但通常弱于持续加入同等质量的新数据，并增加记忆与过拟合风险。规模定律可以纳入重复次数或有效数据量，不能只把磁盘字节数代入公式。

## 上线调用次数会改变最优点

若只计算预训练，较大的模型可能在固定训练 FLOPs 下取得更低 Loss。若加入推理：

```text
总成本 = 一次训练成本 + 单次推理成本 × 未来调用量
```

调用量越大，单次推理的小差异越重要。较小但训练更久的模型、蒸馏模型或稀疏模型可能拥有更低生命周期成本。相反，若任务只运行少量高价值请求，训练一个专用小模型未必划算。

真实决策还要加入延迟上限、显存容量、并发、能源、工程复杂度和质量门槛。FLOPs 相同也不代表墙钟时间或云账单相同，因为硬件利用率和通信开销不同。

## 怎样估“更大模型还是更多 Token”

团队通常先训练一组较小的代理模型，改变参数量、数据量和计算量，拟合 Loss 曲线，再在预算约束下估计候选点。随后还要做目标任务、稳定性和部署评测。只用两三个点画直线，或者把别人的常数直接套到新架构上，都容易得到虚假的精确答案。

估计还会受训练尚未收敛、学习率计划、数据顺序和评测污染影响。一个大模型表现差，可能是欠训练；一个小模型分数高，也可能是测试集更接近其训练数据。规模定律提供预算线索，不替代实验设计。

## 回答五个真实追问

**为什么 Llama 3 一类模型超过传统 Chinchilla Token 数？** 因为团队不只优化一次训练的计算效率，还考虑固定模型尺寸、数据利用和长期推理成本；目标与约束不同。

**数据质量能抵掉规模吗？** 它能显著改变单位 Token 的价值，但没有跨任务通用的“一个高质量 Token 等于几个普通 Token”换算。

**加入推理成本后是否应该更小、训练更久？** 大量调用时往往更值得考虑，但最终取决于质量门槛、硬件、延迟和调用量，不能只看参数。

**固定预算怎样找参数与 Token 的最优点？** 用多组受控训练拟合趋势，在预算约束下选候选，再用目标任务和部署成本验证。

**参数更多为什么不一定更强？** 参数只是容量；数据、计算、训练稳定性、架构和评测共同决定这些容量是否被有效利用。
