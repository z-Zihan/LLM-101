# 一句话里的词，模型是怎么互相“看见”的？

> 所属专题：[Transformer](./03-Transformer到底是什么.md) → **Attention** → [上下文](../02-聊天Token与上下文/07-上下文和上下文窗口是什么.md)
>
> 扩展路线：这篇不是主路线下一站；可以先完成[训练和推理](./18-训练和推理有什么区别.md)，再回来深挖。

Attention 常被翻译为注意力机制，这个名字太像人的心理活动，很容易让人以为模型在句子上主动“看重点”。更合适的第一层直觉是：**它让 Token 之间按当前需要读取和传递信息。** 实际发生的是一组可训练的数值运算：对于当前位置，计算其他允许访问的位置与它有多匹配，再按权重汇总那些位置携带的信息。

原始聊天问“层数、宽度和专家是不是越多越好”，背后还有一个更基础的问题：每一层怎样让相隔很远的 Token 互相影响？Attention 就是 Transformer 用来建立这种位置关系的核心组件。

## 先看“她”指向谁

阅读这句话：

> 小明把苹果给了小红，因为她很饿。

处理“她”这个位置时，“小红”通常比“小明”或“苹果”更有助于形成合适表示。模型不能只靠最近的一个词，也不能提前写死所有语法规则；它需要根据当前内容计算各位置提供的信息。

Attention 会让“她”的当前表示发出一份匹配需求，与句中允许读取的各位置比较，再把那些位置的内容按不同权重组合回来。结果不是一个中文标签“她=小红”，而是一组融合上下文后的新数值，供后续层继续计算。

这个例子只展示直觉。真实模型可能在不同层和不同头中分散处理指代、语法、语义和其他模式，权重最高的位置也不一定就是最终答案的唯一来源。

## Query、Key、Value 分别承担什么

一组常见 Attention 会从每个 Token 的当前表示计算三种向量：

- Query（查询）表示当前位置需要匹配什么；
- Key（键）表示各位置可供匹配的特征；
- Value（值）表示匹配后真正被汇总的内容。

当前位置的 Query 与所有允许位置的 Key 计算相似分数，分数经过缩放和 Softmax 后变成总和为 1 的权重，再用这些权重对 Value 做加权求和。

```text
当前位置 Query × 各位置 Key
            ↓
       匹配分数
            ↓ Softmax
       注意力权重
            ↓ 加权汇总 Value
       新的上下文表示
```

这张图想帮你看清“匹配”和“取内容”是两个角色。读图时最重要的是 Key 参与算权重，Value 参与形成输出；查询、键和值都只是矩阵投影得到的数值向量，不是真有搜索框、钥匙和资料卡。

用矩阵写时，常见形式是 `softmax(QKᵀ / √d) V`。零基础阶段不必计算公式，只需知道除以维度相关尺度是为了控制分数大小，Softmax 把分数转为相对权重，最后乘 V 才得到汇总结果。

## Self-Attention 的 Self 指同一组输入

Self-Attention（自注意力）表示 Q、K、V 都由同一段序列的表示产生。每个位置既可以发出 Query，也提供自己的 Key 与 Value，于是序列内部的位置能够交换信息。

“Self”不是模型关注自己，也不代表自我意识。Cross-Attention（交叉注意力）则让 Query 来自一组表示、Key 和 Value 来自另一组表示，例如原始 Encoder–Decoder Transformer 中，Decoder 可以用交叉注意力读取 Encoder 的输出。

在自回归生成中，还会加入因果遮罩。训练时整段正确文本已经存在，但位置 5 只能读取位置 1 到 5，不能偷看位置 6 的正确答案；推理时未来 Token 本来就尚未生成。遮罩把不允许读取的位置分数排除在权重计算之外。

## 多头不是几个人分别开会

多头注意力（Multi-Head Attention）会把输入投影到多组较小的 Q、K、V 空间，并行计算多次 Attention，再把各头结果合并。不同投影让模型有机会从不同表示子空间建立关系。

```text
同一组 Token 表示
   ├─ Head 1 → Attention 结果
   ├─ Head 2 → Attention 结果
   └─ Head 3 → Attention 结果
              ↓ 拼接与投影
          交给后续模块
```

这张图想说明多头是同一层中的并行参数化计算。读图时不要把每个头固定命名为“语法专家”“事实专家”；研究中确实能观察到某些头呈现特定模式，但功能可能重叠、分散或随输入改变。

头数增加也不是无限有益。主隐藏维度通常会在各头之间分配，更多头会改变每头维度、参数布局和硬件执行方式，最终仍需结合模型规模和实验判断。

## Q、K、V 并没有各自的人工标签

三组投影矩阵和模型的其他参数一样，通常从随机初值出发，由最终训练目标共同更新。训练数据不会额外标注“这个向量应该当 Query”或“那个词应该成为 Key”。如果某组投影有助于降低下一个 Token 预测等目标的 Loss，反向传播就会沿整条计算图调整它。

把匹配与内容分开有实际作用。Query 和 Key 可以学习一套适合决定“读哪里”的表示，Value 则保留“读到后传什么”的表示。如果直接拿 Query 与 Value 既计算权重又传递内容，同一组向量必须同时承担寻址和载荷两种约束，表达选择会更少。这里的角色由计算结构规定，具体匹配规律则是训练学出来的。

点积也不是天生理解语义。两个向量同方向时点积较大，只提供一种连续、可微、适合矩阵并行的匹配函数；训练会调整投影，使当前任务中有用的组合得到更合适的分数。未经训练的随机 Q、K 点积没有可靠的语言含义。

## 为什么分数要除以 √d_k

若 Query 和 Key 各维数值的方差近似稳定，维度越多，点积的波动通常越大。很大的正负分数进入 Softmax 后容易变成接近 0 或 1 的尖锐分布，梯度会集中或变小，训练更难稳定。

除以 `√d_k` 让不同 Key 维度下的分数量级更可控。这是方差尺度上的工程与数学处理，不是把“相关性百分比”开平方。现代架构还可能使用归一化、不同打分函数或其他稳定化方法，不能把这一项当成所有 Attention 的唯一形式。

## 从张量形状看一次实现

设输入形状为 `[batch, sequence, hidden]`。线性投影得到 Q、K、V 后，常把 `hidden` 拆成 `heads × head_dim`，并转成 `[batch, heads, sequence, head_dim]`。随后：

```text
Q @ K.transpose(-2, -1)
→ [batch, heads, query_length, key_length]
→ 缩放、Mask、Softmax
→ 权重 @ V
→ [batch, heads, query_length, head_dim]
→ 合并 heads 并做输出投影
```

Self-Attention 中 Q、K、V 来自同一批序列表示；Cross-Attention 中，Q 通常来自当前解码序列，K、V 来自另一组表示，因此 `query_length` 与 `key_length` 可以不同。实现时最常见的错误不是公式本身，而是转置维度、Mask 广播、缓存长度和因果方向弄反。

## 为什么它比逐步传递更适合大规模训练

循环神经网络常把前一步状态传给后一步，远处信息需要经过较长路径。Self-Attention 允许一个位置直接与其他允许位置比较，训练时许多位置的 Q、K、V 和分数矩阵可以通过批量矩阵运算并行计算。

这不表示 Attention 没有成本。标准全注意力要处理大量位置对，序列长度增加时分数矩阵会快速变大；长上下文还会增加 KV Cache 等运行状态。局部、稀疏、线性化等 Attention 变体试图减少成本，但会引入不同的信息范围、实现与质量权衡。

Attention 也不会自己理解顺序。Transformer 还需要位置表示，让模型分清“猫追狗”和“狗追猫”。它更不会独自完成整个模型计算；前馈网络、残差连接、归一化和其他层会继续改变表示。

## Attention 做完以后，Transformer 层还没做完

Attention 负责让不同位置读取、汇总信息；MLP（也常叫 FFN，前馈网络）则在每个位置上继续加工刚得到的表示。残差连接给新计算保留一条回到原表示的通道，归一化帮助控制数值尺度；具体“先归一化还是后归一化”会因架构而异。

一层 Decoder-only Transformer 可以先用下面这条教学链理解：

```text
一组 Token 表示
  ↓ Self-Attention：位置之间读取与汇总信息
Residual / Normalization
  ↓ MLP / FFN：每个位置继续加工自己的表示
Residual / Normalization
  ↓
下一层 Transformer
```

真实实现会把归一化放在子层之前或之后，也可能使用并行子层、门控 MLP 与不同残差结构；但“Attention 不是整个 Transformer”这个边界不变。多层重复后，每个位置形成更贴合当前上下文的 Hidden Representation，输出层再把最后位置的表示转换成整个词表的 Logits。

这些 Q/K/V 投影和 MLP 参数都没有单独的人工答案。它们之所以能逐渐形成有用计算，是因为最终预测产生的 [Loss 会通过反向传播把梯度传回来](./12-没人给大模型批作业它怎么知道预测错了.md)。

## Attention 权重能不能解释模型为什么回答

权重图可以显示某一层、某个头、某次前向计算怎样分配汇总比例，是有价值的诊断线索。但最终输出还受 Value 内容、输出投影、其他头、前馈网络、残差以及后续许多层影响。

因此，权重最高不能直接翻译为“模型只依据这个词作答”，低权重也不一定代表该 Token 对最终结果没有因果影响。研究已经指出“Attention 权重是否就是解释”需要谨慎检验，不能把好看的热力图当作完整因果证明。

同样，Token 在[上下文窗口](../02-聊天Token与上下文/07-上下文和上下文窗口是什么.md)内，只表示它有机会参与计算；模型是否在目标任务中可靠利用它，还受位置、层数、训练和输入组织影响。Attention 提供访问机制，不提供正确理解保证。

## 三个边界把概念放回原位

**Attention 不是 Transformer。** Attention 是 Token 之间的信息读取与汇总机制，Transformer 还包含前馈网络、位置表示、残差和归一化。

**Attention 不是 Memory。** 它在本次前向计算中组合当前序列表示，不负责跨会话保存用户信息，也不会把新资料永久写进参数。

**Attention 不是人的注意体验。** “关注”是描述权重分配的类比，不能据此推断意识、意图或主观感受。

## 现在怎样用自己的话解释

处理一个 Token 位置时，模型先用 Query 与其他位置的 Key 计算匹配程度，把分数变成权重，再按权重汇总对应 Value。Self-Attention 的 Q、K、V 来自同一序列，多头注意力在多组投影中并行重复这个过程。

这个机制让不同位置更直接地交换信息，是 Transformer 的核心组件；它仍受上下文长度和计算成本限制，权重也不是模型答案的完整解释。

## 把七个真实追问收回来

**为什么不直接比较 Query 和 Value？** Key 负责可训练的寻址特征，Value 负责被取回的内容；分开让匹配与传递拥有不同表示空间。

**Q、K、V 怎样学出来？** 它们的投影矩阵由最终训练 Loss 通过反向传播共同更新，没有专门的 Q/K 人工标签。

**点积为什么能表示相关性？** 点积只是连续匹配函数；训练把对任务有用的方向组织到投影空间中，语义来自数据、目标与整网训练。

**为什么除以 `√d_k`？** 为了控制点积分数随维度增长的尺度，避免 Softmax 过早饱和。

**整句训练时为什么还要 Causal Mask？** 不遮住未来位置会泄露正确答案，训练目标就不再对应真实的自回归生成条件。

**一个大 Head 能代替多个小 Head 吗？** 参数预算可能接近，但多个投影和独立 Softmax 提供不同的并行匹配子空间；质量与效率仍需实验。

**Self-Attention 与 Cross-Attention 的代码差别是什么？** 核心算子相同，主要差别是 Q 与 K/V 的来源和序列长度，进而影响 Mask 与缓存。
