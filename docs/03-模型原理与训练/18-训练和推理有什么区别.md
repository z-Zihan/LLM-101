# 训练和推理有什么区别？

> 你现在的位置：[Transformer](./03-Transformer到底是什么.md) → **训练 → 推理** → [下一个 Token 预测](./10-为什么预测下一个Token能学到能力.md)
>
> 课程导航：[上一篇：Transformer 到底是什么](./03-Transformer到底是什么.md) · 第 13 / 28 篇 · [下一篇：为什么预测下一个 Token 能学到能力](./10-为什么预测下一个Token能学到能力.md)

原始聊天把几个常被拆开的疑问连到了一起：训练模型到底发生在哪个阶段，参数怎么变，为什么硬件要求高；成型模型是不是也在做乘加，只不过参数稳定了；部署以后，一个 Token 又是怎样生成的？

答案的分界很明确：**训练用数据和目标改变参数，推理使用当前参数计算新结果。** 两边都会执行模型的前向计算，但训练还要衡量误差、反向传播并更新参数；推理通常不做这些更新。

## 同一次前向计算，走向两个不同目的

垃圾邮件模型收到一封邮件时，用参数计算“垃圾邮件”的概率，这一步叫前向计算。训练期间，系统知道样本标签，会比较预测与正确标签，再修正参数；上线后收到一封真正的新邮件，系统只需要给出分类结果。

```text
训练：样本 → 前向计算 → Loss → 反向传播 → 更新参数

推理：新输入 → 前向计算 → 预测或生成结果
```

这张图想帮你抓住唯一不可混淆的动作：参数更新。读图时注意两边都经过前向计算，训练在它后面多出一条反馈回路；普通推理到输出就结束。

训练（Training）是一个总称。预训练、监督微调和许多偏好优化虽然数据与目标不同，只要它们根据训练信号更新模型参数，都属于训练。推理（Inference）则是加载某个参数版本，对未参与这次更新的新输入执行计算。

## 一步训练里参数怎样改变

以预测下一个 Token 为例，训练系统会从数据中取一批序列。模型根据每个位置之前的 Token 计算概率；真实后续 Token 已经在训练文本中，因此可以衡量模型给正确目标分配了多大概率。

损失函数（Loss Function）把预测与目标的差异压缩成可优化的数值。模型给正确 Token 的概率越低，相关损失通常越大。Loss 不负责判断整段文字是否“有灵魂”或“像人”，它只按照预先定义的训练目标打分。

反向传播随后利用微积分的链式法则，计算 Loss 对各个可训练参数的梯度。梯度不是参数的“责任百分比”，而是描述在当前位置附近，参数稍微变化会怎样影响 Loss。优化器结合梯度、学习率和内部状态，决定实际更新量。

```text
参数 θ
  ↓ 前向计算
Loss(θ)
  ↓ 反向传播得到梯度
∂Loss / ∂θ
  ↓ 优化器计算更新
新的参数 θ'
```

这张图想说明模型学习的体现形式：训练步骤结束后，参数张量中的数值被改成了新值。读图时最重要的是更新通常很小，能力来自大量样本和许多步骤的累积，不是一次把整篇文章写进参数。

不同训练方式会改变数据、目标和优化流程。预训练常用自监督的 Token 预测；SFT 使用任务示范；偏好优化利用回答比较或奖励信号。它们可以共享“前向—Loss—梯度—更新”的骨架，却不代表所有算法细节一样。

## 为什么训练吃掉更多显存与计算

前向计算时，设备要保存模型参数和当前批次的中间激活。训练为了反向传播，通常还要保留或重新计算许多中间结果，并存储参数梯度、优化器状态与数据批次。多个设备共同训练时，还要同步梯度或参数分片。

可以把资源分成两本账：

- **计算账**：需要完成多少矩阵乘加和其他算子，决定在给定硬件上大致要跑多久；
- **存储与搬运账**：参数、激活、梯度和优化器状态能否放进内存/显存，以及数据能否及时送到计算单元。

“算力”常指设备单位时间可完成的数值运算能力，但真实速度还受显存带宽、设备互联、算子效率、精度和利用率影响。GPU 卡可以理解成带有大量并行计算单元和高速显存的加速设备；乘加是神经网络矩阵运算中的基础动作，不是为了产生一个人类可见答案而单独执行一次。

网上有时用“训练计算约等于若干倍参数量乘 Token 数”做数量级估算。倍数依赖模型结构、前向与反向实现、激活重算、稀疏专家和统计口径，不能把某个 `6 × 参数 × Token` 当作所有训练的精确账单。

推理通常不需要梯度和优化器状态，资源负担较小，却绝不免费。它仍要加载权重、读取当前上下文、执行每层计算并保存生成所需缓存；并发用户、长输入和长输出还会增加吞吐与显存压力。

## 模型保存、部署与推理是三个相邻动作

训练完成后，团队把参数、模型配置和 Tokenizer 等保存到文件。部署（Deployment）是把这些工件放进可运行环境，选择推理引擎和硬件，配置并行、批处理、缓存、API、限流与监控。推理是服务收到具体请求后，真正执行模型计算的那一段。

```text
Checkpoint 与配置
       ↓ 部署系统加载
GPU / 其他设备中的推理服务
       ↓ 收到请求
Tokenizer 编码 → 模型前向计算 → 解码输出
```

这张图想帮你避免把“模型文件”“部署服务”和“一次回答”叫成同一件事。读图时注意，权重文件放在硬盘上不会自己回答问题；它要被程序按正确结构加载到可计算设备中，才能提供推理。

部署还可能量化权重、把模型分到多张卡、同时合并不同用户请求，或把常用前缀缓存起来。这些做法改变运行成本和延迟，不等于重新训练参数。

## 一个 Token 在推理服务里怎样生成

用户文字先由 Tokenizer 编码成 Token ID。模型把 ID 转成向量，经过多层 Transformer，最后为词表中每个候选 Token 计算分数；生成策略把分数转成概率并选择一个 Token ID，再解码成文字。

```text
输入文字
  ↓ Tokenizer
Token ID 序列
  ↓ 加载好的固定参数逐层前向计算
下一个 Token 的分数 / 概率
  ↓ 采样或选择
新 Token ID
  ↓ 接回上下文
再次前向计算，直到结束条件
```

这张图把部署与生成串在了一起。读图时最重要的是循环：未来 Token 尚不存在，所以自回归模型先生成一个，再把它作为新输入的一部分继续；成型模型确实仍在做大量矩阵乘加，只是普通推理不会根据答案好坏反向更新参数。

KV Cache 会保存历史 Token 在 Attention 中已经算过的 Key、Value 等中间状态，新一步不必重复计算全部前缀。它节省重复工作，却会占用显存，也不是长期 Memory。

采样设置会影响从概率分布中选择哪个 Token，因此相同输入可能产生不同回答。无论选择是否随机，这个阶段都叫推理；“推理”在工程语境里指使用模型算输出，不保证输出包含人类意义上的逻辑推理。

## 不采样，结果就一定完全相同吗

生成阶段最显眼的随机性确实来自 Token 采样。若改成每一步都选分数最高的 Token，也就是常说的贪心解码，选词动作本身不再需要随机抽样。但这还不能推出“任何环境下都逐位相同”。

深度学习框架会把计算拆给大量并行硬件。浮点数精度有限，并行归约的先后顺序、所选 GPU 算子、软件版本和硬件平台都可能带来细小数值差异；当两个候选 Token 的分数非常接近时，细小差异也可能改变最终选择。PyTorch 的复现说明因此明确提醒：跨版本、跨平台，甚至 CPU 与 GPU 之间，不能保证完全相同的结果。

Dropout 等训练期随机机制在正常推理时应通过评估模式关闭。Layer Normalization、残差连接和 KV Cache 本身不是必须随机的步骤；如果相同条件下它们造成变化，更可能需要检查模型模式、缓存状态、并发批处理或具体算子实现，而不是笼统归因于“模型会随机思考”。

产品界面里的 `temperature=0` 通常表示关闭采样或采用近似贪心策略，确切语义仍以产品文档为准。做复现测试时，要同时固定模型与 Tokenizer 版本、完整输入、生成参数、随机种子、框架与驱动版本，并启用可用的确定性算法。这样能显著提高复现程度，却不应把一次平台内复现承诺扩大成跨所有后端的永久逐位一致。

## 聊天时模型会不会顺便学习

普通聊天请求通常使用一个固定的已部署参数版本做推理。你在 Prompt 中纠正模型，后续轮次可能因为纠正内容仍在[上下文](../02-聊天Token与上下文/07-上下文和上下文窗口是什么.md)而表现不同；一旦信息没有被再次带入，底层参数并不会因此永久记住。

产品可能保存聊天记录、更新用户 Memory、记录反馈或把匿名化数据放入未来训练管线。这些是产品状态和后续数据流程，不等于当前请求一边回答一边训练。要判断数据是否会被用于改进模型，还需查看具体服务的隐私设置与政策。

同样，RAG 把外部资料放进当前 Context，微调则通过新的训练步骤更新参数。两者都可能让回答更符合领域需求，改变的位置和更新成本完全不同。

## 训练和推理的“推理”不是同一个词义

机器学习工程中的 Inference 通常译为推理，意思是用训练好的模型计算输出；分类一张图片、预测房价也叫 Inference，即使没有多步逻辑。

模型能力讨论中的 Reasoning 也常译为推理，指根据条件和规则经过中间步骤得到结论。一个模型正在做 Inference，不代表它在当前任务上表现出可靠 Reasoning。后面的[推理能力是什么](../04-模型能力/03-推理能力是什么.md)会单独处理这层区别。

## 回答原始聊天中的几个确认

**训练过程是什么？** 数据进入模型做前向计算，Loss 衡量训练目标，反向传播计算梯度，优化器更新参数；许多步骤累积后得到新参数版本。

**训练为什么对硬件要求高？** 除了前向计算，还要保存激活、计算梯度、维护优化器状态并在设备间同步。容量、计算速度、显存带宽和互联都会成为瓶颈。

**显存里的内容等 Loss 稳定后，就是成型模型吗？** 显存里有训练中的参数和许多临时状态。最终需要选择合适 Checkpoint、完成评估并把权重与配置保存；Loss 变平也不自动代表能力、安全和泛化都合格。

**成型模型是不是也在做乘加，只是参数稳定了？** 是一个不错的第一层理解。推理使用固定参数继续做前向计算；但生成还包含 Tokenizer、采样、缓存和服务系统，参数“稳定”也不保证输出正确。

**模型部署后怎样生成一个 Token？** 服务加载参数，编码输入，执行前向计算得到词表分数，选择并解码一个 Token，再把它接回序列循环生成。

**除了 Token 采样，推理还有随机性吗？** 可能有。正常评估模式会关闭 Dropout 等训练期随机机制，但并行浮点计算、非确定性算子、软件与硬件版本仍可能造成细小差异；是否影响最终文本取决于解码方式和候选分数是否接近。
