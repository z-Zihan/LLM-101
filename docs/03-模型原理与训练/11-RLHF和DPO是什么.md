# RLHF 和 DPO 是什么？

> 所属专题：[模型生命周期](./01-一个大模型到底是怎么诞生的.md) · [训练](./18-训练和推理有什么区别.md) · [泛化](../04-模型能力/01-泛化是什么.md)
>

监督微调（SFT）用示范回答教模型“在这个输入下怎样回答”。偏好优化则利用“回答 A 比回答 B 更好”之类的相对信号，让模型更常产生符合目标的输出。RLHF 和 DPO 是两条常见路线，不是所有聊天模型都必须使用的固定套餐。

“对齐”也不等于让模型拥有统一的人类价值观。实际训练目标来自具体标注规范、数据分布和安全政策，只能在测到的范围内塑造行为。

## 为什么有好答案还要 RLHF

如果团队拥有大量高质量标准答案，SFT 是重要起点。它直接最大化示范文本的概率，训练稳定、实现相对简单。但很多质量标准难写成唯一答案：两个回答都正确时，可能一个更清晰；安全、礼貌、长度和格式也常是相对偏好。

偏好数据让标注者比较候选，而不必从空白写出完美答案。RLHF 进一步把学到的评价信号用于优化模型自己生成的分布，探索哪些输出能获得更高 Reward。它可能改善超出原始示范的行为，也会引入 Reward 偏差、训练不稳定和更高成本。

所以不是“SFT 或 RLHF 二选一”。常见流程先用 SFT 得到可用 Policy，再用偏好优化调整；若 SFT 已满足业务目标，额外 RL 未必值得。

## 人类反馈可以怎样记录

反馈形式包括二选一、多个候选排序、分项评分、点赞点踩和文字批注。二选一比较通常比绝对打分更容易保持一致，并能直接构造 chosen/rejected 对；完整排序包含更多关系，却增加标注负担。

点赞/点踩便宜但含义模糊：用户可能因为答案太长、事实错误或只是没解决当下问题而点踩。分项量表能区分正确性、安全、风格和格式，但需要清晰规范与一致性检查。

数据设计要记录 Prompt、候选生成方式、标注者分歧、顺序随机化和适用人群。若两个答案质量差距过大，模型只学会识别显眼错误；差距过小又可能让标签接近随机。

## Reward Model 怎样给出标量

语言模型式 Reward Model 通常读取 Prompt 与完整回答，在末端表示上接一个标量输出头。训练时不要求这个分数等于人类的绝对“幸福值”，而是让 chosen 的分数高于 rejected。

一种常见成对损失鼓励 `r(chosen) - r(rejected)` 为正。模型因此学习排序函数。标量方便优化，却会压缩多维目标，且只在训练数据覆盖的回答分布附近可靠。

Reward Model 的架构可以与 Policy 相近或更小，参数规模不是唯一因素。标注质量、候选难度、校准、分布外测试和是否过拟合标注者偏好同样重要。

## PPO 阶段有哪些模型

经典语言模型 RLHF 的 PPO 阶段常涉及：

- Policy：正在优化、负责生成回答；
- Reference：冻结的参考模型，用于衡量 Policy 偏离程度；
- Reward Model：冻结地给完整回答评分；
- Value/Critic：估计当前位置未来 Reward，帮助降低策略梯度方差。

实现可能共享骨干、合并 Value Head 或分布式放置，因此“同时四份完整模型”不是永远准确的显存算法。概念职责仍需区分：Reward 提供终点评价，Value 估计过程回报，Reference 限制漂移。

## KL 惩罚为什么重要

Policy 若只追逐 Reward Model 的高分，可能迅速离开人类数据与参考模型熟悉的分布，生成奇怪重复文本或利用评分漏洞。KL 惩罚对偏离 Reference 的程度收费，让优化保持在较可信区域。

惩罚太强，模型几乎不改变；太弱，Reward 上升却真实质量下降。实际系统会调系数或使用自适应控制，并同时观察 Reward、KL、长度、任务质量和安全指标。

KL 不是正确性保证。Reference 本身可能有问题，Reward Model 也可能偏；它只是控制更新幅度的一种约束。

## DPO 为什么不显式训练 Reward Model

Direct Preference Optimization（DPO）从同样的偏好对出发，把“chosen 相对 rejected 更受偏好”的概率模型与最优 Policy 关系重写成一个监督式目标。训练直接比较当前 Policy 与 Reference 对两个回答的相对对数概率。

它不需要先单独拟合 Reward Model，再在线采样跑 PPO，工程上更简单、通常更稳定。但偏好信息仍隐含在目标里，Reference 和温度系数仍影响更新；它也没有消除数据偏差、分布外泛化或 Reward Hacking 的广义问题。

DPO 更像离线偏好优化。若任务需要与环境交互、探索新轨迹或长期信用分配，PPO 等在线 RL 方法仍可能有不同价值。

## Rejected 应该有多差

“完全胡说”很容易区分，却只教会粗粒度边界。与正确答案表面相似、但在关键事实、推理或安全上失败的 Hard Negative 往往信息更强，因为它迫使模型学习细微偏好。

然而 Hard Negative 若标签含糊，会放大噪声。实用数据集应混合不同难度，剔除 chosen 也错误的样本，检查答案长度和风格捷径，并按业务错误类型分层评测。不能把模型自己生成的 rejected 未经核验地当成人类真实偏好。

## Reward Model 怎样评估

至少要在与训练隔离的偏好对上测排序准确率，并按主题、长度、安全类别和候选难度拆分。还要检查：

- 分数与人类偏好是否校准；
- 换写法、顺序或长度后是否走捷径；
- 面对新 Policy 生成的分布外回答是否稳定；
- 多位标注者不一致时，模型是否假装存在唯一真值；
- Policy 优化后真实人工评价是否同步提高。

PPO 会主动寻找高 Reward 区域，因此能把 Reward Model 的小漏洞放大。定期收集新 Policy 样本做红队、重新标注和 Holdout 评测，比只看训练 Reward 更重要。

## 多目标 Reward 与 Reward Hacking

正确性、格式、安全和长度很难压成一个永久固定的加权和。量纲不同会让某一项支配；目标之间可能冲突；模型还会利用代理指标，例如用固定套话骗取“安全”分，或写得很长骗取“详细”分。

可以采用分项 Reward、约束优化、分层规则、Pareto 分析或按场景路由，但每种方案仍需明确取舍。高风险硬约束不宜只靠一个可学习标量表达。

Reward Hacking 的根源是优化代理指标而非真正目标。防护包括更丰富的对抗数据、独立评估器、不可见测试、人工复核、限制优化步幅和持续监控现实结果。

## 回答十个真实追问

**为什么不只做 SFT？** 示范适合教目标回答，偏好比较适合表达多个可接受答案之间的相对质量；是否需要 RL 取决于任务。

**反馈用排序还是点赞？** 信息量、成本和歧义不同；应匹配目标并检查标注一致性。

**Reward Model 怎样输出标量？** 它读取 Prompt 与回答，用标量头训练 chosen 得分高于 rejected。

**PPO 有几个模型？** 概念上区分 Policy、Reference、Reward 和 Value；实现可共享部分参数。

**KL 为什么重要？** 它限制 Policy 远离参考分布，降低追逐 Reward 漏洞的速度，但不是正确性保证。

**DPO 为什么不用显式 RM 和 PPO？** 它把偏好模型与最优 Policy 的关系改写成直接比较 chosen/rejected 概率的离线目标。

**Rejected 越差越好吗？** 不是。明显坏样本教粗边界，可靠的困难负例更能教细粒度差异，两者应合理混合。

**RM 会把偏差放大吗？** Policy 会搜索高分区域，确实可能放大 RM 漏洞，因此要做分布外与优化后人工评测。

**多个 Reward 直接加权有什么坑？** 尺度、冲突和捷径会让加权结果偏离真实目标，高风险约束需单独治理。

**Reward Hacking 怎样发生？** 模型找到评分器偏爱的表面模式，却没有完成真正任务。
