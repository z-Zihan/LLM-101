# 分布式训练是什么？

> 所属专题：[训练](./18-训练和推理有什么区别.md) · [参数](./06-参数到底是什么.md) · [GPU 与推理瓶颈](./19-GPU显存和推理瓶颈.md)
>

单张 GPU 放不下模型、训练太慢或 Batch 太小时，团队会把计算和状态分到多张卡甚至多台机器。分布式训练不是一种单独算法，而是一组切分模型、数据、参数状态和计算阶段的方法。

每种并行策略都在“单卡少做或少存什么”与“设备之间多通信什么”之间交换。卡数增加不保证线性加速，网络拓扑、负载平衡和故障恢复会变成训练的一部分。

## DDP：每张卡有完整模型

Distributed Data Parallel（DDP）让每个 Rank 保存一份完整模型，读取不同的数据分片，各自完成前向与反向。反向传播产生参数梯度后，Rank 之间通过 All-Reduce 聚合，通常得到全局平均梯度，再各自执行同样的优化器更新。

```text
Rank 0: 数据 A → 前向 → 反向 ┐
Rank 1: 数据 B → 前向 → 反向 ├─ All-Reduce 梯度 → 各自更新
Rank 2: 数据 C → 前向 → 反向 ┘
```

框架不一定等全部反向结束才一次通信。DDP 常把参数分桶，某个桶的梯度就绪后便启动异步 All-Reduce，与后续反向计算重叠。同步语义仍要求进入下一次一致更新前完成相关归约。

DDP 主要扩大数据并行吞吐，不减少每卡保存完整参数、梯度和优化器状态的要求。

## FSDP 不等于流水线并行

Fully Sharded Data Parallel（FSDP）或 ZeRO 把训练状态分片到不同 Rank，需要计算某层时临时收集相应参数，计算后再释放或重新分片。每张卡不必长期保存完整模型状态。

Pipeline Parallel（PP）则把不同层放在不同设备，让多个 Micro-Batch 像流水线一样经过各阶段。某张卡长期负责前几层，另一张卡负责后几层。它会产生阶段间激活通信和流水线气泡。

二者都能让单卡放不下的模型训练，却切分不同对象：FSDP 以状态分片为中心，PP 以层和执行阶段切分为中心；实际大训练可以组合。

## TP、PP、DP、EP 分别切什么

- Data Parallel（DP）：切数据样本，主要同步梯度或状态分片；
- Tensor Parallel（TP）：切一层中的矩阵或 Head，每层常需 All-Reduce / All-Gather；
- Pipeline Parallel（PP）：切层，阶段之间发送激活与梯度；
- Expert Parallel（EP）：MoE 的不同专家放到不同设备，路由 Token 时常用 All-to-All。

TP 适合单层本身太大，通信频繁且依赖高速互联。PP 跨阶段通信频率较低，但有负载平衡和气泡。DP 扩吞吐最直接，却复制模型；EP 只对稀疏专家架构有意义，并受路由不均影响。

## ZeRO-1、2、3 分片范围

以普通数据并行为基线：

- ZeRO-1 分片优化器状态；
- ZeRO-2 再分片梯度；
- ZeRO-3 进一步分片参数。

分片越彻底，每卡常驻显存越少，通信和实现复杂度通常越高。精确显存不能只按参数除以卡数，还要计算激活、临时 Gather Buffer、通信桶、混合精度副本和碎片。

ZeRO-3 前向时会在需要某层前通过 All-Gather 临时拼出参数，完成该层后可释放非本 Rank 分片；反向时再次取得所需参数，并用 Reduce-Scatter 聚合且分发梯度。框架会预取和重叠通信，以免每层都完全等待。

## 三种 Collective 做什么

All-Reduce 让所有 Rank 得到归约后的完整结果，DDP 梯度同步常用它。All-Gather 把各 Rank 的分片收集为完整张量，ZeRO-3 取完整层参数会用到。Reduce-Scatter 先归约再把结果分片给各 Rank，适合分片梯度。

Collective 的成本取决于消息大小、Rank 数、算法和拓扑。Ring、Tree 或分层算法在不同规模与网络上表现不同。NCCL 负责高效实现 GPU Collective，却不能修复错误的并行切分或慢网络。

## 断点恢复不能只保存权重

从 Epoch 中间精确恢复，通常还需保存：

- 优化器和学习率调度器状态；
- 全局 Step、梯度累积位置和混合精度状态；
- 随机数生成器状态；
- DataLoader / Sampler 的 Epoch、Shuffle 种子和已消费位置；
- 数据版本、世界大小、并行拓扑和分片元数据。

若只恢复模型参数，训练可以继续，却可能重复或漏掉数据、改变学习率，甚至因并行布局不同无法装载。分布式 Checkpoint 还要处理写到一半的原子性与损坏检测。

DistributedSampler 不必每一步通信。只要所有 Rank 使用相同数据集长度、Epoch 和随机种子，就能独立生成同一全局排列，再按 Rank 取互不重叠的切片。每个 Epoch 调用一致的 `set_epoch`，可以让 Shuffle 改变又保持各 Rank 协调。

## 跨机器为什么突然变慢

单机 GPU 可能通过 NVLink 或高速交换互联，跨机则受网卡、交换机、RDMA 配置和拓扑限制。训练每步通信量若大于网络能隐藏的范围，新增机器反而延长 Step。

诊断时分别记录计算时间与 Collective 时间，比较单机和跨机；检查链路带宽、错误重传、Rank 到 GPU/NIC 的亲和性、消息大小、并行策略与网络是否支持 GPUDirect。降低通信频率、扩大计算块、梯度累积或改变并行维度都可能有帮助，但会改变内存、收敛或延迟。

## 回答九个真实追问

**DDP 核心是梯度 All-Reduce 吗？** 是重要核心；它常按梯度桶在反向过程中重叠通信，而不是只在最后一次性执行。

**FSDP 为什么不是 Pipeline Parallel？** FSDP 分片训练状态并按需 Gather，PP 则把不同层长期放在不同阶段。

**TP、PP、DP、EP 切什么？** 分别切层内张量、层阶段、数据样本和稀疏专家，通信位置也不同。

**FSDP 与 ZeRO 什么关系？** 都采用状态分片思想；ZeRO 的阶段描述分片范围，FSDP 是 PyTorch 的具体全分片实现体系。

**70B 单卡放不下，ZeRO-3 为什么能训？** 每卡只常驻参数分片，逐层临时 Gather 完整参数并在使用后释放。

**All-Reduce、All-Gather、Reduce-Scatter 有何区别？** 分别是所有 Rank 得完整归约结果、收集完整张量、归约后各留分片。

**中途恢复还要存什么？** 数据位置、Sampler、随机状态、调度器、Step 和并行拓扑，否则可能重复、漏数据或改变训练轨迹。

**DistributedSampler 为何不用逐步通信？** 所有 Rank 用同一确定性排列，再按 Rank 规则切片。

**跨两台服务器变慢怎么查？** 拆出 Collective 时间，核对网络带宽、拓扑、亲和性和并行策略能否重叠通信与计算。
