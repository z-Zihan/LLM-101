# 没人给大模型批作业，它怎么知道自己预测错了？

> LLM 最小原理闭环：[下一个 Token 预测](./10-为什么预测下一个Token能学到能力.md) → **NLL / Cross Entropy / Backpropagation** → [训练与推理](./18-训练和推理有什么区别.md)

预训练语料可能有几万亿个 Token，不可能让人逐个写“标准答案”。原始聊天却追问得非常准确：错误程度怎么判断，机器怎么知道是对还是错；Loss 得出来后，那些参数又怎么知道应当往哪边改？

答案分成两段。文本中的真实下一个 Token 自动提供训练目标，负对数似然把“模型给正确答案多少概率”变成 Loss；反向传播再计算每个参数怎样影响这个 Loss，优化器据此做一小步更新。

## 先只看一道有标准答案的小题

假设训练文本里出现：

```text
我今天去学校上课
```

[Tokenizer](../02-聊天Token与上下文/04-Token到底是什么.md) 把它编码成 Token 后，某个训练位置看到的前缀是“我今天去学校上”，真实下一项是“课”。模型为整个 Vocabulary 产生候选概率：

```text
课  70%
班  10%
学   5%
饭   1%
其他 14%
```

这个位置的标准答案不是标注员临时写的，而是原始序列里本来就排在后面的“课”。模型给“课”的概率越高，这一道预测题做得越好；若只给 0.1%，说明它非常不相信真实答案，应受到更大惩罚。

这叫自监督学习：监督信号从数据自身构造出来，不等于“没有目标”。人仍然决定收集哪些数据、怎样清洗、使用什么 Tokenizer 和训练目标，只是不必为每个位置另写标签。

## Logits 还不是概率

[Transformer](./03-Transformer到底是什么.md) 最后一层会为当前位置形成 Hidden Representation，输出投影再为词表每个候选产生一个原始分数，也就是 Logit。Logit 可以是负数，不要求落在 0 到 1，也不要求加起来等于 1。

Softmax 根据整组 Logits 的相对大小得到概率分布。若一个候选分数比其他项高，它的概率通常更大；给所有 Logit 加同一个常数不会改变分布，因为重要的是相对差异。

```text
Hidden Representation
  ↓ 输出投影
整个词表的 Logits
  ↓ Softmax
整个词表的概率分布
  ↓ 读取真实下一个 Token 的概率
训练这一位置的 Loss
```

训练程序不会先把模型生成的文字解码出来再请人判断。它已经知道目标 Token ID，可以直接从概率分布中读取该 ID 对应的数值。

## NLL 为什么使用负对数

若正确 Token 的概率是 `p`，这一位置常用的负对数似然（Negative Log-Likelihood，NLL）是：

```text
Loss_t = -log(p)
```

先看三个结果：

| 正确 Token 概率 | NLL 的直觉 |
|---:|---|
| 0.90 | 很小：模型很相信真实答案 |
| 0.10 | 较大：模型只给了少量概率 |
| 0.001 | 非常大：模型几乎排除了真实答案 |

负号是因为 `0 < p ≤ 1` 时 `log(p)` 不大于 0；加负号后，训练得到的是非负损失。概率越接近 1，`-log(p)` 越接近 0；概率越接近 0，惩罚增长越快。

若这里使用自然对数，三个概率对应的 NLL 大约是 `0.105`、`2.303` 和 `6.908`。它们不是“错了 10.5%”之类的百分比，而是同一目标下可比较、可求和的优化量。训练报告中的 Loss 数值还受词表、Tokenizer、数据、Mask 和归约方式影响，不能只拿两个孤立数字判断哪个模型更聪明。

为什么不直接用 `1 - p`？负对数有两个重要性质。第一，它会强烈惩罚“非常自信却把真实答案概率压得很低”的情况。第二，序列概率原本要把许多条件概率相乘，取对数后乘法变加法，更稳定也更方便优化。

NLL 只回答“模型给训练数据中的真实下一项多少概率”。它不直接知道句子是否诚实、礼貌、有帮助，也不会检查训练文本本身是否错误。训练目标与人类真正想要的产品行为之间仍有距离。

## NLL 和 Cross Entropy 是什么关系

下一个 Token 预测是一个词表大小的多分类问题。真实目标通常可表示为 one-hot 分布：正确 Token 位置为 1，其他位置为 0。预测分布与 one-hot 目标之间的交叉熵（Cross Entropy）化简后，正好就是正确 Token 概率的负对数。

因此在这个常见条件下：

```text
Cross Entropy = -log P(正确 Token) = NLL
```

框架接口里常把 LogSoftmax 和 NLL 合并成一个数值更稳定的 CrossEntropyLoss。这里说“相等”有条件：目标为 one-hot 类别、使用对应定义。若采用 Label Smoothing、软标签、类别权重或不同归约方式，计算细节会改变。

Softmax 也不一定要作为巨大的概率张量单独保存。高效实现可以直接从 Logits 计算 LogSoftmax 与 Loss，避免不必要的中间结果；教学流程把步骤拆开，是为了看清职责。

## 一句话为什么能产生很多训练位置

对序列“我 今天 去 学校 上 课”，训练目标可以错开一位：

```text
输入：我                  目标：今天
输入：我 今天             目标：去
输入：我 今天 去          目标：学校
输入：我 今天 去 学校     目标：上
输入：我 今天 去 学校 上  目标：课
```

真实实现不必把五个前缀分别跑五次。整条正确序列已经在训练批次中，因果遮罩让每个位置只能读取自己及之前的位置，输出却可以在 GPU 上并行计算；每个有效位置再与右移一位的真实 Token 比较。

这种在训练时使用真实历史 Token 作为当前位置输入的做法常叫 Teacher Forcing。它不是老师在旁边逐字提示，而是训练序列本身提供正确前缀。生成时未来 Token 尚不存在，只能把模型刚选出的 Token 接回去，因此无法沿输出时间轴一次并行生成整句。

Padding、文档边界、特殊 Token 或不希望计入训练的部分会用 Mask 排除。实际训练的平均 Loss 通常只除以有效 Token 数，不能把填充位置也当真题。

## “把整条序列概率拉高”严格是什么意思

设 Token 序列为 `x₁, x₂, …, x_T`。自回归模型把联合概率分解为：

```text
P(x₁, x₂, …, x_T)
= P(x₁) × P(x₂|x₁) × ... × P(x_T|x_<T)
```

训练希望提高数据中真实序列在模型下的似然。直接连乘许多小于 1 的浮点数会迅速接近 0，产生数值下溢；取对数后得到求和：

```text
Sequence NLL = -Σ log P(x_t | x_<t)
```

实现中常对一个序列、一个 Batch 或所有有效 Token 的 NLL 求和或平均。平均 Token Loss 便于比较不同 Batch，但比较不同模型报告时仍要检查 Tokenizer、Mask、数据和归约口径。

假设一个 Batch 有两条序列：第一条有 5 个有效目标，第二条有 3 个，其余位置只是为了对齐长度而补的 Padding。训练程序会收集 8 个有效位置的 NLL，再按配置求和或除以 8；被遮掉的 Padding 不应进入分母。若某个实现先算每条序列平均值再对序列平均，长度不同就会得到另一种权重。因此看到“平均 Loss”时，最好继续问一句：究竟是按 Token、按序列，还是按 Batch 归约？

所以“把整条序列概率拉高”不是给整句话一个单独分类标签，而是降低真实序列各有效位置负对数概率的总和；等价地，提高这些条件概率的对数似然。

## Loss 怎样变成 Gradient

到目前为止只有一个数：当前 Batch 的 Loss。模型可能有数十亿个参数，训练还要知道每个参数若稍微改变，Loss 会向哪个方向变化。

反向传播（Backpropagation）沿前向计算图反向应用链式法则，得到 Loss 对每个可训练参数的偏导数，也就是 Gradient（梯度）。梯度不是“这个参数应承担 3% 责任”，而是局部斜率：在当前参数附近，把它向某个方向移动一点，Loss 预计怎样变化。

```text
Parameter θ
  ↓ 前向计算
Loss(θ)
  ↓ Backpropagation
Gradient ∂Loss/∂θ
```

Attention 的 Q/K/V 投影、Embedding 表、FFN 和输出层没有各自的人类标签。只要它们参与了产生 Loss 的计算，梯度就可以沿连接传回去。某组参数若有助于提高真实下一 Token 的概率，会在大量样本和步骤中逐渐形成有用表示。

梯度为 0 不一定表示这个参数“已经完美”，也可能来自饱和、遮罩或断开的计算路径；梯度很大则可能带来数值不稳定。归一化、初始化、梯度裁剪和精度策略会影响训练，但不能替代正确目标与数据。

## Optimizer 和 Learning Rate 决定实际走多远

最简单的梯度下降会沿梯度反方向更新：

```text
新参数 = 旧参数 - Learning Rate × Gradient
```

Learning Rate（学习率）太大可能越过较好的区域甚至发散，太小则训练缓慢。实际 LLM 训练常使用 AdamW 等优化器，它会结合梯度的一阶、二阶统计和权重衰减决定更新量；学习率还可能经过 Warmup 与衰减计划。

优化器不是在全局地图上知道“最佳参数在哪里”。它只根据当前与历史梯度做局部更新。一次 Batch 的方向可能有噪声，能力来自大量不同序列、许多优化步骤和持续评估的累积。

Gradient Accumulation 会先累积多个小批次的梯度，再做一次优化器更新，用来模拟更大的有效 Batch；Mixed Precision 用较低精度加速部分计算，同时通过缩放等技术控制数值风险。它们改变训练工程，不改变“目标 → Loss → Gradient → 参数更新”的主链。

## 参数更新后，模型记住的是哪一条句子吗

一次更新会同时作用于许多共享参数。它可能让相似上下文的真实目标更容易获得高概率，却不会把原句存成可定位数据库记录。海量小更新会形成分布式模式，也可能在某些条件下记住具体片段；泛化与记忆需要另外实验区分。

训练结束后保存的是参数张量、模型结构配置、Tokenizer 及必要元数据，有时还保存优化器状态以便继续训练。Loss 曲线只是训练记录，不是模型能力本身；部署也不会靠一张曲线生成回答。

预训练 Loss 下降不能自动保证事实正确、安全或服从指令。后训练可以使用示范、偏好或奖励信号继续调整模型，产品层还需要验证、权限与外部资料。

## 把开头的真实问题收回来

**谁告诉模型正确答案？** 原始文本中真实出现的下一个 Token。程序把序列错开一位，为许多位置自动构造目标。

**NLL 为什么是 `-log(p)`？** 它让正确答案概率越低时惩罚越大，并把序列概率连乘变成对数概率求和，避免小数连乘下溢。

**NLL 和 Cross Entropy 是一回事吗？** 对 one-hot 的下一 Token 多分类目标，Cross Entropy 化简为正确 Token 的 NLL；软标签或其他归约会改变细节。

**一句话只训练最后一个 Token 吗？** 通常不是。因果遮罩下，序列中多个有效位置可同时产生预测与目标，Padding 等无效位置由 Mask 排除。

**Teacher Forcing 是什么？** 训练时用数据中的真实历史 Token 作为前缀；生成时只能使用模型已经选出的历史输出。

**Loss 怎样修改几十亿参数？** 反向传播计算 Loss 对各参数的梯度，优化器结合梯度、学习率和内部状态做小步更新；大量步骤累积成训练结果。
