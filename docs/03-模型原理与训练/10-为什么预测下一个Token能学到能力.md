# ChatGPT 看起来什么都会，底层只是在预测下一个 Token 吗？

> 你现在的位置：[训练](./18-训练和推理有什么区别.md) → **下一个 Token 预测** → [泛化](../04-模型能力/01-泛化是什么.md)
>
> 课程导航：[上一篇：一句话里的词，模型是怎么互相“看见”的](./05-Attention到底是什么.md) · 第 15 / 32 篇 · [下一篇：没人给大模型批作业，它怎么知道自己预测错了](./12-没人给大模型批作业它怎么知道预测错了.md)

“预测下一个 Token”听起来像手机输入法。可语言模型经过大规模训练后，却能回答问题、翻译、续写程序，甚至处理训练时没有逐字见过的任务。原始聊天因此追问：错误程度到底怎么判断，谁告诉模型什么是对的；这些参数为什么最后会表现出能力？公开社区里也有人问，只做下一个 Token 预测是否足以解释复杂代码生成。

这里没有一条“预测等于智能”的魔法定律。比较准确的理解是：**对现代主流自回归大语言模型来说，根据已有 Token 预测下一个 Token，是预训练和生成过程中的核心机制之一。** 训练目标很窄，训练材料包含的结构很广；为了在大量不同上下文中不断降低预测错误，模型会学到许多可复用表示和规律。最终能力还取决于架构、数据、规模、优化、后训练和产品系统。

这句话不能扩大成“所有语言模型都只做下一个 Token 预测”。掩码语言模型会根据两侧内容恢复被遮住的 Token，Encoder–Decoder 模型也可能使用不同输入结构和训练目标；多模态、检索或偏好训练还会加入其他信号。本篇只追踪自回归生成模型的主干。

## “自回归”就是把自己的已有输出接回输入

自回归语言模型把一段序列的概率拆成一连串条件概率：先根据已有 Token 预测下一项，再把选出的新 Token 追加到序列，继续预测后面一项。它不是一次计算出整句未来文本。

```text
已有：北京是中国的
  ↓ 模型为整个词表计算下一项分数
选出：首都
  ↓ 接回当前序列
已有：北京是中国的首都
  ↓ 再次计算
选出：。
```

第二个新 Token 必须等第一个选定后才知道完整前缀，第三个又依赖前两个，因此生成阶段沿时间方向逐步进行。模型写代码、翻译或解题时，可见输出同样由这个循环产生；任务差别主要由输入、训练所得规律、后训练和外部工具决定，不是切换成另一套“一次输出整段”的底层生成器。

模型每一步先产生 Logits，也就是词表中每个候选 Token 的原始分数。Softmax 可以把这些相对分数转换成概率分布，再由贪心选择或采样规则决定下一项。Logit 不是概率，单个分数脱离其他候选也没有稳定解释。

## 文本自己提供了练习题和答案

假设训练文本里有一句“北京是中国的首都”。[Tokenizer](../02-聊天Token与上下文/04-Token到底是什么.md)会先把它切成 Token。为了便于阅读，下面暂时按词展示；真实切分可能完全不同。

```text
输入：北京                    目标：是
输入：北京 是                 目标：中国
输入：北京 是 中国            目标：的
输入：北京 是 中国 的         目标：首都
```

这张图想帮你看懂“标准答案从哪里来”：每个位置后面真实出现的 Token，就是该位置的训练目标。读图时别把它理解成程序一次只处理一小题；训练实现通常能并行计算序列中多个位置的预测。

这种做法常被称为自监督学习。它仍然有监督信号，只是目标由原始数据自动构造，不需要人工给每个 Token 另写标签。人工会影响数据选择、清洗和训练方案，但不会坐在电脑前逐字告诉模型“下一项选中国”。

训练与聊天生成都使用“根据前缀计算后续分数”的前向过程，但目的不同。训练时真实后续 Token 已知，系统用它计算 Loss 并更新参数；聊天推理时未来答案未知，系统从分布中选择一个 Token，参数通常保持不变。

| 阶段 | 下一个 Token 从哪里来 | 之后发生什么 |
|---|---|---|
| 预训练 | 数据中真实存在的后续 Token 作为目标 | 计算 Loss、反向传播、更新参数 |
| 生成 | 按当前 Logits 和解码策略选择 | 追加到上下文，继续下一轮推理 |

这也是为什么“训练时的 Next-token Prediction”和“聊天时生成 Token”既有关联又不相同：共享模型前向计算，反馈和状态变化不同。

## “错了多少”其实是一道概率题

模型不会只报一个候选答案。它先给词表中的候选 Token 计算分数，再转换成概率分布。假设目标 Token 是“中国”，模型当前给出的简化结果如下：

```text
中国  0.60
城市  0.12
一个  0.08
其他  0.20
```

训练系统查看模型分给真实目标的概率，并用损失函数（Loss Function）得到一个数。常见的交叉熵目标会重罚“真实 Token 概率很低”的情况：给“中国”0.60，损失比只给 0.01 小。随后反向传播计算梯度，优化器微调[参数](./06-参数到底是什么.md)，让类似上下文中的正确目标更容易获得较高概率。

这里的“对错”非常具体：**当前训练位置后面实际出现了哪个 Token，模型给它多大概率。** Loss 并不知道一段回答是否诚实、是否有帮助，也不直接判断整篇文章的事实是否正确。它只是把既定训练目标变成可优化的数值。

```text
上下文 Token
    ↓
模型预测候选概率
    ↓
读取真实后续 Token 的概率
    ↓
Loss → 梯度 → 参数更新
```

这张图把[训练](./18-训练和推理有什么区别.md)中的反馈回路缩到一个位置。读图时最重要的是，模型不是收到一句人类评语后整体“想通了”，而是在海量位置上积累许多很小的参数更新。

## Loss 是下一站，不在这里挤成半篇公式

本篇只需要先抓住接口：模型为整个词表产生 Logits，Softmax 把它们转成候选概率；训练程序知道真实的下一个 Token，于是能把“正确项只得到多少概率”换算成 Loss，再据此调整参数。

真正的训练闭环还要继续回答：为什么常用 `-log(p)`，NLL 与 Cross Entropy 是什么关系，一句话怎样同时产生许多训练位置，因果遮罩和 Teacher Forcing 如何配合，以及 Loss 最终怎样经过反向传播、梯度和优化器变成参数更新。这些问题集中在唯一主解释页：[没人给大模型批作业，它怎么知道自己预测错了](./12-没人给大模型批作业它怎么知道预测错了.md)。

```text
真实下一个 Token → NLL / Cross Entropy → Loss
                                      ↓
                     Backpropagation → Gradient → Parameter Update
```

现在先保留一个边界：下一 Token 预测规定了“要把什么预测好”，Loss 与优化过程负责“怎样从错误走向更好的参数”。两者相连，但不是同一个概念。

## 窄目标为什么会逼出广泛规律

如果数据只有“早上好”重复一亿次，预测目标再明确也学不到编程。真正关键的是，大规模文本里同时存在叙事、解释、问答、证明、代码、表格、翻译和对话。要在这些上下文里持续预测得更准，模型只记几个高频搭配远远不够。

一段代词出现后，后文是否合理取决于它指向谁；一个函数签名出现后，后续代码受类型、语法和前文变量限制；一道题写到一半，下一步受条件和已有步骤限制。语言中的局部词序、长距离依赖、语义关联和任务格式，都会影响后续 Token 的概率。

Transformer 借助[注意力机制](./05-Attention到底是什么.md)让当前位置读取相关上下文，多层计算逐步形成内部表示。训练若发现某种表示能同时帮助许多位置降低 Loss，梯度就可能保留并强化它。于是，同一套参数可以在不同 Prompt 下表现出续写、分类、翻译或代码补全等行为。

```text
多领域文本中的约束与结构
          ↓ 反复预测并纠错
参数形成可复用的内部表示
          ↓ 遇到新上下文
组合已学模式，产生新的后续内容
```

这张图解释的是“能力可能怎样从训练目标中长出来”，不是一份已经穷尽内部机制的证明。读图时注意中间的“可复用”：能处理新组合，才比逐句背诵多走了一步，这会进入下一篇的[泛化](../04-模型能力/01-泛化是什么.md)。

## 这是否意味着模型真的理解了语言

“能完成任务”是可以测试的行为；“是否像人一样理解”牵涉不同理论和证据，至今仍有争议。我们不需要先解决哲学问题，才能准确描述模型在某组未见样本上的正确率、失败类型和对条件变化的反应。

模型确实可能记住训练片段，也可能把学到的规律用于新输入，两种现象可以同时存在。一次输出无法告诉我们它主要靠哪一种。研究泛化、记忆和数据污染，就是为了把“看起来会”拆成更可检验的问题。

下一 Token 目标也有明显边界。它奖励符合训练数据分布的延续，不自动要求来源可追溯、事实经过核验或答案满足用户真实意图。流畅但错误的[幻觉](../05-幻觉与模型局限/01-幻觉是什么.md)，正与这种目标和生成方式有关。

## 预训练模型为什么还要做成聊天助手

只做大规模下一 Token 预训练，模型首先学到的是延续文本。用户说“请用三句话解释”，理想产品还要识别指令、遵循格式、拒绝危险请求，并在不确定时适当表达边界。这些行为不全由原始网页文本自然保证。

团队通常会继续做监督微调、偏好优化或其他后训练，用示范与反馈塑造回答方式。产品层还会加入系统提示、检索、工具、Memory、权限和安全策略。因此，聊天助手的最终表现来自一条链，而不是单一训练目标：

```text
下一 Token 预训练
  ↓ 获得广泛语言与任务模式
后训练
  ↓ 更符合指令、偏好与安全目标
产品系统
  ↓ 加入上下文、知识、工具和交互规则
用户看到的回答
```

这张图想防止把“语言模型”和“完整 AI 产品”混为一谈。读图时注意，每一层都能改变结果；后训练仍可能使用 Token 生成目标，但训练数据与优化信号已经不同。

## 把三个真实追问收回来

**错误程度怎么判断，怎么知道对错？** 预训练时，真实文本的后续 Token 提供目标；Loss 根据模型分给这个目标的概率计算错误程度。它判断的是预测任务，不是对整段回答做事实审判。

**NLL 和 Cross Entropy 是什么关系？** 对 one-hot 的下一个 Token 目标，交叉熵等于正确 Token 概率的负对数，也就是该位置的 NLL。序列训练再对多个有效位置求和或平均。

**一句话只训练最后一个 Token 吗？** 通常不是。真实序列错开一位后，许多位置都能提供“前缀 → 下一个 Token”训练对；因果遮罩防止偷看未来，已知位置仍可并行计算。

**只预测下一个 Token，为什么能回答、翻译和写代码？** 因为要在包含这些任务的大量文本中预测准确，模型会学到可复用的语言、结构和任务模式；Prompt 能让某些模式在当前上下文中发挥作用。后训练又进一步把续写能力塑造成指令响应。

**模型一次会生成整句话吗？** 对典型自回归生成不是。一次前向步骤得到下一位置的词表分数，系统选出一个 Token，追加后再预测下一项。

**训练和聊天是在做同一件事吗？** 两者共享根据前缀计算 Logits 的机制；训练拿真实目标计算 Loss 并更新参数，聊天用解码策略选 Token 而不进行普通训练更新。

**“预测下一个 Token”就等于理解吗？** 不是同一概念。预测表现是可测行为，“理解”有不同理论定义；应通过未见任务、干预测试、失败类型和泛化实验评估能力，而不是从训练目标直接下哲学结论。

**这足以解释所有复杂能力吗？** 不能这样下结论。下一 Token 目标是核心训练机制，但能力还受数据、Transformer 架构、参数规模、训练计算、优化过程、后训练、采样和工具影响；某项表现究竟来自记忆、泛化还是系统辅助，需要专门实验。
