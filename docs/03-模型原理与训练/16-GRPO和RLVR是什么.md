# GRPO 和 RLVR 是什么？

> 所属专题：[模型生命周期](./01-一个大模型到底是怎么诞生的.md) · [RLHF 和 DPO](./11-RLHF和DPO是什么.md) · [训练和推理](./18-训练和推理有什么区别.md)
>
> 这是一篇偏好优化扩展页，不改变 32 篇主路线顺序。

上一篇讲过 RLHF：训练一个 Reward Model 给回答打分，再用 PPO 优化策略。这篇讲两条近年更常出现在开源训练报告里的路线——RLVR 用「可验证的奖励」替代人工标注的偏好，GRPO 用「组内相对比较」替代 Value 网络。它们不是新噱头，而是把 RLHF 里最贵的两个部件（人工标注和 Critic 模型）换掉之后，剩下的那套还能干活的东西。

这两个主题天然绑在一起：RLVR 提供「去哪拿奖励」，GRPO 解决「拿到奖励怎么用」。近年大模型的推理能力训练（长思维链、数学、代码）大量依赖这一对组合，不理解它们就看不懂这些训练报告在说什么。

## 可验证的奖励解决了什么

RLHF 的 Reward Model 是一个学出来的代理评分员，它有偏好偏差，会被策略钻空子（Reward Hacking），还要专门伺候它的训练和评估。但有一类任务不需要学出来的评分员：数学题的答案可以对标准答案验算，代码可以跑单元测试，格式要求可以用正则检查。答案对不对这件事由规则说了算，这就是「可验证的奖励」（RLVR，Reinforcement Learning with Verifiable Rewards）。

它解决的问题很具体：奖励信号不再来自一个可能学偏的模型，而来自任务本身的判定规则。数学和代码恰好在 2025 年之后成为「推理能力」的主要训练场，因为只有这两类任务容易大规模自动验证——出题便宜，判卷免费，奖励几乎无噪声。RLVR 不是万能替代：写作、对话、安全这些「没有标准答案」的任务仍然只能靠偏好模型或规则混合，所以实际训练常把可验证奖励与偏好奖励拼在一起用。

也要防另一个方向的误解：RLVR 的「客观」只覆盖判卷那一刻。题目本身可能被污染（预训练语料里见过原题和答案），判卷规则也可能有洞（测试用例覆盖不足的代码任务，模型学会写「看起来能过测试」的实现）。奖励无噪声不等于训练信号无漏洞。

## GRPO 为什么要扔掉 Value 模型

先回忆 PPO 阶段的账单：Policy 要训练，Reference 要冻结，Reward 要推理，还有一个 Value/Critic 模型跟着 Policy 一起训练——它负责估计「当前状态值多少分」，用来给奖励降方差。对语言模型来说，这个 Critic 通常是与 Policy 同量级的完整模型，显存和计算直接翻倍。

GRPO（Group Relative Policy Optimization）的观察是：PPO 用 Critic 估的其实是一个「基线」——把回报减去基线，好的更新方向为正，差的为负。这个基线不一定要学出来。对一个问题采样一组（比如 8 个）回答，用组内平均奖励当基线：高于平均的回答获得正优势，低于平均的获得负优势。同一个问题共享难度水平，组内比较天然消掉了「这道题本来就难」的成分。

具体流程：每个 Prompt 采样 K 个回答，各自算奖励，算出组均值，每个回答的优势 = 自身奖励减去组均值（常再除以组内标准差做归一化），然后套 PPO 的裁剪目标更新。整个过程没有 Critic、没有独立 Reward Model（奖励直接来自验证器），相比 PPO 少了一整份模型的训练和推理，这正是它成为开源训练默认选项的原因之一。

DeepSeek 的 R1 系列训练报告是让这套组合出圈的关键节点：RLVR 提供数学与代码的奖励，GRPO 提供无 Critic 的优化器。注意「GRPO = R1 全部创新」是常见误读，R1 的贡献更多在训练流程设计和数据管线，GRPO 只是其 RL 阶段的优化器选择。

## 组内基线的隐藏代价：GRPO 在偷偷换目标

「减去组均值」听起来只是个降方差的技巧，但 2026 年 11 月的一篇分析论文（arXiv:2611.02404）证明了一个不太直观的事实：当奖励本身依赖整个组时，减去组均值不只是丢弃信息，而是改变优化目标。

先界定「奖励依赖组」是什么意思。普通奖励每个回答自己打自己的分，互相独立；但另一类越来越常见的奖励天然是「组内集体属性」：多样性奖励看你和其他几个回答差得多不多，覆盖率奖励看一组回答合起来铺多宽，分布匹配奖励看整组分布离目标分布有多近。训练多样性、训练模型对齐人群观点分布（而不是多数派暴政）、训练一组回答覆盖多个正确答案，用的都是这类奖励。

这篇论文的核心定理（α-identity）说：这类任务下，GRPO 的期望更新等于「每个回答自身奖励的梯度，加上 α 倍它对其他回答奖励的影响」，其中 α = −1/(K−1)。真正想优化的组总奖励目标，对应的是 α = +1——一个回答帮同组伙伴拿了奖励，应该被记功。而 GRPO 把这个符号整个反过来：你帮了队友，扣分；你压了队友，加分。名字里叫「组相对」，实际训练的是一场零和锦标赛：每个回答都在学「怎么赢过自己的组友」，而不是「怎么让整组更好」。

后果有闭式解。一个成对的多样性加成（两个回答不同就加分），传到 GRPO 更新里的真实权重是 (K−2)/2(K−1)：K=2 时恰好为零——两个不同得好答案和同一个好答案说两遍，GRPO 的优势完全一样，它根本看不见多样性；K=8 时权重 3/7，不到一半。组再大也救不回来：K→∞ 时 GRPO 趋近于没有基线的 REINFORCE，而 REINFORCE 也不是组目标的最优解。论文在六种来自近年方法的奖励结构上做了验证，GRPO 从未好于无基线 REINFORCE，常常更差。

理论预测在实验里定量兑现。一个能精确读出策略的 9B 沙盒实验（Qwen3.5-9B + LoRA，四选项任务），12 组带闭式预测的训练全部收敛到「自己那个估计器对应的博弈」的不动点，最大 ℓ1 误差 0.018——GRPO 训出来的策略停在锦标赛均衡上，REINFORCE 停在 Nash 均衡上，各回各家。两个真实任务更直观：

- GlobalOpinionQA（对齐某国人群的真实观点分布）：GRPO 两个样本一组训练，按理论预言塌缩到多数派答案——到人类分布的平方误差从基线的 0.20 恶化到 0.49，比不训练还差得多；换上修正后的估计器，误差降到 0.08。
- NoveltyBench（质量乘多样性的开放生成）：GRPO 在所有随机种子上都塌缩；修正估计器保持多样性，集合效用比 GRPO 高 1.16（K=2）/ 0.56（K=8），换成独立的第三方裁判评分结论不变。

注意这些数字的适用范围：全部来自「奖励依赖组」的任务。数学题对答案这种独立奖励不受此影响——那里每个回答的奖励与组友无关，「外部性」恒为零，减不减均值只影响方差，不影响目标。所以「GRPO 换目标」的适用边界要记准：训练数学推理照旧，训练多样性、分布对齐、集合级目标时才要当心。

同一篇论文给出修正的代价几乎为零：把 α 从 −1/(K−1) 改成 +1，每个回答记上它对组友奖励的边际贡献，就叫 Team-GRPO。它不需要任何额外模型调用——成对奖励本来就要算两两关系，修正只是改用组内已有的量；甚至 K=2（每题两个样本，最省推理预算的档位）也能无偏工作，而这恰是 GRPO 完全失效的档位。max@k、分布匹配、集合级 RL 等近年专用估计器都可以看作它在特定奖励上的特例。

这条发现的教训超出了 GRPO 本身：「基线只要不依赖动作就不改变期望目标」是策略梯度的经典结论，但它有个前提——各样本的奖励相互独立。组内基线恰恰依赖了组友的动作，前提一破，结论就悄悄失效。降方差技巧不是免费的，它可能在你看不见的地方改写你以为是的东西。

## 同一份密集信号，两种记账方式：蒸馏能替代强化学习吗

GRPO 之外还有一条省算力的路：on-policy distillation（OPD，在策略蒸馏）。学生在自己的 rollout 上训练，但每个 Token 的「裁判」换成冻结教师模型给出的逐 Token 概率分布，用反向 KL 把学生往教师的分布上拉。它和 GRPO 共享一个关键性质——训练数据都来自学生自己生成的轨迹，差别在监督信号：GRPO 靠环境给一个标量奖励，OPD 靠教师给每个位置一个分布。蒸馏听起来「信号更密」，似乎应该更省算力。2026-11-05 同日出现的三篇论文把这笔账算清了，结论比直觉曲折：**老师是谁，比用不用蒸馏更重要。**

第一笔账（Salesforce，arXiv:2611.08453）系统对比了两种方法到达同一准确率所需的教学 FLOPs，变量扫遍任务难度、师生规模、领域和优化配置。结果分两层：

- **外聘教师：蒸馏账面更贵。** 用一个和训练无关的强教师（直到 32B）做 OPD，在同等配置下每个 FLOP 换来的准确率普遍不如 GRPO，而且学生常出现回答长度膨胀——教师偏好更长的回答，这个偏好被学生原样继承，白白烧掉推理预算。文献侧还有一个佐证：作者审计了 2025-10 之后 406 篇 OPD 论文，没有任何一篇用 FLOPs 口径报告过 OPD 胜过 GRPO；声称更便宜的仅 3 篇，且没有一个用 FLOPs 计量。
- **自产教师：账反转了。** 当教师换成学生自己的 GRPO 检查点，OPD 在数学任务上以少 50 倍的蒸馏 FLOPs 恢复出该检查点的准确率——比外聘 8B 教师的同口径成本低 135.6 倍。更大的学生、代码任务、第二个模型家族上都复现。

但别急着说「先 GRPO 再蒸馏是白花功夫」。单一领域里，GRPO 检查点本身就是想要的模型，再蒸馏确实多余；这笔账真正兑现是在**多领域**场景：数学、代码各自训出的 GRPO 专家各有所长，没有哪个单一检查点通吃。把每个领域的 GRPO 检查点当教师做 multi-teacher OPD，合成一个学生能对齐每个专家的准确率，蒸馏阶段只花专家训练 FLOPs 的 5.2%（2 领域）/ 8.0%（4 领域）；把专家训练和蒸馏加总，这条流水线在 2 领域混合上达到联合 GRPO 的水平，总 FLOPs 省 42.0%。这个配方已进入工业实践——DeepSeek-V4 和 Kimi K3 的报告都用它合并领域专家，此前只作为工程选择陈述，这篇论文第一次给了完整口径的理由。还有一个容易漏掉的对照组：同样场景下用一个外部 8B 教师来合成，学生严重退化（停不下来的重复）——「教师更强」不等于「学生更好学」，逐 Token 的密集监督对师生分布差距是敏感的。

第二篇（arXiv:2611.08016）解释了这种敏感性从哪来。OPD 的训练分布由学生自己当前策略生成，于是有一个 GRPO 没有的反馈回路：每次更新既把蒸馏信号转成参数变化（conversion），又通过参数变化改变整个预测分布、重塑下一批 rollout（broadcast）。两篇论文里观察到的失败模式都归结到这个回路：教师学生分歧很大时，学生响应却有限——更新被 broadcast 摊薄；更危险的是退化——某些更新在局部让师生更一致，却同时抬高了「走不到教师能到的状态」的后续轨迹的概率，学生越来越多地在教师监督不可靠的轨迹上接受密集纠正，错误滚雪球。它还给出一个和第一笔账互补的实践结论：先用离线蒸馏打底，即使瞬时 held-out 准确率没起色，也能让后续 OPD 稳定获益；跳过打底直接 OPD 反而可能让生成质量劣化。**密集监督不是安全垫，它的安全性取决于学生正在什么轨迹上接受监督。**

第三篇（arXiv:2611.07959, CoRD）直接在 rollout 分布上动刀，补 OPD 最盲的区域。蒸馏只监督学生走过的状态，那么「教师能到、学生永远到不了」的状态——教师解题路径上的关键分叉——从头到尾没被训练过。CoRD 保留在策略损失，只把训练状态的分布往教师那边挪：用投机解码的极大耦合从师生分布的几何插值中采样，两个分布一致的位置保留学生的 Token，不一致的位置换成学生低估权重的那部分教师分布里的 Token。干预次数被压到任何精确采样器允许的下限，且随学生学习自动消退。在 Qwen3 与 Qwen3.5 两个家族、0.6B 到 4B 的六个学生上，同等步数同等数据，五个公开数学基准的平均 pass@1 比 OPD 高 0.9–2.0 分，pass@8 高 1.2–3.4 分；在冻结的教师可达状态上，4B 学生 16 步达到 OPD 80 步的差距闭合。

把三篇合起来，教科书式的「蒸馏 vs 强化学习谁更省」是个提错的问题。外聘教师时 GRPO 更省；自产教师时蒸馏是极便宜的恢复与合并手段；学生的 rollout 分布本身才是被低估的变量——OPD 的成败几乎完全由「学生处在什么轨迹上」决定，CoRD 的全部增益就来自调度这个分布。三个结论共同支持一个判断：这套「GRPO 训专家、蒸馏做合并」的流水线之所以成立，是因为它把两种方法的短板错开了——GRPO 承担探索，蒸馏只做保守的迁移。

## RLVR 与 GRPO 的边界

几个容易混淆的边界值得单独说清。

RLVR ≠ GRPO。前者是奖励从哪来（验证器），后者是奖励怎么用（优化器）。DeepSeekMath 用 GRPO 时奖励混合了规则与模型打分；不用 GRPO 的训练也可以用可验证奖励；不用可验证奖励的场景（纯偏好任务）也可以跑 GRPO。四象限都存在，别把它们绑死。

GRPO ≠ R1 的全部。如前所述，GRPO 是 R1 训练流程里的一环，「推理能力是 GRPO 训出来的」这类说法把流程设计、数据管线和优化器的贡献混在一起了。

可验证 ≠ 无漏洞。题目污染、测试覆盖不足、验证器被反向利用，都会让「客观奖励」训练出窄门。RLVR 任务通常需要轮换题库和持续审计判卷规则。

组内比较 ≠ 组间公平。GRPO 的基线来自同组样本，不同 Prompt 的组之间没有可比性；组内相对优势只回答「这道题里哪个回答更好」，不回答「哪些题值得训练」。题目的采样与过滤是另一套工程。

## 回答八个真实追问

**RLVR 和 RLHF 是替代关系吗？** 不是全覆盖替代。有标准答案的任务用 RLVR 更稳更便宜；无标准答案的偏好任务仍然要靠 Reward Model 或规则混合。实际训练常两者拼接。

**GRPO 到底省了什么？** 省掉 Value/Critic 模型的训练与推理，用组内均值当基线；通常也不需要独立 Reward Model（奖励来自验证器）。显存和算力省一大截。

**为什么组内平均能当基线？** 同一 Prompt 的 K 个回答面对同一难度，组均值近似「这道题的一般水平」，减掉后剩下的是回答之间的相对好坏，方差降低且难度被消掉。

**GRPO 训数学题有什么坑？** 独立奖励下目标没有被换掉，主要坑在数据侧：题目污染、通过率过低的题没有有效梯度、通过率过高的题浪费算力，题目难度分布需要持续筛选。

**多样性训练为什么会塌缩？** 多样性奖励依赖整组。GRPO 的负号把「帮队友」记成「压队友」，K=2 时多样性加成在更新里的权重恰好为零，模型只会收敛到多数派答案。

**Team-GRPO 改了什么？** 只改基线的符号语义：α 从 −1/(K−1) 换成 +1，每个回答按「自己对组友奖励的边际贡献」记功，恢复组总奖励的真实梯度。无需额外模型调用，K=2 即可无偏工作。

**K 该设多大？** 独立奖励下 K 影响基线质量与算力预算的平衡——组越大基线越稳，采样成本也越高，公开训练报告里常见 16 或 64；组依赖奖励下论文显示大组只能缓解而非消除 GRPO 的偏差，两样本档位直接失效，此时应改用无偏估计器。

**_OPD 和 GRPO 该选哪个？_** 看教师从哪来。从头训能力用 GRPO（外聘教师做 OPD 每 FLOP 换到的准确率更低，还常继承教师的长度偏好）；把已训好的专家合并成一个模型用 multi-teacher OPD（蒸馏阶段只花专家训练 FLOPs 的 5.2%–8.0%，全流程总账可省 42%）。想用 OPD 直训，先离线蒸馏打底，并盯着学生 rollout 分布是否在滑向教师监督不可靠的区域。



**这些结论适用于我的任务吗？** 看奖励结构：回答之间奖励独立（对答案、跑测试）→ GRPO 仍是合理的省 Critic 方案；奖励依赖整组（多样性、覆盖、分布匹配）→ 警惕锦标赛效应，考虑修正符号或专用估计器。
