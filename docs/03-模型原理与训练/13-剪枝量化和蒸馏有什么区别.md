# 剪枝、量化和蒸馏有什么区别？

> 所属专题：[参数](./06-参数到底是什么.md) · [模型文件](./09-safetensors和GGUF是什么.md) · [推理](./18-训练和推理有什么区别.md)
>
> 扩展路线：本篇比较三种模型压缩与加速路线，重点是“改变了什么”和“硬件是否真的受益”。

一个公开问题直接问：为了优化速度，什么时候应该用剪枝、量化或蒸馏？另一个真实问题追问：蒸馏和量化到底是什么关系，一个模型能不能两种都做？

这三种方法都可能让部署更便宜，却不是三个强弱档位。剪枝减少或跳过一部分结构，量化用更紧凑的数值表示近似计算，蒸馏重新训练一个学生模型学习教师行为。选错方法时，模型文件看起来变小，真实延迟却可能没有改善。

## 先看它们到底改变了什么

| 方法 | 主要改变 | 参数个数一定减少吗 | 是否需要训练 | 要获得速度收益还依赖什么 |
|---|---|---:|---|---|
| 剪枝 | 删除、屏蔽权重或移除结构 | 不一定 | 常需微调恢复 | 稀疏格式、算子与硬件支持 |
| 量化 | 权重、激活或缓存的数值编码 | 否 | PTQ 可不重训，QAT 需要训练 | 目标位宽的高效内核 |
| 蒸馏 | 训练较小学生模仿教师 | 通常会 | 是 | 学生架构本身适合目标硬件 |

参数“个数”和每个参数“占多少位”是两条维度。把一个 7B 模型从 16-bit 量化到 4-bit，仍约有 70 亿个参数；把 32 层学生蒸馏成 16 层，参数数和计算图都可能改变；把许多权重置零却继续用稠密矩阵保存，文件和算子形状甚至可能不变。

## 剪枝：哪些连接可以不再计算

剪枝（Pruning）尝试找到对目标表现影响较小的权重、通道、注意力头、神经元或整层，再把它们屏蔽或移除。最简单的幅值剪枝会优先处理绝对值较小的权重，但“数值小”只是启发式标准，不代表对所有输入都不重要。

非结构化剪枝可以在矩阵任意位置产生 0：

```text
原权重矩阵        剪枝后
● ● ● ●          ● 0 ● 0
● ● ● ●    →     0 ● 0 ●
● ● ● ●          ● 0 0 ●
```

它能达到很高稀疏度，却留下不规则位置。普通 GPU 稠密矩阵内核仍可能把这些 0 当作普通元素搬运和计算；若文件还保存完整矩阵加掩码，磁盘体积甚至可能变大。要真正加速，需要稀疏存储、稀疏算子和适合该稀疏模式的硬件。

结构化剪枝会整组移除通道、头、块或层，使矩阵形状直接变小。它通常更容易在现有硬件上获得延迟收益，但一次移除的信息更多，质量恢复可能更难。剪枝后常继续微调，让剩余参数适应改变后的结构。

“剪掉 30% 权重”因此不能推出“文件小 30%、延迟降 30%”。至少要说明剪的是哪种结构、掩码是否固化、运行时是否使用稀疏内核，以及 Batch、硬件和任务条件。

## 量化：参数还在，表示方式变了

[量化](./06-参数到底是什么.md#量化改变表示精度不改变参数个数)使用较少位数近似权重，有些方案也量化激活或 KV Cache。较小表示能降低权重文件、显存容量和内存带宽压力；低精度矩阵内核若受硬件支持，还可能提高吞吐。

训练后量化（Post-Training Quantization，PTQ）从训练好的模型出发，使用统计信息或校准数据决定缩放与分组，不重新执行完整训练。量化感知训练（Quantization-Aware Training，QAT）在训练中模拟低精度误差，让参数提前适应，成本更高但可能在激进位宽下保留更多质量。

“4-bit”仍然不够描述一个方案。它可能只量化权重，也可能采用不同分组大小、缩放因子、异常值处理和混合精度；运行时还可能把部分值临时转换成更高精度计算。[GGUF](./09-safetensors和GGUF是什么.md)可以承载量化或 F16 张量，文件格式不是量化算法本身。

量化最常见的收益来自模型仍保持原架构，转换与部署相对直接。风险是不同任务对误差敏感度不同，同一模型的代码、数学、长上下文和工具选择能力可能退化不一致。必须在目标任务与目标硬件上同时测质量和性能。

## 蒸馏：重新训练一个学生

知识蒸馏（Knowledge Distillation）使用教师模型产生的概率分布、输出或中间表示，训练较小的学生模型。教师对多个候选类别或 Token 的相对概率，能提供比单个正确标签更丰富的学习信号；温度等设置会改变分布的平滑程度。

```text
训练样本 ─→ 教师模型 ─→ 软目标 / 示例 / 中间表示
    └──────────────────→ 学生模型训练
```

学生可以层数更少、宽度更窄，也可以换成更适合部署的架构。蒸馏因此有机会直接减少参数量和计算深度，不依赖稀疏内核；代价是需要数据、训练预算与学生设计，也可能继承教师错误、偏见和覆盖盲点。

LLM 语境中“蒸馏”有时泛指用强模型生成回答或推理样本，再训练小模型；严格实验应说明学生学的是概率分布、隐藏表示、最终答案还是合成数据。只说“模型是某强模型蒸馏的”不足以判断方法和质量。

蒸馏也不保证小模型复制教师的全部能力。学生容量有限，训练数据只覆盖部分任务，长尾知识和复杂推理可能先丢失。评测应比较学生与教师在目标任务上的差距，而不是只看学生比同尺寸普通模型强。

## 三种方法可以组合，但顺序要验证

一个常见方向是先得到较小学生，再对学生做量化；也可以对模型做结构化剪枝、微调恢复后再量化。组合目标是同时减少计算图规模和单个权重的存储成本。

但收益不是简单相乘。剪枝改变权重分布，可能影响量化校准；激进量化会让剪枝后恢复更困难；教师若本身量化，生成软目标时的误差也可能传给学生。每个阶段都要保存未压缩基线，并做消融比较：只量化、只剪枝、只蒸馏、组合方案分别带来什么。

LoRA 与这三者的目标又不同。LoRA 主要用低秩适配器降低微调时需要更新和保存的参数量，不自动让底座模型在推理时变小；适配器合并后，仍要另外选择是否量化或剪枝。

## 从部署约束倒推选择

如果主要瓶颈是权重占用和内存带宽，目标硬件又有成熟低精度内核，量化往往是第一项值得测试的方案。若运行时能高效利用固定块或结构稀疏，剪枝才更可能把理论稀疏转成真实速度。

如果必须显著降低层数、参数量或每 Token 计算，而团队有训练数据与预算，蒸馏可能更合适。若模型要在一种固定设备上长期大规模调用，可以共同设计学生结构和硬件内核；若只是偶尔本地使用，复杂剪枝管线的维护成本可能不值得。

选择前先写验收表：

- 目标任务质量最低允许下降多少，哪些错误不能增加；
- 冷启动、首 Token、逐 Token 延迟和吞吐分别优化哪一个；
- 峰值 RAM / VRAM、磁盘和网络下载限制；
- 目标 Batch、上下文长度、CPU / GPU / NPU 与运行时版本；
- 转换、校准、重训、回滚和后续模型更新的维护成本。

只报“压缩率”容易隐藏现实代价。最终应在同一硬件、同一运行时、同一请求集下比较质量、峰值内存、延迟分位数、吞吐、能耗和文件大小。

## 回答两个真实问题

**剪枝、量化和蒸馏分别什么时候用？** 量化优先解决数值存储和带宽；剪枝在稀疏结构能被运行时利用时减少计算；蒸馏用训练换一个更小、更适配部署的学生。要从实际瓶颈倒推，不能只看压缩率。

**蒸馏和量化能同时做吗？** 可以。学生模型仍可以继续量化；组合后的质量和性能必须重新测，收益不会自动相乘。

**权重置零后为什么文件没变小？** 非结构化剪枝可能仍保存完整稠密张量和掩码。只有转换成受支持的稀疏表示并使用对应算子，存储或速度收益才会兑现。

**4-bit 为什么不一定更快？** 运行时可能缺少高效内核，反量化和分组也有开销；小 Batch、上下文和硬件都会改变瓶颈。
